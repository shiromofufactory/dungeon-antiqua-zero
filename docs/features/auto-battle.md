# オートバトル

## 位置付け

本書は、ZEROの即時行動制に対応したオートバトルの仕様である。
通常攻撃・奇襲と防御だけを選ぶ旧実装を置き換える。ここで定める係数は初期採用値であり、
実装後の戦闘検証によって変更する場合も、コードと本書を同時に更新する。
判断器は `app/auto_battle.py`、読み取り専用入力は `app/auto_battle_model.py`、
予測器は `app/auto_battle_simulation.py` に実装する。呪文使用方針はSettingsへ保存し、
設定メニューの表示文言は共有JSONを参照する。コマンド記憶の保存形式は
[セーブデータ](./save-data.md) に定める。

参照する正本は次のとおり。

- [ゲーム内容](../../content/docs/da0.md): パーティ、成長、魔力減衰の方向性。
- [戦闘仕様](./battle.md): コマンドの可否、射程、効果、行動制限、ゲージ、演出。
- [プログラム構造](../program-architecture.md): Sceneと戦闘ルールの責務。
- `content/data/spells.json`、`items.json`、`skills.json`、`monsters.json`: 安定キーと効果定義。
- `content/data/texts.json`: 表示文言。開始コマンドは `battle.command.auto` を参照する。

本書はAIの判断規則を定める。未実装の戦闘効果のゲームルールを新たに定める文書ではない。
効果量、継続期間、成功率、解除条件が戦闘仕様にない行動は、AI側の推測で有効化しない。

## 目的とDA2との差分

オートは、死亡・行動不能を避けながら、戦闘を早く終わらせ、MPを使い過ぎないことを目的とする。
完全な最適解の探索ではなく、一定範囲の予測を使う再現可能な判断を行う。

DA2の `app/battle.py` の `auto_prepare`、`auto_main`、`auto_conclude` を参照した。
敵の脅威低減と資源消費による評価は引き継ぐが、ZEROでは各味方のコマンドが直ちに発動するため、
全員分のコマンド予約、回復担当の事前割り当て、呪文名単位の重複排除は行わない。

- 実際の手番ごとに状態を取り直し、現在の行動者の1行動だけを確定する。
- 他の味方の行動は予測上の仮定に留める。後続の味方へ予定行動を保存しない。
- 回復済みHP、解除済み状態、付与済み補正、死亡した対象を次の判断へ反映する。
- 同じ間接呪文でも、失敗後の再試行、別対象への使用、有効な重ねがけは候補にできる。
- 「敵のHPが減ること」と「敵の攻撃能力が下がること」を区別する。
  HPを削っただけでは敵の次の攻撃力を下げない。
- 即時発動の利益と、実行後に次の自身の手番が遅れる不利益を同時に評価する。

## 操作と状態遷移

開始、キャンセル案内、通常攻撃・奇襲のオート演出は `battle.md` に従う。
開始時点の味方と、以後手番が回る味方について、次の順に進める。

1. 手番開始時の毒、自動回復、スタン、睡眠、麻痺などを通常の戦闘ルールで処理する。
2. ためる後の強制攻撃など、コマンド選択を伴わない行動があれば、それを優先する。
3. 判断に必要な状態を読み取り専用のスナップショットとして取得する。
4. 合法候補を列挙し、現在の味方状態から固定条件の回復を先に選ぶ。
   該当する手段がなければ、回復・蘇生・治療以外の候補を8ケース×16手で予測、評価、選択する。
5. 選択したコマンド、呪文またはアイテム、対象を、手動と共通の行動実行経路へ渡す。
6. 効果、消費、タイムライン再挿入が完了してから次の手番へ進む。

生存味方または生存敵がいなくなった場合、または生存味方が全員麻痺した場合は、
判断器を呼ばず通常の戦闘終了へ進む。

計算中は戦闘を進めず、キャンセル入力を受け付ける。複数フレームに分けて計算しても結果は同じとする。
Sceneは `AUTO_THINKING` で1フレームにつき8msを目安に計算し、予測1手番の境界で中断する。
キャンセル時に未確定の判断結果を捨て、同じ行動者のコマンド選択へ戻す。
使用確定後のキャンセルはオート継続だけを解除し、実行中の行動を取り消さない。
オートを中断した時点で、コマンド記憶が有効なら全体コマンドの記憶を「たたかう」へ更新する。
計算中・対象選択中・効果や攻撃の演出中・敵の行動中のいずれにも適用し、
次の全体コマンド表示と次の戦闘開始へ反映する。個別コマンド・呪文・アイテムの記憶は維持する。
割り込みゲームメニューからの復帰は、確定済み行動・計算途中の位置を維持する。

しきべつの結果Windowは、オートが継続している場合に限り、完全に開いてから60フレームで自動的に閉じる。
その間のキャンセルはオートを解除して結果Windowを閉じ、通常の行動帰還後に次の手番へ進む。
勝利・敗北・成長リザルトの入力待ちは自動で閉じない。
戦闘終了、逃走開始、戦闘テスト再開始時にはオートと判断用の一時状態を解除する。

## 使用方針と候補生成

### 方針パラメータ

判断器は次の方針を受け取る。設定メニューの `settings.auto_spells.label` で
`settings.auto_spells.use` / `settings.auto_spells.recovery_only` / `settings.auto_spells.never`
を左右入力で循環変更し、Settingsの `auto_battle_spell_mode` へ保存する。
既定値は `spell_mode=use`、`item_mode=reusable_equipment` とする。
各BattleSceneの生成時に設定を判断器へ渡し、予測中の味方の行動にも同じ制限を適用する。
手動で選ぶ呪文と敵の呪文には適用しない。設定メニューの詳細は [フィールド](./field.md) を参照する。

| パラメータ | 値 | 候補の制限 |
| --- | --- | --- |
| `spell_mode` | `use` | 実装済みの戦闘呪文を使う |
| 同上 | `recovery_only` | `HEAL`、`CURE`、`REVIVE`、`MANA` のみ。実装済みのものに限る |
| 同上 | `never` | 通常の呪文を候補にしない |
| `item_mode` | `reusable_equipment` | 行動者が装備する、使用効果があり `break=0` の武器・腕装備だけ |
| 同上 | `never` | アイテム使用を候補にしない |

装備品の使用効果は `spell_mode` と独立に扱う。`spell_mode=never` でも、
`item_mode=reusable_equipment` なら使える。消耗品、`break=1` の装備品、永久成長アイテムは、
緊急時でも自動使用しない。本仕様では消耗品を許可するモードを設けない。

### 列挙規則

候補 `a` は `(command_key, effect_key, equipment_slot, target_keys)` の組とする。
同じ呪文でも対象が違えば別候補。全体効果は、その時点の有効対象集合を持つ1候補とする。

`command_key` は `BattleCommand` の文字列値を使う。表中の大文字は列挙定数名である。

| 定数 | 安定キー | 定数 | 安定キー |
| --- | --- | --- | --- |
| `ATTACK` | `attack` | `AMBUSH` | `ambush` |
| `SPELL` | `spell` | `AIM` | `aim` |
| `HIDE` | `hide` | `IDENTIFY` | `identify` |
| `PRAY` | `pray` | `COVER` | `cover` |
| `IAI` | `iai` | `FOCUS` | `focus` |
| `BREATH` | `breath` | `MP_SHARE` | `mp_share` |
| `DEFEND` | `defend` | `ESCAPE` | `escape` |
| `ITEM` | `item` | `FORMATION` | `formation` |

`effect_key` は使用する呪文の `name_en`、装備枠は既存の装備枠キーとし、該当なしは空文字列とする。
味方対象キーは `pc:{character_key}`、敵対象キーは `enemy:{monster_key}:{encounter_index}` とする。
`encounter_index` は戦闘開始時の敵編成内の0始まり番号で、途中の死亡や並び替えで変更しない。
対象キー列は固定参加者番号順に並べる。これらは判断中の識別用で、セーブへ保存しない。

- `battle_commands.py` が返す表示中かつenabledのコマンドだけを使う。
  左列3件の表示上限によって表示されないスキルは使わない。
- 呪文は習得、`on_battle`、MP、沈黙、効果の実装状況を確認する。
  呪文・アイテム一覧のスクロール外にある候補は使える。
- 対象は手動と共通の射程、隊列、生死、隠れ状態、補正段階上限などで絞る。
- 状態呪文のうち、開示済み耐性によって必ず失敗する行動・対象の組合せは予測前に除外する。
  現在は `SLEEP`・`SLOW` の成功判定に使う属性が対象の既知耐性に含まれる場合であり、
  除外理由は `known_resistance`。属性なしの呪文へ独自の耐性対応を推測しない。
  全体呪文は全対象で必敗の場合だけ除外し、1体でも未判明・有効な対象がいれば手動と同じ全対象へ使う。
  ダメージを与える呪文は、付随する状態異常が無効でも除外しない。
  この候補除外は味方のオート判断だけに適用し、予測中の敵AIの選択候補は変更しない。
- 防御は常にフォールバックとして残す。かばうの自分対象は防御へ統合する。
- 逃走、テレポート、パーティ編成変更、永続能力上昇、前進・後退 `FORMATION` は候補にしない。
  オートはプレイヤーが組んだ隊列を尊重し、手動で選べる場合も隊列変更を評価前に除外する。
  除外理由は `formation_policy`。前衛消滅時の繰り上げや不意打ち後の復帰など、
  通常の戦闘ルールによる隊列変化は予測・実行ともに維持する。
- ダメージも状態変化も情報開示もなく、MPだけを消費する候補は除外する。
  未対応効果のエフェクトだけを再生する行動も除外する。
- 無効候補の評価は `-∞`。有効な候補が防御だけなら防御を実行する。

## 回復・蘇生・治療の固定判断

`HEAL`、`CURE`、`REVIVE` は、現在の味方状態と使用可能な手段から選ぶ。
敵行動、命中、会心、未来の救援をシミュレーションして必要性を比較しない。
固定条件を満たす合法な手段があれば、攻撃・補助・防御の評価を省略して必ず選ぶ。
すぐ敵を倒せる場合や、残りMPを使い切る場合も、この優先を変更しない。
MP不足、沈黙、使用方針、対象の隠れ状態、未対応効果などによって実行不能な手段は使わない。

現在の戦闘本体は専用の `CURE`・`REVIVE` を実装していない。
当面の対象は `HEAL` と `intensity=0` の全回復に付随する状態解除である。
専用治療・蘇生を有効化する際は、手動戦闘の効果と合法対象を先に実装し、
本節の固定判断へ追加する。未実装の効果をAIだけで発動済みとして扱わない。
MP補充 `MANA` と吸収攻撃 `BLOOD_SUCK` はこの固定判断の対象に含めない。

### ピンチの条件と対象順

手番開始時の毒・自動回復を適用した後の状態から、次を上から調べる。
各段階は、合法な手段がある最初の対象について成立する。

1. **緊急回復**: 生存者の `100×HP <= 35×最大HP`。HP割合の低い順、同率は固定参加者番号順。
2. **状態治療**: 生存者に毒・睡眠・麻痺・混乱・スタンがある。
   睡眠・麻痺・混乱・スタンのある者を毒のみの者より先にし、その中では現在のタイムライン順、
   同順位は固定参加者番号順。解除できる状態がない手段は使わない。
3. **通常回復**: 生存者の `100×HP < 60×最大HP`。対象順は1と同じ。
4. **蘇生**: 死亡者を固定参加者番号順。現在は手段未対応のため成立しない。

固定条件に該当しない `HEAL`・`CURE`・`REVIVE` を、予測によって追加選択することはない。
この判定は生存保証ではない。HP60%以上で受ける一撃死など、固定条件外の危険を
事前に回復する規則は設けていない。
隠れ状態などで先頭対象に使えない場合、次の対象・段階を調べる。
どの対象にも手段がなければ、回復以外のシミュレーションへ進む。

### 手段の選択式

対象 `i` と合法な手段 `a` について、乱数を抽選せず下限の回復量を使う。

```text
能力(a) = type=itemなら20、それ以外はfloor(調整後魔力×(51+内部LV)/50)
R(a,i) = min(M_i-h_i, floor(intensity×能力(a)/10×0.8+1))
intensity=0なら R(a,i) = M_i-h_i
adequate(a,i) = I(100×(h_i+R(a,i)) >= 60×M_i)
```

緊急回復・通常回復は `adequate=1` の手段があればそこから選び、
なければ `R` 最大の手段を選ぶ。同点は後述の `C_MP` が小さい順、
行動後ゲージが大きい順、候補の安定キー順で決める。
治療は解除できる状態がある手段から同じ順に選ぶ。
現在の治療手段は全回復だけなので、解除する種類はすべて同じである。
将来専用治療が対応した際は解除状態数を先に、蘇生が対応した際は蘇生後HPを先に比較する。
全体効果は手動と同じ合法対象全体へ適用し、その中の最優先対象で手段を比較する。

選択した回復の総合点 `Q`、敗北割合、死亡区分は計算しない。
判断結果には理由 `recovery_urgent`・`recovery_cure`・`recovery_heal` と、
ケース数0・予測手番数0・空の評価内訳を記録する。
未来のタイムラインやHPを進めず、実際の効果と消費は手動と共通の実行経路で確定する。

## 判断に使える情報

### 許可する情報

味方のHP・MP・能力・装備・習得・状態と、現在の隊列、ゲージ、開示済み図鑑情報、
表示されたダメージ・回復・付与結果を使う。
DA2同様、予測用の敵の攻撃、命中、防御、回避、術防御、素早さ、術補正、行動候補定義は参照してよい。
これらの参照は予測のための内部情報利用として明示的に許可する。
一方、未開示の種族・属性相性、非表示の現在HP、未来の抽選結果は参照しない。

未開示の種族特効はなし、未開示の弱点・耐性は等倍・補正なしと仮定する。
実際には耐性がある効果を試すこともあり、その結果が開示された次の判断から修正する。
非表示の敵MPは、最大MPから観測済み消費を引いた値を推定値とし、観測できた回復を加える。
沈黙やMP不足でも呪文を選ぶ敵AIでは、選択候補を勝手に除外せず、不発を予測する。

### 敵HPの推定

個体ごとに、その戦闘で観測したHP減少の合計からHP回復の合計を引いた `D_e` を記録する。
死亡の有無は実際の状態を使う。生存中の敵については次で初期HP・最大HPを推定する。

| 開示状態 | 予測用の最大HP `M_e` と現在HP `h_e` |
| --- | --- |
| しきべつでその個体の現在HP表示が有効 | 開示済み最大HPと表示中の現在HPをそのまま使う |
| `profile` 開示済み、現在HP表示なし | 開示済み最大HPを `M_e` とし、`h_e=clamp(M_e-D_e,1,M_e)` |
| `profile` 未開示 | 後述の予測ケースごとに `M_e=max(floor(B×(0.75+0.75u)),D_e+1,1)`、`h_e=clamp(M_e-D_e,1,M_e)` |

`B` は判断開始時の生存戦闘参加者の最大HPの中央値（偶数人数は中央2値の平均）とする。
味方最大HPは1以上なので、`B` は常に正である。HP推定用の `u` は後述の用途番号9を使う。
この事前推定は敵HPを知らない場合の初期値であり、敵種別の隠されたHPを推測器へ渡して置き換えない。
既知の最大HPと観測履歴から結果的に正確なHPを推定できることは許可する。

予測中に新しい属性やprofileを開示する行動をしても、未開示の実データを先読みしない。
その予測ケースの仮定値を保持し、情報取得そのものは後述の情報点で評価する。
実際の使用結果が確定した後の次の判断では、新たに開示された実データを使う。

## 短期予測

### 予測範囲とケース数

固定回復が成立しなかった場合、回復以外の候補ごとに8ケースを計算する。
各ケースは現在の候補を実行した直後を `t=0` とし、
以後16回のタイムライン手番を進め、`t=16` までの状態を得る。
この16回は味方と敵を合わせた手番数であり、キャラクターごとに16回行動させる意味ではない。
毒死亡、睡眠、スタンなどで行動しない手番も1回として数える。描画フレーム数は使わない。
戦闘が途中で終わった場合、残りの `t` は終了状態を保持し、追加の消費・成長は発生させない。

行動後のゲージ、同値時の安定順、死亡者除外、前衛消滅時の繰り上げは戦闘仕様と一致させる。
敵味方の効果成功率、命中、会心、継続期間のばらつきを含む近似予測であり、
8ケース中の件数を真の確率や生存保証と呼ばない。

### 抽選の再現性

ゲーム本体・演出の乱数を消費せず、次の固定分位点を使う。

```text
k = ケース番号（0..7）
n = 戦闘開始時に固定する参加者番号（味方0..4、敵5..9）
v = 予測中のその参加者の手番回数（現在の候補は0）
h = 効果対象の固定参加者番号（対象なしは0）
s = 用途番号
j = ((v × 10 + n) × 10 + h) × 16 + s
u(k,j) = frac((k + 0.5) / 8 + ((37 × j) mod 101) / 101)
```

`frac(x)=x-floor(x)`。用途番号は、0:行動選択、1:単体対象選択、2:右手命中、3:右手会心、
4:右手追加効果、5:左手命中、6:左手会心、7:左手追加効果、8:呪文ダメージ・回復量、
9:敵HP推定、10:呪文状態成功、11:状態継続期間、12:逃走候補追加の1/2判定、
13:逃走候補追加の味方選択、14:逃走候補追加の攻撃比較値、15:予約とする。
HP推定では `v=0,h=n` とする。敵の物理攻撃は右手用の用途番号を使う。

整数抽選 `[L,R]` は `L+floor(u×(R-L+1))`、実数抽選 `[L,R]` は `L+u×(R-L)` とする。
重み付き候補選択は安定キー順の累積確率が初めて `u` を超える候補を使う。
全体効果は対象番号を変えて判定する。対象集合・行動候補の並びに表示名を使わない。
比較する全候補に同じ分位点を使い、候補追加や候補列挙順で既存候補の予測を変えない。

### 予測中の敵行動

対応済みの敵AIと同じ候補追加条件、重み、対象選択、発動可否を使う。
`int=0` の等確率選択、後衛の待機、逃走の二段階条件、とっしんの倍率も再現する。
敵AIの新しい知恵段階を実装した場合、予測も同じ行動分布に対応させる。
予測器が未対応の敵AI段階を基本AIとして黙って扱わない。

### 予測中の味方の継続方針

全候補の比較に共通の、再帰探索を行わない継続方針を使う。
各予測手番で開始時処理と強制行動を先に実行し、その後に次を上から評価する。
その予測手番の合法候補と使用方針に従い、該当する手段がなければ次へ進む。

1. 緊急回復、状態治療、通常回復、対応後の蘇生を、前述の固定判断と同じ条件・対象順・手段選択で調べる。
2. 物理攻撃をする。隠れ状態なら奇襲を使う。
3. 攻撃できなければ防御する。

回復の必要性や手段を別の予測で比較しない。選ばれた回復の効果・消費は、
その予測ケースの状態へ適用する。攻撃・補助候補の結果に後続の固定回復を反映するためであり、
現在行動者の回復候補をケースごとに評価する処理ではない。

物理攻撃の対象は、予測用残りHP以下の期待ダメージを出せる対象を優先し、
その中では後述の脅威重み `w_e` の大きい順とする。
撃破見込みの対象がなければ `w_e×min(期待ダメージ,h_e)/M_e` が最大の対象を使う。
期待ダメージは、現在の予測状態に対する8分位点の平均で計算する。
同点は対象の固定参加者番号で決める。平均ダメージによる撃破見込みを確実な撃破と呼ばない。

継続方針は比較用の近似であり、本番の後続手番へ保存しない。
本番でも毎回、固定回復を先に判定し、成立しない場合だけ回復以外を予測して選び直す。

## 共通の評価式

### 記号と敵の脅威重み

`I(condition)` は真なら1、偽なら0、`clamp(x,L,R)=min(max(x,L),R)` とする。
判断開始時の生存味方集合を `A0`、戦場に残る戦闘参加味方全体を `A`、生存敵集合を `E0` とする。
控えと離脱者は含めない。以下の集合と脅威重みは、その判断内では固定する。

敵ごとに、判断開始時のパーティへその敵が1手番だけ行動する8ケースを別途計算する。
この計算に他の参加者の手番は入れず、敵本人の手番開始時処理は入れる。

```text
b_e = (1/8) × Σ_k [Σ_{i∈A0} 実HP減少(e,k,i)/M_i + 0.25 × z(e,k)]
w_e = 1 + clamp(b_e,0,2)
```

`M_i` は味方最大HP。実HP減少は0以上で現在HPを上限とする。
`z` はその1手番で新しく行動不能になった味方の人数で、同じ味方の複数状態は1人と数える。
敵本人の毒死亡・行動スキップ・逃走・不発では、被害がなければ `b_e` の加算は0。
`w_e` は1..3であり、呪文・追加効果・攻撃範囲などによる被害の差を反映する。
次に動く敵の切迫度は、重みに別係数を掛けず、予測中に被害が発生する時期で反映する。

### 状態の価値

ケース `k` の時点 `t` の予測状態 `S` を次で採点する。

```text
V(S) = 2000 × I(勝利) - 2000 × I(敗北)
     - 600 × L(S)
     + 45 × H(S)
     + 35 × B(S)
     + 80 × K(S)
     + 20 × D(S)
     + J(S)

L(S) = Σ_{i∈A0} I(iが死亡中)
H(S) = Σ_{i∈A} clamp(h_i/M_i,0,1)
B(S) = Σ_{i∈A} I(iが生存し、通常の手番でコマンド選択または強制攻撃を実行できる)
K(S) = Σ_{e∈E0} w_e × I(eが死亡または逃走で戦場から除外済み)
D(S) = Σ_{e∈E0} w_e × clamp((h_e_start-h_e)/M_e, -1, 1)
```

`h_e_start` はそのケースの判断開始時の推定HP。死亡・逃走で除外された敵の現在HPは、
`D` の計算に限り0とする。敵の回復で開始時よりHPが増えた場合、`D` は負になり得る。
味方死亡による600点減点は、判断開始時に生存していた者だけに適用する。
将来の継続方針で蘇生が対応した場合、その後のHPと行動能力は予測状態の値へ反映する。
現在行動者の蘇生をこの共通式で比較することはなく、固定判断で選ぶ。

`B` は、その時点の能力・状態で通常の手番が来たと仮定した行動能力を数える。
入力受付中か、行動演出中か、戦闘終了済みかというSceneのフェーズでは判定しない。
沈黙だけで行動不能にしない。毒、隠れ、前後列、攻撃対象の不在も、
それだけでは行動不能ではない。睡眠・麻痺・スタン等は、その状態の戦闘ルールに従う。
混乱が強制行動となるルールでは、通常コマンドを選べないため0とする。

情報点 `J` は判断開始後に新しく開示する項目だけを累計する。
profileは同種につき2点、属性相性は同種・属性につき0.4点、お宝識別は同種につき1点、
現在HP表示の有効化は個体につき2点とする。
開示済み項目を再加点しない。属性項目は `ResistanceType` ごとに数え、
弱点と耐性の欄を別々に数えない。

係数2000は早期の戦闘終了、600は新たな死亡の回避を重く扱うための値とする。
HP満量の価値45、行動可能な1人の価値35に対し、敵除外の価値は脅威重み1あたり80とする。
単なる敵HP減少の価値20は除外より低く設定し、情報点は救命・撃破より小さくする。
これらは実戦で調整済みの数値ではなく、本仕様の初期係数である。

### MP費用と回復用の留保

行動者の使用直前MPを `p`、最大MPを `P`、実消費MPを `m` とする。
MP消費なしは `C_MP=0`。消費ありは次で計算する。

```text
r = clamp(p/max(P,1),0,1)
q = 使用可能な通常呪文のHEAL/CURE/REVIVEの最小実消費MP（なければ0）
R = min(P,2q)
C_MP = m × (0.8 + 1.6 × (1-r)^2)
     + 8 × max(0, R-(p-m)) / max(R,1)
     + 12 × I(p-m=0)
```

`q` は現在の方針が許可する、習得済み・戦闘対応済みの呪文から求める。
一時的な沈黙と現在MP不足は `q` の算出時だけ無視する。留保は使用禁止線ではなく減点であり、
救命・撃破の利益が上回る場合は使える。最大MP0、`q=0` でもゼロ除算しない。
再使用できる装備品はMP費用0だが、ゲージ遅延による不利益は予測に反映する。

### 候補の総合点

```text
γ = 0.95
W = Σ_{t=0..16} γ^t
U_X(a) = (1/(8×W)) × Σ_k Σ_t γ^t × (X(S_{a,k,t})-X(S_{k,start}))
C(a) = (1/8) × Σ_k Σ_{予測中の味方実行行動l} γ^{t_l} × C_MP(l)

Q(a) = 2000U_勝利(a) - 2000U_敗北(a)
     - 600U_L(a) + 45U_H(a) + 35U_B(a)
     + 80U_K(a) + 20U_D(a) + U_J(a) - C(a)
```

開始状態の勝利・敗北フラグと情報点は0。`t_l` は現在候補なら0、以後はその手番番号とする。
MP費用には、予測中に後続の味方が支払う分も含める。現在行動者の消費だけで比較しない。
敵のMP消費は行動可否へ反映するが、味方の資源費用には含めない。
`U` は時間重み付きの平均、`C` は時間重み付きの消費合計であり、費用を `W` で割らない。
各項目は符号を持ち、予測開始状態との差を取る。負の総合点も有効な値として比較する。
架空の何もしない行動を0点の候補に加えない。

将来のダメージ・回復・行動回数の差を含むため、別途「呪文は一律何点減点」
「ゲージ遅延1につき何点減点」といった重複減点は行わない。
同じ被害軽減に、状態名の固定点と回避した被害点を重ねて加点しない。

### 回復以外の危険区分と同点判定

8ケースについて、範囲内で一度でも敗北した割合を `p_all(a)`、
範囲内で一度でも死亡した `A0` の人数の平均を `d_new(a)` とする。
死亡後に蘇生しても、ここでは死亡した事実を消さない。

```text
T_all(a) = floor(16 × p_all(a))
T_death(a) = floor(4 × d_new(a))
```

候補を `(T_all, T_death, -Q)` の辞書順で比較する。
全滅見込みが1/16以上、平均新規死亡人数が0.25以上改善する候補を、細かい資源効率より優先できる。
同じ区分内のリスク差は、総合点の敗北・死亡項にも反映される。
この区分は真の安全確率ではなく、8ケースの比較値である。
`p_all` は1/8刻みとなるため、敗北ケースが1件増えると `T_all` は2増える。
ケース数の短縮に合わせて危険区分の係数を変えることはしない。

`Q` は比較直前に小数第4位まで丸める（ちょうど中間は絶対値の大きい側）。
同点の場合、次の順に決める。

1. `p_all` が小さい。
2. `d_new` が小さい。
3. 現在候補の `C_MP` が小さい。
4. 現在候補の行動後ゲージが大きい。
5. 通常呪文によって今回初めて使用記録が付く呪文系統の数が多い。
6. 現在候補のコマンド・効果・装備枠・対象の安定キー列の辞書順。

5は同点時だけの育成配慮とする。熟練度・経験値・お宝を増やすための戦闘引き延ばしは加点しない。

## 各行動の評価値の計算

以下の `F_a` は現在候補を実行した後の状態更新を表す。
回復・蘇生・治療以外の各候補について `F_a` と継続方針から `U_L` 等を計算し、上記の `Q(a)` に代入する。
表中の項目は主要な変化であり、記載のない共通項を0と決めつけない。
例えば補助呪文で被害が減り、後続の固定回復を減らせた場合は攻撃機会やMP費用へ反映する。
固定回復の選択には共通点を使わず、回復以外の候補間だけで共通の単位を使う。

### 物理攻撃と追加効果

物理結果は `battle_physical.py` と `battle.md` の計算を共用する。
平均乱数1回で命中したと仮定せず、8ケースで命中・会心・追加効果を個別に判定する。

```text
通常攻撃力 = floor(補正済み武器攻撃 × 補正後の力 × (175+25×武器LV+内部LV) / 1250)
ダメージ倍率 = 0.8 + 命中値/250
非会心ダメージ = floor(max(攻撃力-防御,1) × ダメージ倍率 × (1-防御/100) + 0.99)
会心ダメージ = floor(攻撃力×2 × ダメージ倍率 × (1-防御/100) + 0.99)
```

命中値、素早さ補正、会心率、属性・種族特効、防御中の軽減は戦闘仕様を使う。
右手・左手を順に反映し、右手で死亡した敵へ左手のHP減少や追加効果を重ねない。
そのため `D` は過剰ダメージを加点せず、`K` も同じ敵を1回しか数えない。

| 行動 | `F_a` と評価値の計算方法 |
| --- | --- |
| 通常攻撃 `ATTACK` | 通常物理結果を反映。主項は `80U_K+20U_D-600U_L`。撃破により後続の被害・行動不能が消えれば `45U_H+35U_B` も改善する |
| 奇襲 `AMBUSH` | 隠れによる命中補正・回避無視・会心条件を反映し、隠れを解除。通常攻撃と同じ式。出現後に敵の対象になる被害も予測する |
| ねらう `AIM` | 命中値+100で攻撃し、再挿入ゲージを実効素早さ-16とする。通常攻撃と同じ式。追加威力と減った後続行動を両方数える |
| ためる `FOCUS` | 現在はダメージ0で対象とためる状態を記録。次の自身の手番で攻撃力2倍の強制攻撃。主項は通常攻撃と同じだが、準備中の被弾・解除・救援できない手番を含める |

追加効果も同じ物理候補の `F_a` に含め、次の変化として採点する。

| 追加効果 | 評価への反映 |
| --- | --- |
| 毒 | 敵本人の各手番開始時に `ceil(M_e/16)`、開示済み毒弱点なら `ceil(M_e/8)` を減算。実減少だけが `D`、毒死亡が `K` に入る。既存毒への再付与そのものは0点 |
| 睡眠 | 残り手番数、被ダメージによる解除、回避不能を反映。停止した敵行動による `L/H/B` の改善と、後続攻撃の `D/K` を数える。後続がすぐ起こすなら利益も短くなる |
| スタン | 次の1手番をスキップ。睡眠との消費順も戦闘仕様どおり。実際に回避した被害だけを数える |
| 麻痺 | 敵への付与は戦闘仕様により失敗なので0点。味方に付く被害予測では、行動不能と回避条件を反映する |
| 沈黙 | 敵の呪文選択は残し、不発として処理。通常攻撃を止めたものとして数えない |
| 即死 | 成功時にHP0・除外とし `K/D` に反映。ボス補正・ポイント不足・失敗を含む |
| 防御低下 | その段階の実効防御を後続の物理計算へ使い、増えた実ダメージを `D/K` で採点。付与だけの固定加点なし |
| 未対応の吸収・混乱等 | 戦闘実行側が反映しない間は追加価値0。物理攻撃自体は対応済み部分で評価する |

追加効果の成功率は、命中したケースについて発動可否ポイントと0..99判定を使う。
「命中率×付与率×固定点」を別加算しない。会心による付与率変化も同じケース内で扱う。

### 呪文と装備品の使用効果

通常呪文は使用確定時に実消費MPを払い、対応系統LVによる詠唱遅延を使う。
アイテム発動はその使用経路の術者能力・遅延を使う。
以下の `m` は実消費MPであり、装備品発動では0。

```text
回復術者能力 = floor(調整後魔力×(51+内部LV)/50)
type=itemの回復術者能力 = 20
通常回復量 = floor(intensity×回復術者能力/10×(0.8+0.4u)+1)
実回復量 = min(通常回復量, M_i-h_i)
intensity=0の実回復量 = M_i-h_i（戦闘仕様の同時状態解除を含む）

攻撃術補正 = 調整後魔力×(7+系統LV+内部LV/25)/16
攻撃呪文ダメージ = floor(intensity×術補正×(100-術防御)/100×(0.20+0.05u)×属性倍率)
属性倍率 = 開示済み弱点4、開示済み耐性1/4、それ以外1
```

開示済みの闇属性とshadowの特例なども戦闘仕様を使う。
武器・腕装備から発動する通常系統の呪文は、手動使用と同じく術者の能力・系統LVを使う。
状態呪文は、耐性による必敗を先に判定し、
`max(1,(術補正-術防御)/2+rate)+開示済み弱点の10` が0..19判定値より大きければ成功とする。
この式を採用する効果に限って使い、全効果の成功率を一律に置き換えない。

| 効果 | `F_a` と評価値の計算方法 |
| --- | --- |
| `DAMAGE` | 対象ごとに実ダメージを反映。主項は `80U_K+20U_D-C`。敵を消すことで改善した生存・行動能力も加算。全体呪文は有効対象の合計を使う |
| 毒属性付き `DAMAGE` | ダメージ後の生存対象へ毒成功判定を行う。直接ダメージと後続毒ダメージを同じHPへ順に反映。毒の既存付与に固定加点しない |
| `HEAL` | 現在行動者は固定判断で選び、`Q` を計算しない。継続方針で選ばれた場合だけ実回復量をHPへ加算し、全回復による状態解除も同じ状態更新に含める |
| `SLEEP` | 成功時の2..3手番と、既存睡眠を短縮しない規則を反映。主項は `-600U_L+45U_H+35U_B+80U_K+20U_D-C`。無効対象・短い戦闘・直後の覚醒では利益が小さくなる |
| `PROTECTION` | 味方の防御段階を1上げ、上限2。段階dの防御を `floor((基礎防御+5d)×(1+d/4))` として以後の被害を計算。主項は `-600U_L+45U_H+35U_B-C` |
| `SLOW` | 成功時の速度補正を戦闘仕様どおり更新。現在ゲージは変更せず、次の行動完了後から `max(1,floor(基礎素早さ×0.75))` を再挿入へ使う。減った被害・増えた味方の攻撃機会を共通式で採点 |
| `IDENTIFY` | 新規情報点と個体の現在HP表示点を `U_J` に加算。自分の攻撃を見送ったことによる後続被害・戦闘長期化と `C` を差し引く。完全識別済みでも個体HP表示が未有効なら2点分は残る |

次はDA2相当の判断範囲を揃えるための拡張先を定める。
戦闘ルール未定義・未実装の間の評価は、エフェクトが再生できても必ず `-∞` とする。
有効化には、戦闘仕様の効果量・成功率・解除規則と、手動実行・予測双方の対応を必要とする。

| 拡張効果 | 有効化後の評価方法 |
| --- | --- |
| `CURE` | 対応後は固定判断で選び、`Q` を計算しない。解除対象の現在状態数と費用で手段を比較する。継続方針へ追加する際も、選ばれた治療の状態変化だけを反映する |
| `REVIVE` | 対応後は固定判断で選び、`Q` を計算しない。死亡者へ合法な手段があれば蘇生後HPと費用で選ぶ。継続方針へ追加する際は戦闘仕様の蘇生HP・解除状態・タイムライン追加位置を反映する |
| `HASTE` | 効果段階の実効素早さを後続の命中・回避と再挿入へ使う。`Q=共通式`。現在ゲージを変更するかは戦闘仕様に従い、AI独自の即時繰り上げはしない |
| `BREAK` | 指定段階の防御を後続の物理計算へ使う。`Q=共通式`、主項は `80U_K+20U_D-C`。すでに同じ下限なら追加価値なし |
| `SILENCE` | 成功・継続・解除を反映し、呪文の不発による被害差を計算。`Q=共通式`、主項は `-600U_L+45U_H+35U_B-C` |
| `CONFUSE` | 味方攻撃・敵攻撃・待機など、戦闘仕様の強制行動分布を使う。`Q=共通式`。常に敵の行動停止として見積もらない |
| `MAGIC_SHIELD` | 術防御または軽減状態を更新し、後続呪文被害を再計算。`Q=共通式`、主項は `-600U_L+45U_H+35U_B-C` |
| `FADE` | 戦闘仕様の対象制限・解除条件を更新。`Q=共通式`。隠れと同一のルールだと決めつけない |
| `PURGE` | 解除対象の補正だけを戻し、速度・防御・攻撃などの後続結果を再計算。`Q=共通式`。解除対象がなければ除外 |
| `CURSE` | 定義された能力変化・追加効果を更新。`Q=共通式`。定義されていない能力低下の加点なし |
| `BLOOD_SUCK` | 実ダメージと、戦闘仕様で求める実吸収回復を同時に反映。`Q=共通式`、主項は `80U_K+20U_D+45U_H-600U_L-C`。過剰ダメージ・過剰回復は加点しない |
| `HEAVENGATE` | 対象条件・成功率に従って除外・ダメージ等を反映。`Q=共通式`、主項は `80U_K+20U_D-C`。種族が未開示なら特定種族への成功を先読みしない |
| `MANA` | 実MP回復を上限付きで反映。共通式にMP回復量の固定加点はなく、以後使用可能になった行動・減ったMP費用で評価。終了間際に使えないMPを補充しても利益なし |
| `TELEPORT`、`STR_UP`、`AGI_UP`、`MAG_UP`、`MHP_UP`、`MMP_UP`、`NONE` | 本仕様では候補外で `Q=-∞`。恒久成長・逃走・効果なしの自動選択はしない |

### 支援コマンドと隊列移動

| 行動 | `F_a` と評価値の計算方法 |
| --- | --- |
| 防御 `DEFEND` | 次の自身の手番開始まで防御状態。命中値25未満の回避、物理ダメージ半減、追加効果ポイント補正を反映。主項は `-600U_L+45U_H+35U_B`。呪文被害を半減しない |

| かくれる `HIDE` | 隠れ状態・対象除外・全員隠れ時の強制出現を反映。次の継続手番では奇襲を使う。`Q=共通式`、主項は `-600U_L+45U_H+80U_K+20U_D`。他の味方へ攻撃が集中する損失も含む |

## 回復・重複回避・複数手番行動の境界条件

- 本番の回復は固定条件に従い、ケース数や予測の終端状態によって省略しない。
- 後続の回復役が直前の敵行動で死亡・行動不能になるケースでは、その救援を成立したものとして数えない。
- 固定回復が成立する場合、敵を今倒して救命できる攻撃との比較はしない。
- 状態治療とHP回復の複合効果は手動と同じ経路で発動し、解除済みの状態へ別の治療役を予約しない。
- 同じ補正の上限到達、対象死亡、既存毒の再付与などは、実際に状態が変わらなければ追加効果価値0。
- スロウ成功で目前の敵手番を飛ばしたり、現在のゲージ値を下げたりしない。
- ためるは準備中の回避不能、行動阻害での解除、次回強制攻撃、対象死亡時の選び直しをすべて予測する。
- 予測範囲に次回のためる攻撃が入らないケースが1つでもあれば、そのためる候補は除外する。
  見えていない将来攻撃の固定点を足さない。
- かくれる後の奇襲は強制ではない。本番の次回判断では救援呪文・防御等も選べる。
  ただし予測の継続方針は前述の優先順であり、隠れたまま回復対象になれない条件も守る。
- 自動回復で危険が解消する場合、そのHP増加を予測して不要な回復を減らす。
- 魔力減衰は戦闘ルールから得る現在の補正済み能力へ反映し、AIが戦闘回数から独自に倍率を導出しない。

## 計算例

次は評価集計の検算用であり、マスターデータの能力・消費MPを複製するものではない。
記載しない `U` は0とする。実際の候補点は8ケース・17状態を集計して求める。

### 固定回復

最大HP100・現在HP30なら緊急回復に該当する。
手段Aの下限回復量が25、手段Bが60なら、AではHP55、BではHP90になるためBを選ぶ。
両方がHP60以上に達するなら、MP費用・行動後ゲージ・安定キーで選ぶ。
どちらもHP60に届かない場合は下限の実回復量が多い手段を選ぶ。
攻撃で目前の敵を倒せる場合も、回復の合法手段があれば回復を優先する。

### 通常攻撃とねらう

通常攻撃が `U_K=0.4,U_D=0.5`、ねらうが `U_K=0.3,U_D=0.6` の場合、
`Q_通常=32+10=42`、`Q_ねらう=24+12=36`。
現在の一撃が強くても、遅延で後続撃破が遅れるねらうは選ばない。
ねらうだけが直後の敵を倒して救命できる場合は、死亡項・区分の改善を含めて逆転できる。

### MP費用

仮に `P=30,p=12,m=3,q=3` なら、`r=0.4,R=6` で、
`C_MP=3×(0.8+1.6×0.36)=4.128`。
同じ条件で `p=6` なら、留保割れが加わり、
`C_MP=3×(0.8+1.6×0.64)+8×3/6=9.472`。
この差は使用禁止ではなく、資源効率の比較へ使う。

## 判断ログ

Sceneの `auto_battle_log` は直近16判断の `AutoBattleLogEntry` を保持する。
連番、読み取り専用スナップショット、候補ごとの評価内訳・除外理由と選択結果を取得できる。
スナップショットからHP推定の根拠を確認し、`BattleForecast` で継続方針を再現できる。
`AutoActionEvaluation.selection_key(snapshot)` は死亡区分を含む選択順を返す。
プレイヤー向けの通常UIへ計算詳細を表示しない。

- 判断の連番、現在行動者、使用方針、候補キーと対象キー。
- 候補除外理由、HP推定の根拠、予測中の味方継続方針。
- `p_all`、`d_new`、死亡区分、各 `U`、MP費用、丸め前後の `Q`。
- 選択理由と同点判定で使った項目。
- 予測ケース数、予測手番数、効果対応表のバージョン。

固定回復にはシミュレーションの評価内訳を捏造せず、前述の理由と0ケース・0手を記録する。
回復以外は理由 `simulation`、8ケース・16手を記録する。効果対応表のバージョンは2とする。
合法でも固定条件が成立しなかった回復候補は、除外理由 `recovery_not_needed` を記録する。

効果対応表は実行側と予測側の双方が対応する効果だけを有効にする。
未対応が検出された候補は除外理由を記録し、防御を含む残りの候補から選ぶ。

## 受け入れ条件と実装時の検証

判断・予測とScene接続の回帰検証は `python3 -B -m unittest tests.test_auto_battle` で行う。
戦闘全体の既存テストと合わせて、次を検証する。

1. 回復直後の次の味方は、回復前の要求を保持せず、最新HPから判断する。
2. 固定回復は敵をすぐ倒せる場合も選び、未来の手番・ケースの評価を実行しない。
   HP35%・60%の境界、状態治療、沈黙・MP不足と装備品の代替を確認する。
3. 回復以外の予測では、敵と回復役の行動順が評価へ反映される。
   回復役が失われた場合の救援を過信しない。
4. スロウが目前の敵手番を遅らせず、次回再挿入から効く。
5. 睡眠をすぐ解除する攻撃、既存毒、補正上限への再使用を過大評価しない。
   既知耐性による必敗状態呪文は候補外にし、未知耐性・全体の混在対象・ダメージ複合効果を除外し過ぎない。
6. 二刀流の右手撃破後に左手のダメージ・追加効果を重ねず、全体攻撃の過剰ダメージを加点しない。
7. 防御・かばうは物理だけを軽減し、代役の被害・死亡と自動かばうを正しく扱う。
8. ためるの解除と強制攻撃、かくれるの攻撃集中と全員出現を予測する。
9. 呪文禁止・回復のみ・装備品許可の組合せ、沈黙、MP不足、射程不成立で合法候補だけを選ぶ。
10. 消耗品、壊れる装備、未対応効果、表示されないスキル、逃走、前進・後退を自動選択しない。
    手動で隊列変更できる場合も評価に含めず、後衛から攻撃不能でも前進を選ばない。
11. 未開示の相性・現在HPと未来の乱数を判断器へ渡さない。取得済み情報は次の判断から使う。
12. 同じスナップショットでは同じ評価を得る。候補順の変更、分割計算で結果と本体の乱数状態が変わらない。
13. 最大MP0、回復手段なし、死亡者あり、敵HP推定下限、予測中の戦闘終了でゼロ除算・進行不能にならない。
14. 計算例の数値、費用の合計、割引平均、死亡区分境界、同点丸めを検算する。
15. 成長・経験値・お宝を目的に不要な行動を追加しない。

Sceneの検証では、開始、計算中キャンセル、使用確定後キャンセル、割り込み停止・復帰、
しきべつ結果の自動閉鎖と解除、勝利・敗北時の入力待ちを確認する。
通常攻撃以外を含む該当画面を起動して目視確認する。

係数調整では、弱い敵の短期戦、多数敵、長期戦、MP枯渇、魔力減衰、回復役不在、
不意打ち、状態異常が重なる編成を比較する。
予測範囲16・8ケースによる判断の限界を記録し、係数だけで補えない場合は予測方針を見直す。
比較のための計測で本仕様の係数・ケース数・範囲を変更した場合は、その値をログに残す。

予測の基本計算量は候補数×8ケース×17状態であり、継続方針の期待ダメージ算出も必要になる。
候補数の多い編成で計算時間とキャンセル応答を測定する。
共通状態の計算結果をキャッシュし、複数フレームに分割しても、時間切れで未評価候補を捨てたり、
先に評価した候補を有利にしたりしない。予測範囲・ケース数を減らす場合は本書の変更として扱う。
