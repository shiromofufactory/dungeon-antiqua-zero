# ワールドマップ拠点仕様

## 位置付け

本書は、ワールドマップ上の街・ダンジョンなどの拠点、その入口、マップごとの到着地点、
訪問済み状態を定める。制作用データの編集操作は
[`map-editor.md`](./map-editor.md)、ゲーム本編での表示・遷移は
[`field.md`](./field.md)を参照する。

## 管理単位

- 拠点はマップチップやオブジェクト定義ではなく、ワールドマップに配置する独立レコードとする。
- 拠点は安定した `id` を持つ。表示名の文言キーは `location.<拠点ID>` として自動決定し、
  制作用マップには保存しない。日本語名は `content/data/texts.json` の `text_ja` を正本とする。
- 見た目のある街などは配置済みオブジェクト実体をアンカーにできる。見た目のない入口はセル座標を
  アンカーにする。このため、透明オブジェクトを入口管理のためだけに追加する必要はない。
- 拠点は移動元を表し、入口セルと移動先への参照を持つ。移動先の座標・向きは持たない。
- 到着地点は移動先を表し、その地点が属するマップ上の座標・向きを持つ。
- 拠点の入口はアンカーからの相対座標で保持する。アンカーにしたオブジェクトを移動すると、
  入口も追従する。
- 移動元は用途別の入場先・テレポート先を持たず、単一の `destination` だけを持つ。
  `destination` は `map_id` と `arrival_id` の組で到着地点を参照する。
- 到着地点はテレポート対象にできるかを `teleport_enabled` で持つ。trueの場合は、候補名と
  訪問済み状態を結び付ける `site_id` も持つ。
- ワールドマップ上の拠点入口から施設内へ入る移動と、施設出口からワールドマップへ出る移動は
  別の移動元であるため、異なる到着地点を参照してよい。施設出口とテレポートは同じ到着地点を使い、
  座標や向きを重複定義しない。

## 制作用データ

制作用マップの `format_version` は2とする。ワールドマップの拠点例を示す。

```json
{
  "sites": [
    {
      "id": "sample_village",
      "anchor": {
        "kind": "object",
        "object_id": "village_1"
      },
      "entrance_offsets": [[0, 0], [1, 0], [0, 1], [1, 1]],
      "destination": {
        "map_id": "sample_village",
        "arrival_id": "from_world"
      }
    }
  ]
}
```

見た目のない入口では、`anchor` を次のようにする。

```json
{
  "kind": "cell",
  "position": [12, 8]
}
```

到着地点はworld、town、dungeonの各profileで使用できる。施設内の入場位置は施設マップに、
施設から出たときやテレポートで到着する位置はワールドマップに、それぞれ別レコードとして置く。

施設マップ側の例:

```json
{
  "arrival_points": [
    {
      "id": "from_world",
      "position": [8, 14],
      "facing": "up",
      "teleport_enabled": false,
      "site_id": null
    }
  ]
}
```

ワールドマップ側の例:

```json
{
  "arrival_points": [
    {
      "id": "sample_village_world",
      "position": [11, 9],
      "facing": "down",
      "teleport_enabled": true,
      "site_id": "sample_village"
    }
  ]
}
```

`up`、`right`、`down`、`left` はそれぞれ上、右、下、左向きを表す。

## 表示と出入り

- PCから各入口セルまでのマンハッタン距離が3以下になったとき、最も近い拠点の名称を入口セルの
  近くへウィンドウなしで表示する。表示位置はマップとともにスクロールする。同距離の拠点がある
  場合は拠点ID順で決める。拠点名は通常は入口セル群の上に置き、PCが入口セル群より上にいる
  場合は、PCとの重なりを避けるため入口セル群の下へ置く。日本語名は共通の「大きい表示文字」
  用途を使い、現在は `umplus_j12r.bdf` で表示する。
- PCが歩行を完了して入口セルへ到着したとき、`destination.map_id` の
  `destination.arrival_id` へフェード遷移する。初期配置や直接的な座標変更では入口判定を発火しない。
- 遷移先マップまたは到着地点がまだ存在しない場合は遷移せず、その拠点を訪問済みにもしない。
- 施設出口は、移動イベント側から通常の `destination` 形式で到着地点を参照する。
- 呪文「テレポート」や街中のテレポート装置では、`teleport_enabled` がtrueで、`site_id` が
  訪問済み拠点と一致する到着地点だけを候補にする。
- たとえば「妖精の里」の施設出口とテレポート先は同じ到着地点を参照する。位置や向きの変更は
  到着地点を1件修正すれば両方へ反映される。
- `destination.map_id` に現在と同じワールドマップを指定し、同マップ内の到着地点を参照すれば、
  ワールドマップ内の移動にも使える。

## 訪問済み状態

- 拠点内への遷移が成立した時点で、拠点IDを `SaveData.visited_site_ids` に記録する。
- 訪問済みIDは集合として保持し、同じ拠点へ複数回入っても重複させない。
- テレポートの候補は訪問済みで、かつ対応する `teleport_enabled` の到着地点がある拠点だけとする。
- 表示名や座標を保存せず、安定した拠点IDだけをセーブ対象にする。
- ゲーム本編のデバッグテレポートも同じ候補抽出と到着地点解決を使い、未訪問拠点を
  デバッグ操作だけで訪問済みにはしない。

## マップエディタ

- 「拠点・移動」タブで拠点と到着地点を一覧・選択・編集できる。
- 一覧から拠点を選択すると入口セル群の中心、到着地点を選択するとそのセルが、スクロール可能な
  範囲でキャンバスの表示領域中央へ来るよう即時スクロールする。選択地点がすでに画面内にある
  場合も中央へ移す。
- world profileでは、配置済みオブジェクトの選択情報から「拠点として設定」を実行できる。
  初期入口は、そのオブジェクト定義が持つ全セルとする。
- 「座標拠点を追加」では、キャンバス上のセルを見た目のない拠点アンカーにできる。
- 座標アンカーはキャンバス上のピンクのマーカーを左ドラッグして移動する。専用の移動ボタンは
  設けず、1回のドラッグを1回のUndo単位とする。
- 入口セルは複数選択できる。最後の1セルは解除できない。
- 文言キーは拠点ID欄の下に小さな注記として表示し、日本語名だけを入力できる。新規作成時の
  日本語名は、既存名と重複しない `拠点1`、`拠点2` のような仮名とする。保存時に対応する
  `content/data/texts.json` のレコードを作成または更新する。英語・簡体字中国語の新規値は空文字とする。
  ゲーム用コピーへ反映するときは通常のコンテンツ運用どおり `npm run content:sync` を実行する。
- 移動先マップIDは作成済みマップ、到着地点IDは選択したマップに存在する到着地点から選ぶ。
- 到着地点はキャンバス上で位置を指定し、ID、向き、テレポート対象フラグを編集する。
  テレポート対象にした場合は、対応する拠点IDを拠点一覧から選択する。
- 拠点を新規作成しても到着地点は自動作成しない。施設出口やテレポートに使う到着地点は、必要に
  応じて「到着地点を追加」から独立して作成する。拠点の `destination` は未設定で開始し、移動先
  マップが作成された後にリストから選択する。未選択時の問題一覧には、IDの書式エラーではなく
  マップまたは到着地点を選択するよう案内する。
- 入口は青、座標アンカーはピンク、到着地点は緑のマーカーで表示する。
- マップの左側または上側を増減した場合、座標アンカーと到着地点も地面・オブジェクトと同じ量だけ
  移動する。オブジェクトアンカーは対象オブジェクトの移動へ追従する。

## 検証

次を保存エラーにする。

- 不正または重複した拠点ID、到着地点ID
- world以外のprofileに置かれた拠点
- 存在しないオブジェクト実体を参照するアンカー
- 空、重複、範囲外、通行不可、別拠点と重複する入口セル
- 範囲外または通行不可の到着地点
- 不正な方向、テレポート対象フラグ、対応拠点ID、移動先マップID、移動先到着地点ID
- 存在する参照先マップで、指定した到着地点が見つからない状態
- 存在しない拠点を参照するテレポート到着地点、または同じ拠点に対する複数のテレポート到着地点
- 手入力された `name_text_key` または旧 `teleport_destination`
- 未入力の拠点日本語名

遷移先マップ自体が未作成の場合は警告とし、ワールドマップを先に制作・保存できるようにする。
全マップで拠点IDは一意とし、重複はエラーにする。

## 受け入れ条件

- 見た目のある拠点を配置オブジェクトへ紐づけ、見た目のない拠点をセル座標で配置できる。
- 2×2の街パーツを含む、複数入口セルの指定とゲーム用データへの解決ができる。
- 拠点は移動元、到着地点は移動先として別レコードにでき、ID参照で紐づけられる。
- 拠点の文言キーをIDから一意に生成し、ツールから日本語名だけを編集できる。
- 作成済みマップとその到着地点をリストから選択できる。
- 入口と到着地点の範囲・通行可否・マップ間参照を検証できる。
- 拠点付近で名称を表示し、入口への歩行完了時に指定マップ・到着地点へ遷移できる。
- 遷移成功時だけ訪問済みとなり、テレポート対象の到着地点だけを候補にできる。
