# イベント仕様

## 位置付け

本書は、フィールドや戦闘から起動される通常イベントの定義形式、実行順序、マップ上の
トリガー、イベント制作ツール、検証条件を定める。イベントで表示する実際の文言は
`content/events/messages.json`、キャラクターとアイテムは対応する `content/data/*.json` を正本とする。
Scene、Overlay、Systemの依存方向は
[`program-architecture.md`](../program-architecture.md)、セーブ対象は
[`save-data.md`](./save-data.md)、空間上の編集操作は
[`map-editor.md`](./map-editor.md)を参照する。

本書の初期フィールドイベント範囲は実装済みである。イベント実行器、イベントエディタ、
マップエディタのトリガー編集を利用できる。ID付きイベントバトル開始と戦闘開始時イベントも利用できる。選択肢、
フラグ解除、所持金操作などは、必要になった時点で型付きコマンドまたはadapterを追加する。

## 結論

- イベントは人とプログラムの双方が扱えるJSONを正本とする。YAMLとの二重管理はしない。
- 通常の制作入口として、参照先をリストから選べるローカルWeb版イベントエディタを用意する。
  JSONの手編集も許可するが、保存時とCIで同じ検証を必須にする。
- イベント会話は通常UI文言の `texts.json` と分け、`content/events/messages.json` で管理する。
- イベント本体は `content/events/<namespace>.json`、グローバルフラグは
  `content/events/flags.json`、空間上のトリガーは
  `content/maps/sources/*.json` に分ける。同じイベントを別のトリガーから参照できる。
- イベント本体はコマンド列として表し、条件分岐だけが子コマンド列を持つ。任意の式やPythonを
  JSONへ埋め込まない。
- マップエディタはトリガーの位置、発火方法、イベントIDを編集する。イベント本文は専用
  イベントエディタで編集する。
- Sceneは発火条件の検出、`EventRunner` は条件評価とコマンド進行、既存のDomain Model／Systemは
  実際の状態変更、Overlayはメッセージ入力を担当する。
- 一度に実行するイベントは1件だけとし、イベント中は通常のScene入力と新規トリガー判定を止める。
- イベント実行位置は保存しない。イベント中は手動セーブを開かず、完了後に通常操作へ戻す。
- イベントエディタの保存ボタンはエラーのない保存済み状態でだけ無効にする。未保存または
  検証エラーのある状態では、保存を試行できるようボタン自体は有効にする。

JSONを採用する理由は、既存のマスターデータ、マップ、Python標準ライブラリと揃い、暗黙の
型変換や追加parserを避けられるためである。人向けの入力負担と参照ミスはイベントエディタで
解消する。

## 用語と責務

| 用語 | 内容 |
|---|---|
| イベント定義 | 安定イベントIDと、順番に実行するコマンド列 |
| イベント名前空間 | 1つのイベント定義ファイル内のIDをまとめる名前。ファイル名と一致させる |
| グローバルフラグ定義 | 全イベントから参照できるフラグIDと制作用メモの宣言 |
| イベントメッセージ | `message_id` で参照するイベント専用の多言語会話文 |
| トリガー | いつ、どのイベントIDを起動するかというScene側の設定 |
| イベント呼び出し | トリガーからRunnerへ渡すイベントID、起動元Scene、マップIDなどの値 |
| EventCatalog | 生成済みイベントをIDで検索する不変カタログ |
| EventRunner | 条件評価、コマンド位置、分岐スタック、待機中の効果を所有する実行器 |
| EventEffect | メッセージ、音、移動など、SceneまたはOverlayで完了させる要求 |

トリガーとイベント定義を分けることで、シナリオ本文へ座標を埋め込まず、マップ修正時は
マップ側だけを変更できる。反対に、同じ調査メッセージを接触と決定の両方から起動する場合も、
イベント本文を複製しない。

## ファイル配置と生成

```text
content/events/
├── fairy_village.json        # イベントの制作用正本
├── common.json
├── flags.json                # グローバルフラグ宣言の制作用正本
├── missions.json             # 表示順を持つミッションの制作用正本
└── messages.json             # イベント・ミッション共通のメッセージ正本

content/maps/sources/
└── fairy_village.json        # actor配置とevent_triggersを含むマップ正本

app/events/
├── events.json               # 全定義を索引化したゲーム用生成物
└── messages.json             # ゲーム用メッセージ

app/maps/
└── fairy_village.json        # 解決済みトリガーを含むゲーム用生成物
```

`content/events` はシナリオの入れ子構造を持つためGoogle Sheets同期の対象にしない。
`app/events` はGit管理せず、直接編集しない。イベント検証・生成処理はUIから独立した
`scripts/event_pipeline/`、対話UIは `tools/event_editor/`、本番loaderとRunnerは
`app/resources/events.py` と `app/systems/events.py` に置く。

次の入口を使用する。

```sh
npm run tools:editor -- --editor event
npm run tools:event-editor  # 互換入口
npm run events:validate
npm run events:build
```

`content:validate` はイベント、マップ、マスターデータの横断検証を含むようにする。
`events:build` はエラーが1件でもあれば生成物を更新せず、成功時だけ原子的に
`app/events/events.json` と `app/events/messages.json` を置き換える。マップ生成も存在する
イベントIDとの参照整合性を検証する。

## ミッションの編集・生成

イベントエディタの「ミッション」タブで、行動の手掛かりをミッション単位で編集する。
ミッションはnamespaceへ属さず、`content/events/missions.json` の配列を正本とする。
このファイル名はイベントnamespaceの予約名とし、イベント定義ファイルの走査から除外する。
ファイルがまだない場合は空の一覧として扱い、エディタの保存時に作成する。

```json
[
  {
    "id": "explore_nector",
    "note": "ネクター探索中の案内",
    "condition": {
      "type": "all",
      "conditions": [
        {"type": "flag_set", "flag_id": "quest.started"},
        {"type": "not", "condition": {"type": "flag_set", "flag_id": "quest.done"}}
      ]
    },
    "message_id": "mission.explore_nector"
  }
]
```

- `id` は一覧全体で一意な `lower_snake_case`。表示名を識別子にしない。
- `note` は任意の制作メモで、ゲーム用生成物から除外する。
- `condition` はイベント分岐と同じ形式。フラグ、メンバー、所持アイテム、
  `all`、`any`、`not` を使う。条件の入れ子は16段までとし、空の条件集合を認めない。
  条件を外したミッションは `condition` を省略し、常に表示する。
- `message_id` は `content/events/messages.json` を参照する。ミッション追加時には
  専用メッセージを同時に作成し、同じ編集画面で日本語・英語・簡体字中国語を行単位で入力できる。
  既存メッセージの選択、新しい専用メッセージの作成、日本語プレビューも利用できる。
  同じメッセージを参照するイベントやミッションにも本文編集が反映される。
- 一覧のドラッグハンドルで表示順を変更する。追加、削除、条件・本文・並び順の変更は
  未保存状態とし、Undo／Redo、保存、エディタ切替時の未保存確認の対象にする。
  ミッション削除時も、共有の可能性があるメッセージは自動削除しない。
- 保存・検証は全namespaceとミッションの参照を検証する。使用中のフラグやメッセージを
  削除・改名した場合は保存を拒否し、正本と生成物を更新しない。
- `python3 -B scripts/validate-events.py` と `npm run events-build` もミッションを検証する。
  成功時は `app/events/events.json` の `missions` に制作メモを除いた配列順を維持して生成する。
  従来の `missions` を含まない生成物も、実行時には空の一覧として読み込める。

ゲーム内の表示・操作は [`information-menu.md`](./information-menu.md) を参照する。

## イベント定義形式

### ファイルルート

制作用イベント形式の初期 `format_version` は1とする。

```json
{
  "format_version": 1,
  "namespace": "fairy_village",
  "events": [
    {
      "id": "meet_alvan",
      "note": "里でアルヴァンと話す",
      "commands": [
        {
          "command": "branch",
          "condition": {
            "type": "flag_set",
            "flag_id": "quest.alvan_joined"
          },
          "then": [
            {
              "command": "message",
              "message_id": "fairy_village.meet_alvan.after"
            }
          ],
          "else": [
            {
              "command": "message",
              "message_id": "fairy_village.meet_alvan.first"
            },
            {
              "command": "join_party",
              "character_key": "Alvan"
            },
            {
              "command": "set_flag",
              "flag_id": "quest.alvan_joined"
            }
          ]
        }
      ]
    }
  ]
}
```

名前空間とイベントのローカルIDは `lower_snake_case` とする。
ファイル名は `<namespace>.json` と一致させる。実行時に使う完全IDは
`<namespace>.<local_id>` とし、上の例では `fairy_village.meet_alvan` になる。

名前空間はイベントを整理するための名前であり、呼び出し元のマップIDとは1対1で対応しない。
たとえば複数マップから `common.*` を呼んでもよく、1つのマップから複数の名前空間を参照してもよい。
ただし `move_actor` と `face_actor` は起動元マップに対象actorが必要なため、そのイベントを参照する各マップとの
横断検証対象になる。

イベント参照には常に完全IDを保存する。JSONへイベントIDの省略形を保存しない。`note` は
制作者向けでありゲーム用生成物から除外する。

### グローバルフラグ形式

`content/events/flags.json` はイベントnamespaceから独立した配列で、次の形式とする。

```json
[
  {
    "flag_id": "quest.alvan_joined",
    "note": "アルヴァンが一度加入した"
  },
  {
    "flag_id": "game_started",
    "note": "ゲーム開始処理を完了した"
  }
]
```

- `flag_id` は全イベントを通じて一意なグローバルIDとする。
- IDは `lower_snake_case` の単独名、または同形式をドットでつないだ分類名を使用できる。
  `quest.*` や `world.*` は任意の整理方法であり、イベントnamespaceとは結び付けない。
- どのイベントファイルからでも同じフラグを条件・設定に使用できる。
- 条件やコマンドに書かれただけの未知フラグを自動作成しない。綴り違いは検証エラーにする。
- `note` は任意の制作メモで、ゲーム用生成物には含めない。
- フラグIDの削除・変更時は全イベントとセーブ互換性への影響を確認する。

### イベントメッセージ形式

`content/events/messages.json` は全イベント定義から共有する配列で、次の形式とする。

```json
[
  {
    "message_id": "fairy_village.meet_alvan.first",
    "portrait_character_key": "Alvan",
    "text_ja": ["はじめまして。", "アルヴァンです。"],
    "text_en": ["Nice to meet you.", "I'm Alvan."],
    "text_zhcn": ["初次见面。", "我是阿尔万。"]
  }
]
```

- `message_id` は2要素以上をドットでつないだ `lower_snake_case` とし、全体で一意にする。
- IDの接頭辞をイベント名前空間に合わせることは推奨するが、強制しない。
- `portrait_character_key` は任意で、指定時は `characters.json` の `name_en` と顔座標を使う。
  現在パーティにいないキャラクターも表示できる。同じメッセージを参照するすべての箇所で
  顔の有無と種類は共通とし、イベントのmessageコマンド側には顔情報を持たせない。
- PC以外の顔は `portrait_x` と `portrait_y` に `faces/faces.png` 内の左上座標を
  32px単位で保持する。両属性は必ずペアで指定し、`portrait_character_key` とは
  同時に指定しない。PCは座標の移動に追従できる `portrait_character_key` を優先する。
- 各 `text_*` は1表示行ごとの文字列配列とする。`text_ja` は1行以上必須、未翻訳の
  `text_en` と `text_zhcn` は空配列を許可し、その場合は既存の言語フォールバックを使う。
- 通常UI、用語、ショップなどで使う `content/data/texts.json` とは相互参照しない。

### 条件

初期条件は次のとおり。

| `type` | 必須属性 | 真になる条件 |
|---|---|---|
| `flag_set` | `flag_id` | `SaveData.event_flags` にグローバルフラグIDがある |
| `member_in_party` | `character_key` | 現在の活動パーティにキャラクターがいる |
| `item_at_least` | `item_key`, `quantity` | 装備中を除くインベントリに指定数以上ある |
| `all` | `conditions` | 1件以上の全子条件が真 |
| `any` | `conditions` | 1件以上のいずれかの子条件が真 |
| `not` | `condition` | 子条件が偽 |

不在、未所持、未設定は専用の重複conditionを増やさず `not` で表す。

```json
{
  "type": "all",
  "conditions": [
    {
      "type": "not",
      "condition": {
        "type": "member_in_party",
        "character_key": "Cerion"
      }
    },
    {
      "type": "item_at_least",
      "item_key": "POTION",
      "quantity": 2
    }
  ]
}
```

`quantity` は1以上の整数とする。初期仕様のアイテム所持条件は、イベント消費と同じ対象にするため
インベントリだけを数え、自動的に装備品を外して数えない。装備中を含む所有判定が必要になった
場合は、意味の異なるconditionを追加する。

条件評価は状態を変更せず、短絡評価の有無に結果が左右されない。未知のconditionは偽として
続行せず、生成時エラー、本番loaderエラー、開発中の実行エラーとして扱う。

### コマンド

初期コマンドは次のとおり。属性名に表示名や配列位置を使用せず、正本の安定キーを使う。

| `command` | 必須属性 | 完了条件・結果 | 使用可能な起動元 |
|---|---|---|---|
| `set_flag` | `flag_id` | フラグを集合へ追加。同じ値は成功扱いのno-op | field / battle |
| `join_party` | `character_key` | キャラクターをパーティ末尾へ加入 | fieldのみ |
| `leave_party` | `character_key` | 活動パーティから外し、成長状態は保持 | fieldのみ |
| `give_item` | `item_key`, `quantity`（任意: `show_message`） | 全数量を一括で追加。通知ONなら閉じるまで待機 | field / battle |
| `take_item` | `item_key`, `quantity` | 全数量を一括でインベントリから削除 | field / battle |
| `branch` | `condition`, `then`, `else` | 条件に応じて片方の子コマンド列だけを実行 | field / battle |
| `end_event` | なし | branchを含む現在のイベント全体を直ちに終了し、後続コマンドを実行しない | field / battle |
| `message` | `message_id` | メッセージOverlayを閉じるまで待機 | field / battle |
| `play_se` | `se_id` | SE再生を要求して同フレームで完了 | field / battle |
| `change_bgm` | `bgm_id` | BGM切替要求が受理された時点で完了 | field / battle |
| `stop_bgm` | なし | BGMをフェードアウトして停止し、完了まで待機 | field / battle |
| `flash_screen` | `color` | 画面全体の指定色フラッシュが終わるまで待機 | field / battle |
| `change_brightness` | `percent` | 指定した画面の明るさへ滑らかに変更し、完了まで待機 | field / battle |
| `shake_screen` | `frames` | 画面全体を指定時間だけ横揺れさせ、完了まで待機 | field / battle |
| `wait` | `frames` | 指定フレーム数を待ってから後続コマンドへ進む | field / battle |
| `recover_party` | なし | 活動パーティ全員のHP・MPを最大値へ戻し、全状態異常を解除 | field / battle |
| `open_shop` | `shop_key` | 指定ショップを開き、退出してフィールドへ戻るまで待機 | fieldのみ |
| `start_battle` | `battle_id`, `monster_keys` | 指定編成のイベントバトルを始め、帰還後に後続コマンドへ進む | fieldのみ |
| `move_party` | `direction`, `steps` | 指定歩数のフィールド移動演出完了まで待機 | fieldのみ |
| `move_actor` | `actor_id`, `direction`, `steps` | 指定actorの移動演出完了まで待機 | fieldのみ |
| `face_party` | `direction` | パーティの先頭を指定方向へ向け、同フレームで完了 | fieldのみ |
| `face_actor` | `actor_id`, `direction` | 指定actorを指定方向へ向け、同フレームで完了 | fieldのみ |

`branch.else` は空配列を許可するが省略しない。`then` と `else` の各コマンドへも同じ検証を再帰的に
適用し、入れ子の深さは16までとする。`else` にコマンドがあれば空の `then` は正常な分岐とし、
条件が真のときは何もしない。空のイベントと両側が空の分岐は警告にする。

#### パーティとアイテム

- `join_party` はすでに活動中なら成功扱いのno-opとする。初加入なら現在の加入レベル規則から
  Memberを作り、過去に離脱して保存済み状態があればその状態を再利用する。
- 活動パーティは1〜6人、戦闘参加は先頭5人という既存規則を変えない。6人時の加入は状態を
  変更せず、イベントを安全に中断する。
- `leave_party` は不在なら成功扱いのno-opとする。フィオラ、最後の1人、または既存の隊列不変条件を
  破る離脱は指定できない。離脱者の成長、HP・MP、装備は `character_states` に保持する。
- `give_item` と `take_item` は数量全体を適用できる場合だけ変更する。所持上限超過または数量不足で
  一部だけ増減しない。
- `give_item.show_message` は真偽値とし、省略時は `false` とする。エディタでは入手メッセージの
  ON/OFFを指定でき、新規コマンドの初期値はOFFとする。`take_item` には指定しない。
- ONなら全数量の追加に成功した後、`content/data/texts.json` の `event.received_item` に
  現在言語のアイテム名を `ITEM` として渡し、顔なしの標準MessageOverlayで1回表示する。
  複数個でも個数を表示せず、通知を閉じるまで後続コマンドを実行しない。
  OFFなら追加成功後に同フレームで後続コマンドへ進む。
- 入手通知の表示待ち中に同じコマンドを再適用しない。上限超過で追加できなかった場合は
  成功通知を表示しない。入手通知は会話ログへ追加しない。
- `take_item` はインベントリだけを対象とし、装備品を暗黙に外さない。
- 動的な上限・不足で実行できない場合は、そのコマンド以降を実行しない。開発時はイベントIDと
  コマンドpathを診断へ出し、本番では対応するシステム文言を表示して通常操作へ戻す。

イベント全体のロールバックは行わない。失敗し得る加入、取得、消費、移動を先に置き、完了フラグは
その後に置く。イベントエディタは、同じ分岐内で失敗し得るコマンドより前に `set_flag` がある場合を
警告する。

#### メッセージ

```json
{
  "command": "message",
  "message_id": "fairy_village.meet_alvan.first"
}
```

- `message_id` は `content/events/messages.json` の既存IDを参照する。翻訳後文字列をイベント定義へ
  複製しない。
- 顔グラフィックは参照先のメッセージレコードが持つ任意の
  `portrait_character_key` または `portrait_x` / `portrait_y` から解決する。
- 顔なしでは本文領域をWindow全幅にし、顔ありでは32×32pxの顔領域を確保する。左右配置、話者名、
  自動送りは画面仕様が必要になった時点で追加する。
- 本文は拠点名表示と同じ大きい表示文字用フォントを使う。日本語では `umplus_j12r.bdf` を使用する。
- メッセージ欄は日本語・中国語では12px文字の後に4px空ける16px間隔で2行、英語では8px文字の
  後に4px空ける12px間隔で3行を表示する。ページ分割も日本語・中国語は2行、英語は3行単位とする。
- メッセージWindowの初回表示時は、中央の水平線から上下へ8フレームで開く。開き切るまでは顔、
  本文、送り矢印を表示せず、決定入力も受け付けない。ページ送りではWindowを開き直さない。
- ページを開いた直後は本文を空にし、1フレームにつき1文字ずつ先頭から表示する。決定ボタンを
  押しているフレームは2文字ずつ表示する。表示途中の決定入力ではページを送らず、全文表示後の
  新しい決定入力で次ページまたはイベント進行へ移る。
- 全文表示後の入力待ちでは、イメージバンク0の `(88, 16)` を起点とする8×8pxの下向き矢印を
  Windowの本文領域右下へ表示し、30フレームごとに表示／非表示を切り替える。
- イベント中の決定入力は最上位のメッセージOverlayだけが受け取り、閉じた入力を次のコマンドや
  FieldSceneへ持ち越さない。
- `message` で表示した会話はログへ `message_id` と引数を記録する。旧セーブの通常UIログが持つ
  `text_key` も復元できるが、新しいイベントメッセージへは使用しない。演出専用でログへ
  残さない指定が必要になった場合は別属性として追加する。

#### 音声

```json
{"command": "stop_bgm"}
```

- `bgm_id` は拡張子なしの安定IDとし、現在の `BgmPlayer` と同じID解決を使う。同じIDへの切替は
  曲頭へ戻さない。
- `change_bgm` の派生となる `stop_bgm` は、現在の音量から30フレーム（60fpsで0.5秒）かけて
  フェードアウトし、BGM専用チャンネルだけを停止する。フェード完了後に後続コマンドへ進む。
  すでに停止中なら待たずに進む。イベントエディタでは独立した「BGM停止」コマンドとして選択する。
- 停止時はジングル後のBGM予約も解除する。停止後はイベント完了やゲームメニューからの復帰で
  自動再開せず、次の `change_bgm` またはSceneによるBGM切替要求まで無音を維持する。
  同じ曲を再指定した場合も通常音量で再生を開始できる。
- フェードは `BgmPlayer.update()` で進め、設定音量を変更しない。ゲームメニュー中は
  フェードの進行と再生を停止し、復帰後に残り時間から再開する。フェード中の明示的なBGM切替や
  即時停止は予約されたフェード停止を解除し、後から新しい曲を停止しない。
- イベントで切り替えたBGMは、別のBGMコマンドまたはScene遷移まで継続する。再生位置と現在曲は
  セーブしない。
- `se_id` も数値Sound番号ではなく安定IDとする。Pyxel Sound番号との対応は
  `app/audio/catalog.json` へ分離し、イベントエディタと本番コードが同じカタログを読む。
- 音量は `Settings.bgm_volume` / `se_volume` を使い、イベント定義へ音量設定を持たせない。

#### 画面フラッシュ

```json
{"command": "flash_screen", "color": "white"}
```

- `color` は将来の色追加を想定した安定した色名とし、現在は `white` のみ指定できる。
- 6フレームで画面全体を白へ変化させ、続く6フレームで通常色へ戻す。完了後に後続コマンドを実行する。描画中のSceneとOverlayの両方へ適用し、BGM音量は変更しない。
- 設定で画面フラッシュを軽減している場合は視覚効果を省き、後続コマンドへすぐ進む。

#### 画面の明るさと横揺れ

```json
{"command": "change_brightness", "percent": 50}
{"command": "shake_screen", "frames": 18}
```

- `change_brightness.percent` は0、25、50、75、100の整数とし、通常時を100%、完全な暗転を0%とする。
  エディタでは5つの百分率から選択し、初期値は100%とする。その他の値、文字列、小数、
  真偽値は生成時と実行時読込でエラーにする。
- 現在の明るさから指定値まで30フレーム（60fpsで0.5秒）かけて線形補間し、変更完了後に
  後続コマンドへ進む。コマンド開始時に指定値へ飛ばさず、暗くする場合も明るくする場合も
  同じ時間で変化させる。
- 明るさはイベント完了後や画面遷移後も維持する。100%を指定すると通常色へ戻る。
  フェード、フラッシュ、キャラクターの局所パレット効果と合成し、それらが終了しても
  指定した明るさを失わない。全SceneとOverlayを対象にし、BGM音量は変更しない。
- `shake_screen.frames` は `wait.frames` と同じく6以上の6の倍数の整数とする。
  エディタでは6フレームを初期値とし、数値欄の増減も6フレーム単位とする。
  0、負数、小数、真偽値、6の倍数でない値は生成時と実行時読込でエラーにする。
- 横揺れは6フレーム周期で左右最大2pxの描画カメラ移動とし、縦方向には動かさない。
  SceneとOverlayの両方を揺らし、partyやactorの実際の位置を変えない。
  指定回数目の `update()` で元の描画位置へ戻し、後続コマンドへ進む。
- 両コマンドはフィールドと戦闘で使える。演出中は通常操作とイベント以外の進行を止め、
  決定・キャンセルで短縮しない。ゲームメニュー中は演出時間も停止し、横揺れをメニューへ
  適用せず、復帰後に残り時間から再開する。
- 描画ではタイマーを進めない。中断時は横揺れを解除し、明るさの変更を現在値で止める。
  明るさと演出時間はセーブへ保存せず、ニューゲーム、ロード、タイトル復帰で100%に戻す。

#### パーティ全快とショップ

```json
{
  "command": "recover_party"
}
```

- `recover_party` は活動中のパーティ全員を対象に、HP・MPを最大値へ戻し、死亡（HP 0）、毒、
  麻痺、眠り、混乱を全て解除する。離脱中のキャラクター状態は変更しない。

```json
{
  "command": "open_shop",
  "shop_key": "FAIRY_HAMLET_ITEMS"
}
```

- `shop_key` は `content/data/shops.json` の既存 `shop_key` を参照し、イベントエディタでは
  登録済みショップから選択する。未知IDは生成時エラーにする。
- `open_shop` は標準フェードで本番のショップOverlayを開く。ショップ退出後のフェードが
  完了してから後続コマンドへ進み、イベントを起動したフィールド操作へ戻る。

#### 待機

```json
{"command": "wait", "frames": 12}
```

- `frames` は6以上の6の倍数の整数とし、6、12、18……フレームを指定する。
  エディタは6フレームを初期値とし、数値欄の増減も6フレーム単位とする。
  0、負数、小数、真偽値、6の倍数でない値は生成時と実行時読込でエラーにする。
- 開始後の `update()` で1フレームずつ数え、指定回数目で待機を完了して後続コマンドへ進む。
  連続した待機には余分なフレームを挟まない。
- フィールドと戦闘の両方で使用できる。待機中は通常操作、actorの自律移動、別イベント、
  移動口、エンカウント、戦闘進行を止め、画面描画とBGMは継続する。決定・キャンセルで短縮しない。
  フィールドのPC・表示中の人物actorの浮遊／歩行パターンも通常どおり継続する。
- 強制割り込みゲームメニュー中は待機の残り時間も停止し、復帰後に再開する。
  残り時間はイベントの一時状態として扱い、セーブへ保存しない。

#### 移動

```json
{
  "command": "move_party",
  "direction": "right",
  "steps": 2
}
```

```json
{
  "command": "move_actor",
  "actor_id": "village_elder",
  "direction": "left",
  "steps": 2
}
```

- `direction` は `up`、`right`、`down`、`left`、`steps` は1〜255の整数とする。
- 1セルずつ通常の歩行速度と向き変更を使い、全歩数の演出が終わってから次のコマンドへ進む。
- イベント制御移動中はプレイヤー入力、ランダムエンカウント、step/touch/interactトリガー、
  移動口によるマップ遷移を発火させない。移動口やイベントのセルも通行可能なら通過し、
  指定歩数を進む。actorの歩行ではpartyの到着処理を実行しない。
- マップ外や通行不可セルへ進む命令は状態を半セルに残さず、現在セルで停止してイベントを中断する。
- `move_actor.actor_id` は現在マップの安定したactor実体IDを参照する。actorの初期位置、見た目、
  通行設定はマップ側が所有し、イベント定義へ複製しない。
- partyはほかのactorの現在セルと移動先セルへ進まず、actorはこれらに加えてpartyの現在セルへ
  進まない。通行不可地形や人物の占有による中断と、移動口・イベントの発火抑止は区別する。

#### 向き変更

```json
{"command": "face_party", "direction": "right"}
```

```json
{"command": "face_actor", "actor_id": "village_elder", "direction": "up"}
```

- `direction` は `up`、`right`、`down`、`left` とし、歩数は指定しない。
- 現在セルで向きだけを変更し、同じフレームで後続コマンドへ進む。未完了の歩行がある場合は
  現在の論理セルへ戻して停止する。トリガーや移動口、エンカウントは発火させない。
- `face_actor.actor_id` は現在マップの `stationary` / `roaming` を参照する。
  `prop` / `treasure`、不在のactor、戦闘開始イベント内の指定は生成エラーとする。
- 会話中の `stationary` に `face_actor` を実行した場合は、イベント終了後も明示した向きを維持し、
  会話開始前の向きへの自動復元を取り消す。別actorを向けた場合は、会話相手の自動復元を維持する。
- 位置と向きはフィールドの一時状態とし、セーブへ保存しない。

## マップ上のトリガー

### 制作用形式

actor種別と共通スプライトシート参照はversion 4で追加され、現在の制作用マップの
`format_version` はdungeonの出現種別設定を追加した8とする。宝箱actor、
`sprite_source` と `floating` はversion 6で追加した。後者2つは省略時の既定値を持つ。
version 3のactorは `appearance_id` を
廃止し、用途に応じた `kind` と共通シート内の
`sprite_index` へ明示的に移行する。actorのないversion 3マップはversion番号だけを更新できる。
既存の `sites`、`arrival_points`、`event_triggers` はそのまま維持する。

```json
{
  "format_version": 8,
  "actors": [
    {
      "id": "village_elder",
      "position": [12, 8],
      "kind": "stationary",
      "sprite_index": 3,
      "sprite_source": "pc",
      "floating": true,
      "facing": "down"
    },
    {
      "id": "treasure_1",
      "position": [14, 8],
      "kind": "treasure",
      "contents": {
        "type": "gold",
        "amount": 500
      }
    }
  ],
  "event_triggers": [
    {
      "id": "meet_elder",
      "event_id": "fairy_village.meet_alvan",
      "activations": ["touch", "interact"],
      "anchor": {
        "kind": "actor",
        "actor_id": "village_elder"
      },
      "offsets": [[0, 0]]
    },
    {
      "id": "entrance_notice",
      "event_id": "fairy_village.entrance_notice",
      "activations": ["step"],
      "anchor": {
        "kind": "cell",
        "position": [4, 10]
      },
      "offsets": [[0, 0], [1, 0]]
    }
  ]
}
```

actorは次の4種類とする。

| `kind` | 用途 | 向き | 通常時の移動 |
|---|---|---|---|
| `prop` | 看板などの固定物 | なし。`facing` は指定しない | 移動しない |
| `stationary` | 定位置の人物・モンスター | 4方向 | 自律移動しない |
| `roaming` | 村人などの移動人物・モンスター | 4方向 | 30〜90フレームの待機後、上下左右またはその場待機を等確率で選ぶ |
| `treasure` | 報酬と開封状態を持つ宝箱 | なし。`facing` は指定しない | 移動しない |

すべてのactorに任意の `visibility_condition: {"flag_id": "story.open", "value": true}` を
指定できる。登録済みフラグ1つとbooleanだけを指定し、trueはON時、falseはOFF時に表示する。
省略時は常に表示する。表示条件を満たさないactorは描画（影を含む）、party・他actorに対する
衝突、actorアンカーのイベント起動、宝箱の開封対象から外し、自律移動の待機・歩行と宝箱の
アニメーション更新も停止する。フラグ変更はマップを読み直さず即時反映し、現在位置、向き、
待機時間、開封状態を保持して再表示する。イベントからの明示的な `move_actor`・`face_actor` は
非表示中も実行でき、再表示時は変更後の位置・向きを使う。制作操作は
[`map-editor.md`](./map-editor.md#イベント) を参照する。

宝箱以外の `sprite_index` は0以上の整数とし、マップ固有画像ではなく後述の共通シートを
左上から右、次に下へ読む番号とする。人物actorの `sprite_source` は `npc` または `pc` とし、
省略時は既存マップとの互換性のため `npc` とする。人物actorの任意boolean `floating` は、
その配置で浮遊表示するかを指定し、省略時は `false` とする。種族、`sprite_source`、
`sprite_index` から自動設定しない。同じ妖精の画像でも通常配置は `true`、ベッドや倒れ姿など
待機パターンを切り替えない配置は `false` または省略とする。`floating` は
`stationary` / `roaming` だけに指定でき、
`prop` / `treasure` に指定した場合は生成エラーとする。actorは演出や地形表現のため、
下地が通行不可のセルにも配置できる。表示中のactor自身がpartyと他actorの進入を防ぐ。
`stationary` と `roaming` はactorをアンカーとする
`touch` または `interact` で起動される際、未完了の自律歩行を初期セルへ戻し、partyの先頭と
actorを互いの方へ向ける。`stationary` はイベント終了時に会話開始直前の向きへ戻すが、
そのactorへ `face_actor` を実行した場合は明示した向きを維持する。
`roaming` は会話時の向きを維持し、その後の自律移動で向きを更新する。`prop` は会話や調査でも
向きを変えない。宝箱の中身、入力、演出、保存規則は
[`treasures.md`](./treasures.md) を正本とする。

actorの配置、現在位置、向き、待機タイマーはFieldの一時状態とし、セーブしない。
自律移動はマップ外、通行不可地形、party、表示中の他actorの現在セルと移動先セルへ進まず、
イベント中と通常メニュー中は更新を止める。イベントのメッセージ表示・入力待ち、`wait`、
画面演出中は、表示中の人物actorの画像パターンだけを更新し、現在位置、向き、自律移動の
待機時間は維持する。非表示actorは更新せず、イベント指定の移動対象は通常の移動更新だけで
歩行パターンを進める。`move_actor` と `face_actor` は向きと歩行を持つ
`stationary` / `roaming` に使用できるが、`prop` と `treasure` の参照は生成エラーとする。

`floating=true` の人物actorは、停止中に右足、立ち、左足、立ちの画像パターンを各20フレームで
切り替え、移動中は通常の歩行パターンと速度を優先する。現在は16×32px画像の描画Y座標を
ずらさない。
開始位相は `map_id` とactorの安定IDから自動決定し、同じ画面内の浮遊actorが同期しにくい
ようにする。位置や画像を変更しても位相は維持し、actor IDまたはmap IDを変更した場合だけ変化する。
この指定は停止中の画像パターンを制御し、妖精PC画像では共通影の表示にも使用する。actorの
現在セル、描画Y座標、移動先、衝突、
トリガー座標、足元Yによる描画順は変えない。イベントやメニューで自律移動を停止している間も、
フィールド上に表示されていればパターン切り替えを継続する。PC用画像を選んだactorも
`floating` の明示値だけに従う。妖精PCの画像を選んだactorは、`floating=false` の配置では
共通影も表示しない。人間など妖精以外のPC画像を選んだactorの影には影響しない。

### actor共通アセット

マップによらず使える次の画像ファイルを正本とし、`npm run images:build` で通常の
画像bundleへ収録する。

| actor | 正本パス | 画像ID | 配置 |
|---|---|---|---|
| `prop` | `content/images/actors/props.png` | `actors/props` | 16×16pxの単一チップを行優先で並べる |
| `stationary` / `roaming` | `content/images/actors/characters.gif` | `actors/characters` | 1キャラ48×128pxのブロックを行優先で並べる |
| `stationary` / `roaming`（`sprite_source=pc`） | `content/images/characters/ch_walk.gif` | `characters/ch_walk` | PCの`battle_sprite`と同じ番号の48×128pxブロックを使う |
| `treasure` | `content/images/actors/treasure.png` | `actors/treasure` | 閉・途中・開の16×16pxを横3コマに並べる |

`props.png` の幅と高さは16pxの倍数とする。`characters.gif` と `ch_walk.gif` の幅は
48pxの倍数、高さは128pxの倍数とする。1キャラブロック内は、16×32pxの画像を横3列、縦4行に並べ、
列は左足・立ち・右足、行は下・上・左・右の順とする。停止中は立ちコマを表示し、
移動中だけ右足・立ち・左足・立ちを各4フレームで循環する。透過色は他のZERO画像と同じパレット番号1
`#FF0080` を使う。シート不在、寸法不正、範囲外の `sprite_index` は、代替画像を出さず
実行時リソースエラーとする。

トリガーのアンカーは次の3種類とする。

| `anchor.kind` | 内容 |
|---|---|
| `cell` | `position` を基準とする。マップ上の見た目と独立した場所 |
| `object` | `object_id` の起点を基準とし、エディタでオブジェクトを動かすと追従する |
| `actor` | `actor_id` の現在位置を基準とし、ゲーム中のactor移動にも追従する |

`offsets` はアンカーからトリガー対象セルへの相対座標で、1件以上を指定する。cellアンカーの
通常の単一セルは `[[0, 0]]` とする。オブジェクトの表示範囲すべてへ自動展開せず、どのセルへ
触れるかを明示する。actorアンカーは `offsets: [[0, 0]]` に固定する。

初期activationは次の3種類とする。

| activation | 発火タイミング |
|---|---|
| `step` | プレイヤー操作による1セル歩行が完了し、対象の通行可能セルへ入った直後 |
| `touch` | プレイヤーが対象セルへ進もうとし、接触が成立した時。対象は通行不可でもよい |
| `interact` | パーティが停止中に対象セルを向き、決定操作がtriggeredになった時 |

`prop`、`stationary`、`roaming` は1体につきactorアンカーのトリガーを1件必ず持ち、`activations` は
`["touch", "interact"]`、`offsets` は `[[0, 0]]` に固定する。マップエディタはactor作成時、
または未設定の旧actorを選択した時にこのトリガーを自動追加する。発火方法とoffsetは
actorのUIへ表示せず、起動するイベントだけをactor編集欄で選ぶ。`treasure` は専用の開封処理を
持つためactorトリガーを登録せず、宝箱を参照するactorトリガーは生成エラーとする。

cell / objectアンカーの単独トリガーで選択できるactivationは `step` と `touch` だけとし、
`interact` を単独登録できない。起動条件の違う複数シナリオを同じセルへ重ねず、1イベント内の
`branch` で表す。同じマップ、activation、解決後セルが複数トリガーで重複する状態は生成エラーにする。

初期配置、ロード、到着地点への配置、イベント制御移動、押したままの入力復帰では発火しない。
`step` はセルへ入ったエッジで1回だけ、`touch` は1回の移動試行で1回だけ、`interact` は決定の
初回押下で1回だけ発火する。表示・移動・画面遷移を待つイベントの終了後は、起動に使った方向または
決定入力が離されるまで通常入力へ戻さない。条件分岐の空側など、待機する効果がなく起動した
フレーム中に完了したイベントは入力の解放を待たず、通常の歩行を継続する。

方向入力では、停止中のpartyを入力方向へ向けてから、移動先セルの `touch` を通行判定より先に
調べる。対象が通行不可セルでも、イベント開始時には対象側を向く。待機する効果があれば移動を
開始せず、`step` は評価しない。即時完了した場合と `touch` がなかった場合は通常の通行判定と
歩行を行い、歩行完了後に
`step` を調べる。決定入力では `interact` だけを調べる。待機するイベントは1回の操作で1件だけ
起動する。即時完了した `touch` の後は、到着セルの `step` を評価できる。

停止中の決定入力では、まず従来どおり向いている隣接セルの宝箱、`interact` の順に調べる。
どちらもなく、その隣接セルが `interact_through` を有効にしたオブジェクトの構成セルなら、
同じ方向のさらに1セル先について宝箱、`interact` の順に調べる。通過は1セルだけとし、複数の
対象オブジェクトを連鎖して越えない。`step`、`touch`、移動時の通行判定には影響させない。
奥の人物actorを起動した場合も、partyとactorはカウンターを挟んで互いの方向を向く。

### ゲーム用形式

object/cellアンカーは生成時に絶対セルへ解決する。移動するactorアンカーだけはactor IDと
offsetを残す。

```json
{
  "event_triggers": [
    {
      "id": "entrance_notice",
      "event_id": "fairy_village.entrance_notice",
      "activations": ["step"],
      "target": {
        "kind": "cells",
        "cells": [[4, 10], [5, 10]]
      }
    },
    {
      "id": "meet_elder",
      "event_id": "fairy_village.meet_alvan",
      "activations": ["touch", "interact"],
      "target": {
        "kind": "actor",
        "actor_id": "village_elder",
        "offsets": [[0, 0]]
      }
    }
  ]
}
```

本番ではactivationごとのセル索引をマップ読込時に作り、毎フレーム全イベントを走査しない。

## ゲーム開始からの起動

ニューゲーム開始直後のイベントは空間上のトリガーとして扱わず、ニューゲーム成立時の安全な
境界から `worldmap.prologue` を明示的に起動する。開始イベントのコマンド列は通常イベントと
同じく `content/events/worldmap.json` を正本とし、実行方法だけをスタート処理が所有する。

開始イベントは、初期フィールドの適用とフィールドBGMの開始後、完全暗転中に起動する。これに
よりフェードイン後はイベントを表示した状態となる。保存データのロード時には起動しない。
イベントを再実行する必要がある場合は、通常イベントと同様にフラグ条件で分岐させる。

初期配置で `step` を発火させる代替にはしない。ロード地点やマップ到着地点へ配置された際の
意図しない発火を防ぐため、位置トリガーの発火条件は変更しない。

## イベントバトルと戦闘からの起動

フィールドイベントの `start_battle` は、戦闘IDと敵編成を指定する。

```json
{"command": "start_battle", "battle_id": "shrine_guard", "monster_keys": ["Giant Spider", "Giant Spider"]}
```

`battle_id` は全イベントで共通の `lower_snake_case` 識別子、`monster_keys` は
`content/data/monsters.json` の `name_en` を1〜5件並べる。複数の開始コマンドで同じIDを
使用してよい。敵編成を指定しないバトル開始は認めない。開始時は通常エンカウントと同じ画面遷移を
使い、不意打ちは発生しない。イベントバトルでは全体コマンドの「にげる」を灰色で表示して
選択できない。開始元のイベントは戦闘が終わるまで待機し、勝利または逃走で
フィールドへ戻るフェードの終了後に後続コマンドを再開する。全滅時は開始元イベントを中断する。

イベント定義へ任意の `battle_start_id` を設定すると、そのIDのイベントバトルで最初の味方手番に
入った時、コマンドウィンドウを開く直前にイベントが1回起動する。該当イベントがある場合は
コマンドウィンドウの表示を保留し、イベント完了後に初回戦闘ヒントを表示する。ヒントを閉じた後に
コマンドウィンドウを開く。敵に先手を取られた場合は、味方の手番まで待つ。味方の手番が来る前に
戦闘が終われば起動しない。

```json
{"id": "guard_opens", "battle_start_id": "shrine_guard", "commands": [
  {"command": "message", "message_id": "shrine.guard_opens"}
]}
```

同じ `battle_start_id` を登録できるイベントは全名前空間を通じて1件だけとする。登録のないIDの
バトルは通常どおり進む。戦闘開始イベント中は戦闘入力を止め、メッセージOverlayの終了後に
同じ戦闘状態へ戻る。加入、離脱、ショップ、移動、別のバトル開始は登録イベント内で使用できず、
入れ子の分岐も含めて生成時に検証する。戦闘IDと発火済み状態はセーブしない。

HP変化や勝敗など、戦闘途中の条件付きトリガーは別途仕様を定めて追加する。

## 実行モデル

```text
FieldScene / BattleScene
        │  EventInvocation(event_id, source)
        ▼
EventCoordinator
        │  定義と明示的なサービスだけを渡す
        ▼
EventRunner ──→ 条件評価／SaveData・PartySystem・InventorySystem
        │
        ├──→ MessageEffect ──→ MessageOverlay ──→ 完了通知
        ├──→ AudioEffect ────→ BGM／SEサービス ─→ 完了通知
        ├──→ MovementEffect ─→ FieldScene ──────→ 完了通知
        └──→ OpenShopEffect ─→ ShopOverlay ─────→ 退出後に完了通知
```

1. Sceneが通常更新の安全な境界でトリガーを検出する。
2. EventCoordinatorは別イベント実行中でないことを確認し、EventCatalogから完全IDを解決する。
3. EventRunnerはコマンド位置とbranchのスタックを作る。
4. 同期コマンドは既存Systemへ委譲して結果を受け、直ちに次へ進む。
5. メッセージ、移動、ショップはEventEffectを1件返して待機する。SceneManagerまたはSceneがOverlay／演出を
   開き、完了結果をRunnerへ返す。
6. 全コマンド完了後、または `end_event` の実行後、CoordinatorがRunnerを破棄し、入力リリース待ちを経てScene操作へ戻す。

Runner自身はPyxel、Window、具体的Scene、ファイルI/Oを参照しない。巨大なGame Contextも
受け取らず、条件参照と状態変更に必要な `SaveData`、PartySystem、InventorySystemなどを
明示的に渡す。Sceneをまたぐ効果はTransitionまたはEventEffectとして返し、Runnerから
`Game.scene` を直接変更しない。

Runnerの状態は実行中だけ有効であり、SaveDataへコマンドindexやbranchスタックを保存しない。
メニュー、セーブ、別イベントの起動も許可しない。アプリ終了やロード後はイベント開始前の
保存地点から再開し、フラグなど完了済みの永続状態によって通常の分岐を選び直す。

## エラーと中断

- ビルドで発見できる不正参照、未知属性、使用context違反は実行時へ持ち込まず生成を失敗させる。
- 実行時に動的理由でコマンドを完了できない場合、そのコマンドは状態を変更せずイベントを中断する。
- 中断時は開いているイベントOverlayとイベント制御移動を閉じ、セル途中へ状態を残さない。
- 開発起動ではイベントID、JSON path、理由を画面と標準エラーへ出す。本番では内部IDを見せず、
  持ち物上限など利用者が対処可能な場合だけ対応文言を表示する。
- イベント定義の欠落・破損はセーブデータを初期化する理由にしない。該当イベントを起動せず、
  セーブ状態を保持したまま診断する。
- 前の同期コマンドまでの変更はロールバックしない。このため完了フラグを最後に置く規則を
  エディタ警告とレビューで守る。

## イベントエディタ

画面全体（フォーム・リンク・ダイアログを含む）でブラウザ標準の右クリックメニューを表示しない。

### 役割

イベントエディタはJSONを隠す独自データベースではなく、同じJSONを安全に作る入力支援ツールと
する。手編集、ツール編集、非対話ビルドのすべてが `scripts/event_pipeline` の同じparserと
validatorを使う。

マップは空間編集、イベントはコマンド木編集で操作が異なるため、イベント本文をマップエディタへ
埋め込まない。マップエディタの「イベント」タブはトリガーを配置し、既存イベントを選択し、
選択したイベントをイベントエディタで開くところまでを担当する。

### 画面

ヘッダーの「マップ／イベント」で、同じローカルサーバー上のマップエディタとイベントエディタを
切り替える。両エディタは同じヘッダー高とブランド領域幅を使い、切り替え前後でナビゲーションの
位置を変えない。イベント画面では編集対象・生成先のファイルパスをヘッダーに表示しない。
イベントファイルの選択と「新規namespace」ボタンはヘッダーに置く。namespace名の入力欄は
常設せず、「新規namespace」を押したときに開くダイアログへ置く。
未保存変更がある状態で別のエディタへ切り替える場合は独自ダイアログを表示し、
「保存して移動」「変更を破棄して移動」「キャンセル」から選べるようにする。
「保存して移動」は保存に成功した場合だけ移動する。ブラウザ自体を閉じる、再読み込みするなど
独自ダイアログを使えない操作ではブラウザ標準の確認を使う。

画面は次の3列を基本とする。

1. 左: 「フラグ／イベント／ミッション／メッセージ」を1行に並べたタブと、選択対象の一覧。幅は320〜340px。
2. 中央: 選択したグローバルフラグのID・制作メモ、イベント属性・コマンド列・branchの入れ子、ミッション、または多言語メッセージ編集
3. 右: validatorの問題一覧

左列ではタブ、選択対象の見出し、「追加」ボタンを固定し、一覧部分だけをスクロールする。
フラグ・イベント・ミッション・メッセージの各タブで同じ動作とし、一覧の末尾でも追加できる。
画面幅が狭い場合も左列の高さを画面内に収まる範囲に制限し、一覧を独立してスクロールできるようにする。

グローバルフラグは左の一覧から選び、中央でIDと制作メモを編集・削除する。追加時は追加した
フラグを選択し、並べ替えても選択対象を維持する。編集・削除・並べ替えはUndo／Redoの対象とする。
イベント／フラグのIDと制作用 `note` は自由入力できる。フラグ一覧はnamespaceを切り替えても
共通である。参照値は原則としてリストまたは検索付き
セレクターから選ぶ。
フラグ一覧とフラグ参照の選択欄にはIDに加えて制作メモの先頭最大20文字を表示し、超過分は
省略記号で示す。改行・連続空白は1つの空白にまとめる。イベント・ミッションの条件と
`set_flag` の選択欄で共通の表示を使い、選択値・保存値はフラグIDのままとする。
中央の制作メモ編集欄では全文を保持する。

| 入力 | 選択元 |
|---|---|
| `flag_id` | `content/events/flags.json` の宣言済みグローバルフラグ |
| `character_key` | `content/data/characters.json` |
| 顔 | `content/images/faces/faces.png` の32×32px一覧 |
| `item_key` | `content/data/items.json` |
| `message_id` | `content/events/messages.json` |
| `bgm_id` | 本番BGMカタログ／生成元 |
| `se_id` | 安定SEカタログ |
| `actor_id` | 全マップのactor一覧。参照元マップとの一致は保存・生成時に横断検証する |

メッセージは左の一覧から新規作成・選択し、中央で `message_id`、任意の顔、日本語、英語、
簡体字中国語を編集する。新規IDは `<現在のnamespace>.message_<連番>` を既定値にするが、
別の名前へ変更できる。イベントのmessageコマンドはこの一覧からIDを選択し、顔は指定しない。
顔の編集欄は顔が設定されているときだけ選択中の顔を2倍表示し、顔なしでは表示しない。
「顔を選択」を押したときだけダイアログを開く。
ダイアログでは `faces.png` を2倍表示した一覧から画像自体を選択する。選択したセルが
`characters.json` の顔座標と一致する場合は `portrait_character_key`、それ以外は
`portrait_x` / `portrait_y` を保存する。顔または「顔なし」を選ぶとダイアログを閉じ、
「顔なし」では顔指定の属性を削除する。
messageコマンドでは、選択中のメッセージの日本語をゲーム内と同じ1行単位でプレビューする。
日本語が未入力、または参照先IDが存在しない場合は、その状態をプレビュー欄に表示する。

### 操作と安全策

- 起動時に全イベント、フラグ、イベントメッセージ、マスターデータ、音声を読み、参照索引を作る。
- イベントファイルはヘッダーのリストを選択した時点で切り替える。独立した切替ボタンは設けない。
  最後に開いたnamespaceをブラウザへ保存し、次回起動時にURLで別namespaceを指定されていなければ
  復元する。「新規namespace」を押すと入力ダイアログを開き、有効なnamespaceを入力すると空の
  定義として開き、最初の保存時にファイルを作成する。namespaceはマップIDの一覧に制約されない。
- 「コマンド追加」を押すと `message` コマンドを追加し、種類の選択欄とメッセージ属性を表示する。
  ルートとbranchの `then` / `else` のどの追加位置でも `message` を初期選択し、追加を1回のUndo単位とする。
  追加後も種類を変更でき、変更時は旧種類の属性を破棄して新種類の初期値へ置き換える。
  変更は1回のUndoで元に戻せる。未使用属性はJSONへ残さない。
- コマンドはドラッグ＆ドロップした位置へ移動する。ルートとbranchの `then` / `else` の間も
  移動でき、1回のドロップを1回のUndo単位とする。branch自身をその子孫へ移動する操作は許可しない。
- フラグ、イベント、ミッション、メッセージは各一覧のドラッグハンドルから並べ替えられる。並べ替えた配列順を
  制作用JSONへ保存し、1回のドロップを1回のUndo単位とする。この順序はイベントの実行順、参照、
  条件判定には影響しない。選択中のイベントまたはメッセージは移動後も選択状態を維持する。
- conditionは「すべて／いずれか／否定／フラグ／メンバー／アイテム」の部品で組み立てる。
- ID変更・削除後は同じvalidatorで全参照を検証し、問題一覧へ不整合を表示する。参照先の
  一括変更とセーブ済みフラグIDの移行は初期版では自動化しない。
- Undo/Redoは1回のコマンド追加、削除、並べ替え、属性変更を単位とする。
- 未保存変更がある状態でページを閉じる場合や別namespaceへ切り替える場合は確認する。
- エラーがある間は保存しない。警告は内容を表示したうえで保存できる。
- 問題一覧は編集のたびに自動更新するため、独立した検証ボタンは設けない。保存時にも同じ
  validatorを再実行する。
- 保存は変更対象のイベントファイルと共有 `flags.json`、`messages.json` を更新する。他の
  イベントファイルは再整形しない。
- 保存成功後にゲーム用イベントとイベントメッセージを生成する。マップ側の未保存変更は
  イベント保存に含めない。

初期版では任意JSON入力欄、Python式、変数、ラベル／goto、並列実行、タイムライン編集、イベントの
途中再開を提供しない。必要な機能は型付きconditionまたはcommandとして追加する。

## マップエディタのイベント操作

- 「イベント」タブでcellまたはobjectをアンカーにして単独トリガーを追加する。
- 宝箱以外のactorのトリガーはactor作成・選択時に自動追加し、actor編集欄でイベントを選ぶ。
  actorトリガー自身はトリガー一覧、発火方法、offset編集に表示しない。
- キャンバスではトリガー対象セルを半透明の枠、actorを共通スプライトの16x16画像で表示する。
  人物系actorは現在の向きに対応する静止パターンを使う。選択中のactorは画像を隠さないピンクの
  外枠で強調し、画像を読み込めない場合に限って丸印と向きのマーカーへフォールバックする。
  単独トリガーは常時判別できる濃さで表示し、「イベント」タブではさらに強調する。
  activationは左のトリガー一覧と右の編集欄に表示する。
- 「イベント」タブでは、actor配置セルとactorアンカーを含む全トリガーの発火対象セルを薄い
  ピンクで塗って同色の枠で囲む。同じセルに複数の設定が重なる場合も表示は一度とし、既存マーカーを手前に表示する。
- イベントタブで「object trigger」を選び、キャンバス上のobjectを指定してトリガーを追加できる。
  初期offsetは `[[0, 0]]` とする。
- actorのスプライトは、`prop` と人物系で対応する共通シートを切り替え、画像候補を表示する
  ダイアログから選択する。`sprite_index` の直接入力欄は設けない。`treasure` は固定の専用画像と
  中身の編集欄を表示し、画像選択とイベント操作を表示しない。
- actor編集欄の「イベントを追加」は、現在のマップの親マップID（単一エリアなら現在のマップID）を
  namespaceとしてイベントエディタを開き、
  イベントエディタの「追加」と同じ規則で `event_<連番>` を未保存状態で追加する。イベント保存時に
  引き継いだマップも保存し、新規イベントの完全IDを対象actorのtriggerへ紐づける。
  イベントまたはマップの保存に失敗した場合は移動せず、編集を継続できる状態を保つ。
- cellアンカーとoffsetはキャンバスで移動・複数選択できる。objectアンカーは対象の移動へ
  追従し、トリガーだけの絶対座標を保持しない。
- trigger IDは配置時にマップエディタが内部で自動採番する。編集欄には出さず、一覧と選択情報では
  代わりに参照先のイベントIDを識別子として表示する。
- イベントIDはイベントカタログから選ぶ。未作成イベントIDを文字列で仮入力する機能は設けない。
- イベント本文の新規作成と編集は統合入口 `npm run tools:editor` からイベントエディタへ
  切り替えて行う。選択済みトリガーの「イベント本文を編集」では、そのnamespaceとイベントを
  直接開く。actorから追加したイベントは保存時にマップへ反映される。その他のイベントを保存した
  場合は、マップエディタを再読込してイベント一覧を更新する。
- 問題一覧は不正なトリガー、イベント定義、参照先actorのJSON pathと理由を表示する。
- マップ保存はイベント参照を検証し、成功時だけ制作用マップとゲーム用マップを更新する。

## 検証

### イベント単体

次をエラーにする。

- 不正なformat version、名前空間、ローカルID、グローバルフラグID、またはファイル名との不一致
- 名前空間、完全イベントID、グローバルフラグIDの重複
- 未知のフィールド、condition、command、または必須属性の欠落
- 宣言されていないフラグ、存在しないキャラクター、アイテム、イベントメッセージ、BGM、SEの参照
- 0以下または上限外の数量・歩数、空のcondition集合、branchの深さ超過
- フィオラを対象にした `leave_party`
- 数量や歩数など、単体で静的に判定できる不正値

### マップとの横断検証

次をエラーにする。

- 存在しないイベントID、object ID、actor IDの参照
- 宝箱actorを参照するイベントトリガー、または `move_actor` / `face_actor` で固定actorを参照する状態
- 不正、空、重複、範囲外のトリガーoffsetまたは解決後セル
- `step` の対象が通行不可である状態
- 同じactivationと解決後セルを複数トリガーが占有する状態
- actorを参照するイベントが、そのイベントを起動するマップに存在しない `actor_id` を移動・向き変更する状態

別マップのactorを動かすことはできない。1イベントが複数マップから参照される場合、
`move_actor` / `face_actor` の各IDが全参照元マップに存在しなければエラーにする。マップ固有のactorを動かす
イベントはマップ固有のイベントファイルへ分けることを推奨する。

空のイベントまたはbranchの両側が空の場合は警告にする。片側だけが空の分岐は
正常な定義として扱う。
未参照イベント、未使用フラグ、
連続する同値設定、完了フラグの配置は、シナリオデータが増えた段階で静的解析を追加する。
警告は生成を妨げない。

## 実装状況と拡張順序

1. source parser、全体索引、validator、compiler、`EventCatalog` は実装済み。
2. condition、同期コマンド、PartySystem、待機型Runner、メッセージ／音声／移動効果は実装済み。
3. map format 6、actor、宝箱、step/touch/interactトリガーとフィールド接続は実装済み。
4. 同じvalidatorを使うイベントエディタと、トリガーを扱うマップエディタは実装済み。
5. ID付きイベントバトルと最初の味方コマンド受付時のトリガーは実装済み。
6. 戦闘途中の条件付きトリガーと戦闘用conditionは必要時に追加する。

最初の縦方向の確認には、「NPCの前で決定 → 顔付きメッセージ → アイテム取得 → フラグ設定 →
再度決定すると別メッセージ」の1イベントを使う。その後、イベント制御移動と加入・離脱を追加し、
Runnerとマップトリガーを一度に作り込みすぎない。

## 受け入れ条件

- JSONを手編集してもイベントエディタで編集しても、同じ検証とゲーム用生成結果になる。
- イベント、フラグ、キャラクター、アイテム、文言、音声、actorの不正参照をゲーム起動前に検出できる。
- step、touch、interactが定めた入力エッジで1回だけ発火し、初期配置やイベント移動では発火しない。
- 通行不可セルへのtouchでも、partyが入力方向を向いてからイベントを開始し、セルへは侵入しない。
- 宝箱以外のactorを作成・選択するとtouch・interactの固定トリガーが1件自動設定され、
  interactを単独トリガーとして選択できない。
- `interact_through` を有効にしたオブジェクト越しに、1セル奥のactorイベントを決定入力で起動できる。
- 人物actorのtouch・interact起動時は、partyの先頭とactorが互いの方を向いてからイベントを開始する。
- `stationary` actorは会話イベントの終了後に開始直前の向きへ戻り、`roaming` actorは会話時の
  向きを維持する。
- 人物actorは配置ごとの `floating` を保存でき、`true` の配置だけが
  `map_id` とactor IDから決まる安定した開始位相で停止中の画像パターンを切り替える。
  描画Y座標は変更しない。
  同じ妖精画像でも `false` の配置は動かず、妖精PC画像なら共通影も表示しない。
  prop／treasureの `floating` は生成時に拒否される。
- ニューゲームでは初期フィールドの適用後に `worldmap.prologue` が起動し、ロードでは起動しない。
- フラグ、パーティ、インベントリへの操作が既存の上限・隊列・セーブ規則を迂回しない。
- flag、メンバー、アイテムとall/any/notを組み合わせ、then/elseの片方だけを実行できる。
- 顔あり／なしのメッセージを表示し、決定入力が下のSceneへ漏れない。
- メッセージ表示・入力待ち、`wait` 中もPC・表示中の人物actorの画像パターンが切り替わり、
  自律移動、移動口、別イベント、エンカウントは進行しない。イベント指定の移動は従来の速度で進む。
- BGMとSEが安定IDから再生され、Settingsの音量に従う。
- `stop_bgm` はフェードアウト後に停止し、予約曲やゲームメニュー復帰で自動再開しない。
- `start_battle` のIDと敵編成をエディタで指定でき、対応する戦闘開始イベントを1件登録できる。
- 登録イベントは最初の味方コマンド受付時に1回発動し、戦闘入力を止め、終了後に戦闘へ戻る。
- 勝利・逃走後は開始元イベントの後続コマンドを再開し、全滅時は再開しない。
- パーティとactorが指定方向へ指定歩数だけ順次移動し、移動中に別トリガーや移動口を起動しない。
- `face_party` / `face_actor` は位置を変えず指定方向へ向け、後続コマンドへ同フレームで進む。
- `wait` は6フレーム単位の指定時間を待ち、決定・キャンセルで短縮せず後続コマンドへ進む。
- 明るさは0%／25%／50%／75%／100%へ滑らかに変化し、フェードやフラッシュの終了後も維持する。
- 横揺れは6フレーム単位の指定時間だけ続き、終了・中断時に描画位置を復元する。
- `give_item` の通知をON/OFFでき、ONなら個数を含めない入手通知を1回表示してから後続へ進む。
- 会話相手へ `face_actor` を実行した場合はイベント終了後もその向きを維持する。
- イベント中に別イベントや手動セーブを開かず、完了または安全な中断後にScene操作へ戻れる。
- 将来の戦闘開始や選択肢を、既存イベントファイルの意味を変えず新commandとして追加できる。
- 同じ起動プロセス内でマップエディタとイベントエディタを切り替えられる。
