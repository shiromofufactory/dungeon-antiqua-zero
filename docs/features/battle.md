# 戦闘用マスターデータと表示

## 目的

本書は、戦闘Sceneがキャラクターとモンスターのマスターデータから戦闘用画像と基本能力値を
解決する規則、およびゲージ値による行動順とタイムライン表示を定める。本書で定める能力値を
使った詳細な命中・ダメージ計算など、本書に記載しない戦闘ルールは別途BattleSceneと
戦闘Ruleの仕様で定める。

## 参照元と責務

- 正本は `content/data/characters.json` と `content/data/monsters.json` とする。
- ゲームは生成済みの `app/data` を読む。`app/data` は直接編集しない。
- BattleSceneまたは戦闘専用Rendererが、参加者の安定キーからマスターレコードを解決して
  描画する。表示名、配列順、敵種別による画像・アイコン座標の分岐を持たない。
- `Member`、戦闘ルール、セーブデータへ描画用の座標や画像サイズを複製しない。

## キャラクター

`characters.json` の各レコードは、既存の顔グラフィック座標に加えて次の表示データを持つ。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `icon_x` | integer | 戦闘シーン下部のタイムライン用16×16pxアイコンの、イメージバンク1内の左上X座標 |
| `icon_y` | integer | 同アイコンの左上Y座標 |
| `battle_sprite` | integer | `characters/ch_battle` の縦32px単位の戦闘スプライト位置を示す非負インデックス |

タイムラインアイコン座標は0以上の16px単位とし、イメージバンク1の範囲内に収める。
`battle_sprite` の描画元Y座標は `battle_sprite * 32` とする。スプライトの実際の切り出し幅、
配置、重なり順は戦闘Sceneが決め、キャラクター名を使って特例を作らない。

味方の死亡状態は現在HPが0以下、瀕死状態は毒状態、または生存中かつ現在HPが
`最大HP // 4` 以下の場合とし、DA2と同じ判定条件を使う。通常時の瀕死表示は戦闘画像の
左から7番目にある16×32px、死亡表示は左から10番目にある24×32pxのパターンを使う。
死亡と瀕死が同時に成立する場合は死亡表示を優先する。歩行、防御、詠唱、被ダメージなどの
一時ポーズ中は瀕死表示より一時ポーズを優先するが、死亡表示は常に最優先とする。

## モンスター

`monsters.json` の各レコードは次の戦闘用データを持つ。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `image_id` | string または integer | モンスター画像のファイル名（拡張子なし）。`n-1` は `content/images/monsters/n-1.png` を指す |
| `width` | integer | モンスター画像の幅（px） |
| `height` | integer | モンスター画像の高さ（px） |
| `icon_x` | integer | 戦闘シーン下部のタイムライン用16×16pxアイコンの、イメージバンク1内の左上X座標 |
| `icon_y` | integer | 同アイコンの左上Y座標 |
| `mhp` | integer | 戦闘開始時の最大HPおよび初期HP |
| `mmp` | integer | モンスターの最大MP |
| `attack` | integer | 物理攻撃の攻撃力 |
| `hit` | integer | 物理攻撃の基本命中率 |
| `defense` | integer | 物理攻撃に対する防御 |
| `evasion` | integer | 物理攻撃に対する回避率 |
| `agi` | integer | タイムラインのゲージ計算に使う素早さ |
| `int` | integer | 敵の行動選択に使う知恵（思考のかしこさ） |
| `special` | string | 使用できる特殊行動。日本語1文字を1種類の行動キーとして区切りなしで連結する |
| `extra` | string | 通常攻撃に付随する追加攻撃の種類。`items.json` の `extra` と同義 |
| `spells` | string | 使用できる呪文の `spells.json` `name_en` キー。複数は改行区切り |
| `treasure_item` | string | 戦闘終了後にドロップするお宝の `items.json` `name_en` キー |
| `treasure_rate` | integer | お宝のドロップ率。1につき1/16 |
| `lv` | integer | 経験値と熟練度計算に使う敵LV |
| `early_appear` | integer | 撃破経験値計算に使う最早出現値 |
| `max_occ` | integer | 撃破経験値計算に使う最大同時出現数 |
| `gold` | integer | 撃破時に得るGold |

`image_id` は空でない文字列または0以上の整数とし、画像ファイルは
`content/images/monsters/<image_id>.png` に置く。`width` と `height` は画像の実寸をpxで保持する。
タイムラインアイコンの座標規則はキャラクターと同じである。
`mhp` は1以上の整数とする。戦闘開始時に個体ごとの可変状態へコピーし、現在HPが0の
モンスターを死亡状態とする。`agi` は0以上の整数とする。マスターレコード自体は戦闘中に変更しない。
`mmp` と `int` は0以上の整数とする。現在MPを扱う際は `mmp` を戦闘ごとの可変状態へコピーし、
最大MPのマスター値を書き換えない。`int` による行動選択の具体的な判定は敵AIの仕様で定める。
`attack`、`hit`、`defense`、`evasion` は0以上の整数とし、DA2と同じ役割で物理攻撃の
命中判定とダメージ計算へ渡す。ただし、ZEROのモンスターの回避率には `evasion` の値を
直接使い、DA2のように `agi` から導出しない。一時的な能力変化は戦闘ごとの可変状態へ保持し、
これらのマスター値を書き換えない。

`special` は空文字、または1行動につき日本語1文字のキーを区切りなしで連結した文字列とする。
たとえば `逃突` は「逃」と「突」の2種類の特殊行動を持つ。具体的な各キーの挙動は敵AI・特殊行動の
仕様で定め、表示名として扱わない。`extra` は `items.json` と同じく、空文字、眠、乱、死、黙、
吸、止、毒、麻、破のいずれかとする。`spells` は空文字、または `spells.json` に存在する
`name_en` キーを改行で区切った文字列とし、空行は挟まない。値の分割と安定キーへの解決は
データ読込境界で一度だけ行い、行動選択のたびに文字列を解釈し直さない。

`treasure_item` は `items.json` に存在する空でない `name_en` キーとする。`treasure_rate` は
0から16の整数とし、ドロップ確率を `treasure_rate / 16` で表す。0はドロップなし、16は
確定ドロップとなる。ドロップ判定は戦闘終了後に行う。1戦闘での判定回数、複数ドロップ、
所有上限到達時の扱い、結果表示は、敵ドロップ機能を実装する際に別途定める。

## 検証

共有JSONの検証では、キャラクターとモンスターの `icon_x`、`icon_y` がイメージバンク1内の
16px単位座標であることを確認する。キャラクターの `battle_sprite` は0以上の整数、
モンスターの `image_id`、`width`、`height`、`mhp`、`mmp`、`attack`、`hit`、`defense`、
`evasion`、`agi`、`int`、`lv`、`early_appear`、`gold` は上記の型と範囲を確認する。
`special` は改行を含まない文字列、`extra` はアイテムと同じ許容値、`spells` は改行区切りの
各キーが `spells.json` に存在し、空行を含まないことを確認する。
`treasure_item` は `items.json` に存在する空でないキー、`treasure_rate` は0から16のintegerで
あることを確認する。
`max_occ` は1以上のintegerとする。データ上の参照用 `exp` はゲーム内計算に使わない。

画像の追加・変更時は `npm --prefix content run validate` を実行する。共有データを
ゲーム用へ反映する場合は `npm run sync`、画像をゲーム用に更新する場合は
`npm run image-build` を続けて実行する。

## 受け入れ条件

- キャラクターとモンスターのタイムラインアイコンは、各レコードの `icon_x`、`icon_y` が示す
  イメージバンク1の16×16px領域から描画される。
- キャラクターの戦闘スプライトは、各レコードの `battle_sprite` が示す縦32px単位の位置から
  描画される。
- 味方のHPが0以下なら死亡、毒状態または生存中かつHPが最大HPの4分の1以下なら瀕死と判定し、
  瀕死は左から7番目の16×32px、死亡は左から10番目の24×32pxで表示される。
- 死亡表示は瀕死と他の一時ポーズより優先される。
- 死亡した味方は戦闘開始時および戦闘中のタイムラインから除外され、手番が回らない。
- 全員が死亡すると `battle.defeat` を入力待ちで表示し、入力後は本編で
  `BattleResult.DEFEAT`、単独テストでfixtureの再開始となる。
- モンスター画像は、各レコードの `image_id`、`width`、`height` から解決される。
- モンスターの現在HPは `mhp` で初期化され、0になった個体は死亡状態になる。
- モンスターの最大MP、知恵、特殊行動、追加攻撃、使用呪文は、それぞれ `mmp`、`int`、
  `special`、`extra`、`spells` から読み込まれる。
- お宝のアイテムキーと16分率のドロップ率は `treasure_item`、`treasure_rate` から読み込まれる。
- モンスターの攻撃力、命中率、防御、回避率は各マスターフィールドから読み込まれ、
  回避率へ `agi` による補正を加えない。
- 表示名、配列順、敵種別を画像またはアイコンの識別に使わない。

## 戦闘Sceneと単独テスト

本編の戦闘処理、Scene固有状態、入力の解釈、描画は `app/scenes/battle.py` の
`BattleScene` が所有する。`BattleScene` はPyxel入力を直接取得せず、呼び出し元が1フレーム分の
`InputState` を `update()` へ渡す。現在のパーティ、所持品、遭遇モンスター、Settings、画像、
フォント、音声などの依存も呼び出し元から渡し、本編から `tools/` を参照しない。

`tools/screen_mocks/battle.py` は、本番の `BattleScene` へ疑似状態を注入して単独起動する
Composition Rootとする。`BATTLE_TEST_PARTY` で指定した各メンバーを生成し、レベル、隊列、
HP、MPの指定があれば初期状態へ反映する。HPは3桁幅の空白埋めとし、先頭を0で埋めない。
キャラクター名、戦闘スプライト、タイムラインアイコン、モンスター名、画像、画像寸法は、
いずれも生成済みのゲームデータから解決する。単独テスト固有のパーティ、敵編成、所持品だけを
fixtureとして保持し、戦闘処理を複製しない。

### 戦闘勝利リザルト画面モック

勝利後リザルトのレイアウト検討用として、`tools/screen_mocks/battle_result.py` に静的な単独モックを置く。
画面の4pxグリッド（64×60）を横2列、縦3段に分け、32×20グリッドのメンバーWindowを
行優先で6つ配置する。表示順はフィオラ、セリオン、アルヴァン、エリカ、ラグナ、ダインとする。
フィオラの内部レベルは50とし、ほかのメンバーはキャラクターデータの加入レベル差から算出する。
HP・MPは算出した最大値まで回復した状態を使う。

各Windowの左上 `(2, 2)` へ、キャラクターデータの `battle_sprite` が示す行から
戦闘時グラフィックの先頭ポーズ（元X座標0、16×32px）を置く。ダインは戦闘時グラフィックが
未作成のため、この領域を空欄とする。テキストのX座標は、2種類の熟練度を並べる行に合わせて
すべて8グリッドで統一する。Y座標2に日本語のキャラクター名、5に `HP 現在値/最大値`、
8に `MP 現在値/最大値`、13に装備中武器の熟練度、16に
使用可能な呪文系統の熟練度を置く。熟練度はアイコンと `レベル-進行度` で表し、進行度は
2桁で表示する。武器は左手、右手の順、呪文はミスティック、セイクリッド、ネザーの順とする。
該当する武器または呪文系統がない行は表示しない。このモックは表示確認だけを目的とし、
QまたはEscapeで終了する。HP・MPと熟練度の英数字、空白、区切り記号にはステータス画面と
同じ全角表記と日本語フォントを使い、タグ付きアイコンも同じ描画規則で数字へ縦位置を揃える。

### 戦闘開始演出

戦闘Scene起動時は20フレームの戦闘開始フェーズとし、この間は入力を受け付けない。
モンスターはDA2の初期スライド量 `8, 8, 7, 7, 6` と1段階24pxの移動を基準にする。
ZEROは60fpsのため移動を補間し、各モンスターを画面左側からそれぞれ16、16、14、14、
12フレームで定位置へ到達させる。

味方は画面右端の見えない位置（X=256）かつ各自の定位置から上へ24pxの位置を始点とし、
10フレームかけて長い放物線を描きながら定位置へ着地する。パーティ順に開始と着地を
2フレームずつずらす。これらの移動と並行して、共通の画面フェードを使った
6フレームのフェードインを行う。
味方の名前とHPは、最後のメンバーが着地してからまとめて表示する。

タイムラインの先頭6アイコンは画面右端の見えない位置（X=256）を始点とし、各アイコンを
10フレームかけて定位置へ左移動させる。行動順に開始と到着を2フレームずつずらし、最後の
6番目は20フレーム目に到着する。移動中はタイムラインの現在位置マーカーを表示しない。
全演出の完了後はボタン入力待ちを挟まず、初期ゲージ値が最大の参加者を最初の行動者とする。
味方ならそのキャラクターのコマンドWindowを開き、敵なら敵手番へ遷移する。

単独テストでは、開発中に開始演出を繰り返し確認できるよう、メニュー入力（Sキー、またはメニューに
割り当てたゲームパッドボタン）で、どのフェーズからでも戦闘開始フェーズを再実行する。リセット時は
味方のHP・MP、モンスター、インベントリ、選択状態、演出タイマーをfixtureの初期状態へ戻す。
本編の `BattleScene` ではこのリセット入力を無効にし、渡されたパーティ状態と所持品を回復・再生成しない。

### コマンド構成と「こうたい」

戦闘コマンドの表示有無と選択可否は、Pyxelや単独戦闘テストに依存しない
`app/battle_commands.py` で判定する。戦闘Sceneは行動者、パーティ、敵隊列に加え、沈黙、
アイテム、逃走などの戦闘状況に応じた可否を渡し、画面側は返されたコマンド順と
`enabled` を表示へ反映する。将来スキルや状態異常で選択肢が変化する場合も、モック固有の
条件分岐は追加しない。

左列は、「こうげき」、続いて「じゅもん」とスキル候補を表示条件順に評価し、3件を表示した
時点で以降を評価しない。「こうげき」は常に表示し、攻撃対象がない場合（後衛かつ短距離武器
を含む）はdisabledにする。「じゅもん」は、
ミスティック、セイクリッド、ネザーのいずれかの基礎適性が1以上なら表示し、沈黙中は
disabledにする。続いて「ねらう」「かくれる」「しきべつ」「いのり」「かばう」「いあい」
「ためる」「ブレス」「MPシェア」を、この順で対応スキルの保有時だけ表示する。

右列は「ぼうぎょ」「アイテム」「こうたい」の固定順とする。隊列変更コマンドの表示名は、行動者が
前衛なら `battle.command.retreat`（こうたい）、後衛なら `battle.command.advance`（ぜんしん）とする。
パーティが1名なら表示せず、前衛を残せないときはdisabledにする。攻撃対象がない状態で
キャラごとコマンドを開くときは、カーソル初期位置を「ぼうぎょ」とする。

「こうたい」を決定すると、行動中の味方を前衛から後衛、または後衛から前衛へ移す。
前衛から後衛へ移した結果、パーティ全員が後衛になる場合は「こうたい」をdisabled色で表示し、
カーソルの選択対象から外す。後衛から前衛への移動は常に選択できる。パーティが1名だけの場合は
「こうたい」自体をコマンドWindowへ表示しない。

生存かつ戦場に残っている前衛が0人になった場合は、残っている後衛全員を戦闘中だけ前衛として
扱う。この繰り上げは、全前衛の死亡時と、逃走による前衛の離脱時のどちらにも適用する。
繰り上げるメンバーは、通常の「ぜんしん」と同じく1フレーム2px、合計8フレームで後列から
前列へ同時に歩かせ、全員の移動完了後にタイムライン移動または次の手番を再開する。
表示位置、攻撃範囲、敵の攻撃対象、および戦闘中の隊列変更可否は繰り上げ後の隊列を参照する。
自動的に繰り上げた隊列は `Member.formation_row` を変更せず、勝利・逃走・全滅のいずれでも
戦闘終了後の隊列へ引き継がない。

各味方は、その戦闘中に最後に決定したコマンド、呪文、アイテムを別々に保持する。次の手番では、
現在も選択可能な保持値へカーソルを復帰する。所持品の消費やMP不足などで選択できなくなった場合は、
通常の初期位置へ戻す。「こうたい」「ぜんしん」は保持せず、これらを決定した味方の次の手番は
常に通常の初期位置から開始する。戦闘モックの再開始時には全員の保持値を消去する。

戦闘中の決定入力はDA2と同じく長押しリピートを有効にする。押し始めの1回に加え、DA2の
30fpsにおける10フレーム後から2フレーム間隔をZEROの60fpsへ換算し、20フレーム後から
4フレーム間隔で再入力する。リピートされた決定は、そのフレームで入力を受け付けている
コマンド、対象、呪文・アイテム候補、全体コマンド、確認画面へ渡す。これにより、決定ボタンを
押し続けると、各味方が保持しているカーソル位置のコマンドと後続の対象を継続して決定できる。
ボタンを離した時点で待機時間をリセットする。キャンセルとメニュー入力はリピートしない。

「ぼうぎょ」を決定した味方は、次に自身の手番が始まるまで防御状態を維持する。防御状態中の
物理攻撃はDA2と同じく、通常の命中値が25未満なら回避し、25以上なら通常計算後のダメージを
端数切り捨てで半減する。
スプライトは、通常立ち絵ではなくキャラクター戦闘画像の左端から `16 * 7` px の位置を始点に
した16×32pxを描画する。

「ねらう」は「こうげき」と同じ装備、射程、隊列の条件で対象を選ぶ。攻撃できない場合は
コマンドをdisabledにする。命中計算では回避率を適用して0～99の乱数を減算した後の命中値へ
100を加える。この補正後の命中値を命中判定とダメージ倍率の両方に使う。行動後は通常の
規定値である現在の素早さから16を減算した値へゲージを再設定する。

「ためる」は「こうげき」と同じ装備、射程、隊列の条件で対象を選ぶ。決定したターンは攻撃せず、
選択した対象と「ためる」状態をそのキャラクターの戦闘中一時状態として記録する。右上の行動
ポップアップへ `battle.command.focus` を表示し、DA2のSound 37を再生して、防御ポーズを
36フレーム維持した後に行動を完了する。このポーズは防御コマンドのダメージ軽減効果を持たない。

「ためる」状態のキャラクターに対する物理攻撃は、DA2で「まっぷたつ」を選択中の対象と同じく、
対象の回避率を使わず、補正後の基本命中率を最低100として0～99の命中乱数を減算する。このため
必ず命中する。死亡、睡眠、麻痺、混乱、スタンのいずれかになった時点で「ためる」状態を解除する。
睡眠、麻痺、混乱、スタンによる戦闘行動制限そのものは、それぞれの実装時に扱う。

次にそのキャラクターの手番が来たときはコマンド入力を開かず、記録した対象へ通常攻撃を自動実行する。
攻撃力は通常攻撃の2倍とし、命中率や防御計算など、それ以外は通常攻撃と同じにする。記録した対象が
すでに死亡しているなど攻撃不能になっていた場合は、その時点で攻撃可能な対象のうち先頭を選ぶ。
自動攻撃を開始した時点で「ためる」状態を消費する。

### コマンドガイド

コマンド選択中、同じコマンドにカーソルを30フレーム（DA2の30fps・15フレーム相当）留めると、
選択中コマンドのガイドWindowを表示する。Windowは `(0, 0, 34, 13)` とし、
コマンドWindow `(34, 0, 30, 13)` の左に接して画面左上を占める。カーソル移動、コマンドの
決定・キャンセル、またはコマンドWindowが開閉中の間は、ガイドを即時に閉じて待機時間を
リセットする。

ガイド本文は `battle.guide.*` の文言キーから3行までを表示する。「こうたい」と「ぜんしん」は
行動者の現在の隊列に応じて、それぞれ `battle.guide.retreat` と `battle.guide.advance` を使う。
文言が未入力で `pending: true` のキーは、入力されるまでガイド本文を表示しない。

隊列移動はDA2の戦闘中歩行を基準にする。DA2の30fps・1フレーム4pxに相当する速度として、
ZEROでは1フレーム2px、合計8フレームで前後列間の16pxを移動する。移動中のスプライトは、
通常立ち絵と同じ切り出し位置、およびその16px右から始まる切り出し位置を2フレームごとに
交互表示する。コマンドWindowは決定時に即時に閉じ、移動完了後はそのキャラクターの行動を
完了して通常のタイムライン移動へ進む。

### アイテム使用

「アイテム」を決定すると、行動者は呪文使用時と同じ速度で敵側へ16px進み始め、コマンドWindowとは
独立した使用候補Window `(32, 0, 32, 13)` を表示する。移動中は歩行絵を使用し、移動完了後は
通常立ちポーズへ戻す。呪文詠唱ポーズは使用しない。コマンドWindowの右端は維持したまま、左へ8px
広げる。一度に表示する候補は最大3件とし、上下入力で全候補を循環し、選択行が表示端を
越えた場合は一覧を追従スクロールする。候補が4件以上ある間は、一覧Window右枠の上端と下端へ
共通の縦スクロールインジケータを表示する。説明Windowはコマンドガイドから分離したアイテム専用の
`(0, 0, 32, 13)` に表示し、使用候補Windowと接して配置する。選択中アイテムの
`ItemDetailContext.BATTLE` の使用効果を最大3行表示し、アイテム選択を開いた直後から常時表示する。

候補はDA2と同じく、行動者が装備している武器・腕装備を使用効果の有無にかかわらず先に並べ、続いて所持中の
`type1=ITEM` かつ `type2=ITEM` の、使用効果が `spells.json` で `on_battle=1` の消耗品を
マスターデータ順に並べる。戦闘中に使えない成長アイテムやネクターは表示しない。装備品は名前の
先頭へ `＃` を付け、消耗品は右端に所持数を表示する。本モックのインベントリはテスト用に
`items.json` の全アイテムを1個ずつ所持した状態で開始する。

ZEROでは味方ごとにコマンドを選択・完了するため、DA2のような未発動の選択済みアイテムを
予約して候補から除く処理は行わない。使用効果のある候補を決定すると、対応する使用効果呪文の
`to_enemy` と `to_all` に従うターゲット選択へ進む。`break=1` の消耗品は所持品から1個減らし、
同フラグの装備品は装備枠から外すが、いずれもターゲット決定後に限るため、キャンセルした場合は
消費しない。使用効果のない武器・腕装備を決定しても行動は完了せず、候補選択を継続する。
キャンセル時はコマンド一覧へ戻り、カーソルは「アイテム」へ復帰して、行動者を同じ速度で元の位置へ
戻す。ターゲット選択だけをキャンセルした場合は前進位置を維持する。

### 呪文使用

「じゅもん」を決定すると、行動者はDA2と同じく敵側へ16px進み始め、呪文Window
`(36, 0, 28, 16)` を表示する。移動速度はDA2の30fpsにおける4px/フレームをZEROの60fpsへ
換算した2px/フレームとし、移動中は歩行絵、移動完了後はキャラクター戦闘画像の左から8番目にある
防御と共通の16×32pxパターンを詠唱ポーズとして表示する。
高さは4行とし、1回に表示するのはミスティック、セイクリッド、ネザーのいずれか1系統とする。
左右入力で系統を切り替え、上下入力で各系統のレベル1から9、続いてレベル0の候補をスクロールする。
候補は行動者が習得済みで `on_battle=1` の呪文だけとし、MP不足の呪文は灰色で表示して選択対象から除く。

選択中呪文の説明と消費MPは画面左上のガイドWindow `(0, 0, 36, 16)` に、現在MPはその右下へ
重ねる小Window `(20, 9, 16, 7)` に表示する。ガイドは説明2行の後に1行空け、4行目へ消費MPを
表示する。
現在MPは最大MPを省略した `ＭＰ　２０７` 形式とし、数値は3桁幅の空白埋めで表示して0埋めしない。
例えば現在MPが12なら `ＭＰ　　１２` とする。日本語の8×12フォントで表示する英数字は現在MPと
消費MPを含めて全角化する。呪文を決定すると、`to_enemy` と `to_all` に従う
ターゲット選択へ進む。消費MPはターゲット決定時に引き、登録済みの通常エフェクトを再生してから
その味方の手番を完了する。ターゲット選択をキャンセルした場合はMPを消費せず呪文一覧へ戻り、
呪文一覧からのキャンセル時はコマンド一覧へ戻ってカーソルを「じゅもん」へ復帰し、行動者を
同じ速度で元の位置へ戻す。ターゲット選択だけをキャンセルした場合は詠唱位置を維持する。

### アイテム・呪文のターゲット選択

使用効果および呪文の `to_enemy=1` は敵、`to_enemy=0` は生存している味方を対象とする。
`to_all=0` は1体／1人を選択し、敵では通常攻撃と同じ5体配置用の上下左右の候補順、味方では
上下左右のいずれでも生存者を循環して切り替える。敵単体の初期位置は最後の生存敵、味方単体の
初期位置は先頭の生存味方とする。前進中の行動者自身を味方対象にした場合は、カーソルも
前進後のスプライト位置に合わせて左へ16px移動し、スプライトへ重ならない位置に表示する。

`to_all=1` は対象側の生存者全員へカーソルを表示する。DA2と同じく、すべてのカーソルを毎フレーム
交互に表示・非表示にする超高速点滅とする。全体対象時も決定またはキャンセルを受け付け、決定時だけ
アイテム消費またはMP消費と効果演出を開始する。キャンセル時は、アイテムならアイテム一覧、呪文なら
呪文一覧へ戻る。

### モンスター情報の記録とターゲット相性表示

モンスター情報は `SaveData.monster_records` に表示名ではなく `name_en` の安定キーで記録する。
戦闘開始時に、編成内の各モンスターを空の開示項目集合で図鑑へ登録する。同種が複数いる場合も
レコードは1件とする。通常攻撃または敵対象の呪文・アイテムを確定した場合は、実際の対象ごとに
`profile` を開示する。属性を持つ呪文・アイテムでは、その属性の `ResistanceType` 安定キーも
同時に開示する。全体対象では生存対象すべてを記録する。ターゲット選択をキャンセルした場合は
何も開示しない。「しきべつ」が成立した場合は `profile` と全 `ResistanceType` を開示する。

敵対象の呪文または呪文効果を持つアイテムのターゲット選択中は、その効果属性が対象の開示項目に
記録済みの場合だけ、実データの `weakness` / `tolerance` と照合する。弱点なら `WEAK`、耐性なら
`RESIST` を対象画像の中央上部へ表示し、両方に該当する場合は実際の効果計算と同じく `RESIST` を
優先する。単体・全体指定および現在のカーソル位置を問わず、ターゲット選択フェーズ中は選択可能な
全モンスターについて表示する。DA2の30fpsで15フレーム周期・12フレーム表示に相当するよう、
ZEROでは30フレーム周期・24フレーム表示とする。未記録の属性、および弱点・耐性のどちらでもない
属性は何も表示しない。

モンスターからのお宝が実際に所持品へ追加された時だけ、そのモンスターの開示項目へ
`treasure_acquired` を追加する。このフラグはアイテム図鑑の取得済み状態とは分けてモンスター単位で
保持する。ドロップ判定失敗時、および所有上限などでお宝を取得できなかった場合は追加しない。
ドロップ機能の実装までは、戦闘記録Systemがこの記録操作だけを提供する。

### 呪文エフェクト演出

ターゲット決定後、`app/effects/spells.json`に対象呪文の通常エフェクトが登録されていれば、
入力を受け付けない行動演出フェーズへ進む。単体対象には選択した1体、全体対象には生存している
対象側の全員について`SpellEffectPlayer`を同時に開始し、味方には`offset.ally`、敵には
`offset.enemy`を適用する。各対象スプライトだけを設定色でフラッシュし、その上へ現在の画像
パターンを描画する。SEは全体対象でも演出開始時に1回だけ再生する。アイテム使用時も、
`use_spell_key`が参照する呪文に通常エフェクトがあれば同じ経路を使う。
通常の呪文発動時は、呪文系統アイコンと呪文名だけを画面右上の細枠の小さいWindowに表示する。
Windowの横幅は、8pxのアイコンと選択言語フォントによる呪文名の実描画幅を求め、左右の枠内余白を
加えた最小の4pxグリッド幅とする。このWindowは入力待ちにせず、DA2のポップオーバー
既定時間30フレームを60fpsへ換算した60フレームで自動的に消す。ポップアップのタイマーと描画は
行動演出フェーズから独立させ、表示中でもエフェクト完了後6フレームを空けたあとの後退と
次フェーズへの進行を止めない。
アイテム経由の呪文では、アイコンを付けずにアイテム名だけを同じ可変幅ポップアップへ表示する。
エフェクト完了後は6フレームの
間を空け、ポップアップの残り表示時間を待たずに行動者を元の位置へ戻して次フェーズへ進む。
呪文フラッシュ用の一時パレットは演出完了時に解放し、後続のモンスター死亡演出へ同じ有限領域を
再利用する。死亡演出側も完了時に解放する。

使用効果が `HEAL` の呪文とアイテムは、DA2と同じ次の回復処理を行う。通常呪文の術者能力値は
`調整後魔力 x (51 + 内部LV) / 50` の小数点以下を切り捨てた値とし、アイテム経由では術者に
かかわらず20とする。回復量は `intensity x 術者能力値 / 10 x 0.8～1.2 + 1` の小数点以下を
切り捨てる。対象のHPは最大HPを上限として回復するが、回復数字には最大HPで丸める前の回復量を
表示する。`intensity=0` はDA2のヒーリング3と同様に不足HPをすべて回復し、毒、麻痺、眠り、混乱を
同時に解除する。この全回復効果の対象がすでに最大HPなら回復数字は表示しない。

回復反映と数字表示は通常エフェクト終了のDA2換算2フレーム前（ZEROでは4フレーム前）に開始する。
回復数字はダメージ数字 `(128, 0)` の8px下にある `(128, 8)` から横に並ぶ8×8pxの0～9を使い、
対象キャラクターの中央付近からダメージ数字と同じ上下移動パターンで合計35フレーム表示する。
回復数字のタイマーと描画は行動演出フェーズから独立させ、表示終了を待たずにエフェクト完了後の
6フレームを空けて後退とタイムライン移動を進める。

使用効果が `DAMAGE` の呪文は、術補正値を
`調整後魔力 x (7 + 対応する呪文系統の現在LV + 内部LV / 25) / 16` として計算する。
この術補正値は状態異常呪文でも共通して使用する。対象1体ごとのダメージは
`intensity x 術補正値 x (100 - 対象の術防御) / 100 x 0.20～0.25` とし、最後に小数点以下を
切り捨てる。属性が対象の弱点に含まれる場合はDA2と同じく4倍、耐性に含まれる場合は1/4とする。
同じ属性が弱点と耐性の両方に登録されている場合は耐性を優先する。属性なしは等倍とする。
DA2と同じく、死属性を `shadow=1` の対象へ使用した場合は、明示的な耐性・弱点がないときに
2倍としてWEAKを表示する。

ダメージ反映と数字表示は回復と同じく通常エフェクト終了のZERO換算4フレーム前に開始し、
数字にはバンク0の `(128, 0)` から横に並ぶ8×8pxの0～9を使用する。弱点時はバンク0の
`(232, 16)`、耐性時は `(232, 24)` にある24×8pxのアイコンを、対象モンスターの中央から
12px左、上端から20px下へ表示する。相性アイコンは通常エフェクトと同時に開始し、DA2換算
16フレーム（ZEROでは32フレーム）で消える。ダメージ数字と相性アイコンはいずれも独立した
時間制ポップアップであり、表示終了を待たずにエフェクト完了後の6フレームを空けて後退と
次フェーズへ進む。複数対象が同時に倒れた場合は、この6フレーム後に各モンスターの死亡演出を
順に再生してからタイムラインを進める。

使用効果が `SLEEP` の呪文は、DA2の状態異常成功判定へ上記の術補正値とマスターデータの
`rate`を使う。対象1体ごとの判定値は
`max(1, (術補正値 - 対象の術防御) / 2 + rate)` とし、0～19の整数乱数より判定値が大きければ
成功とする。睡眠属性が対象の弱点に含まれる場合は判定値へ10を加え、睡眠耐性に含まれる場合は
術補正値と`rate`にかかわらず失敗する。弱点と耐性の両方に含まれる場合は耐性を優先する。
弱点・耐性アイコンはダメージ呪文と同じ位置と表示時間を使い、失敗時はDA2と同じく`miss`を
表示する。

成功した対象には2～3の睡眠残り行動数を設定し、すでにより長い睡眠中なら短縮しない。睡眠中は
本人のタイムライン手番が来るたびに残り行動数を1減らして行動を飛ばし、通常攻撃に対して回避不能と
する。正のダメージを受けると即座に睡眠を解除する。味方へ睡眠を適用するときはDA2と同じく混乱を
解除し、睡眠中の味方は瀕死と同じ戦闘ポーズを使う。

睡眠中はバンク0の`(32, 136)`から横へ並ぶ4枚の8×8pxアイコンを、DA2換算4フレーム
（ZEROでは8フレーム）ごとに切り替える。味方は戦闘画像の左上から`(12, 0)`、モンスターは
画像左上から`(48, 0)`の位置へ表示する。

使用効果が `PROTECTION` の呪文とアイテムは、生存している味方1人へ確定で防御上昇を1段階
付与する。防御上昇は2段階まで重ねがけでき、すでに2段階の味方は対象候補から除外する。
基礎防御を装備防具の防御合計、段階を1または2とした現在防御は、DA2と同じく
`int((基礎防御 + 段階 x 5) x (1 + 段階 / 4))` とする。したがって1段階は
`int((基礎防御 + 5) x 1.25)`、2段階は `int((基礎防御 + 10) x 1.5)` となる。
防御上昇は戦闘中だけ保持し、対象の死亡時および戦闘終了時に解除する。

防御上昇中はバンク0の `(64, 128)` から横へ並ぶ3枚の8×8pxアイコンを、対象のキャラクター名
左の8px領域へ常時表示する。DA2と同じく1段階では6フレーム、2段階では3フレームごとに
パターンを切り替え、ZEROの60fpsではそれぞれ12フレーム、6フレームへ換算する。
名前表示を隠す戦闘開始・逃走演出中はアイコンも隠す。

使用効果が `SLOW` の呪文とアイテムは、`SLEEP` と同じ状態異常成功判定へ共通の術補正値と
マスターデータの `rate` を使う。成功すると対象の速度補正を `-1` にする。すでに速度補正が
`-1` の対象は候補から除外する。正の速度補正がある対象には、その段階数にかかわらず一度で
補正を0へ戻し、さらにスロウが成功したときに `-1` とする。失敗時は `miss` を表示する。
速度補正はターン数で解除せず、対象の死亡時または戦闘終了時に0へ戻す。

基礎素早さと速度補正から、戦闘中の実効素早さを
`max(1, int(基礎素早さ x (4 + 速度補正) / 4))` で求める。速度補正 `-1` のスロウ中は
基礎素早さの0.75倍、`+1` は1.25倍、`+2` は1.5倍となる。味方の基礎素早さには装備補正後の
素早さ、敵にはマスターデータの `agi` を使う。実効素早さはタイムラインへ再挿入するときの
ゲージ値、物理攻撃時の素早さ命中補正、および味方の素早さ由来回避率へ使う。ZEROの敵回避率は
従来どおりマスターデータの `evasion` を直接使う。

スロウが成功しても、対象が現在保持しているゲージ値と確定済みの順番は変更しない。対象が次に
行動を完了したとき、0.75倍の実効素早さを新しいゲージ値として再挿入する。これにより、DA2で
現在ラウンドの順序を変えず次の行動順計算から反映していた挙動をZEROの連続タイムラインへ対応させる。

スロウ中はバンク0の `(96, 136)` から横へ並ぶ4枚の8×8pxアイコンを、DA2換算8フレーム
（ZEROでは16フレーム）ごとに切り替える。表示位置はモンスター画像の左から
`幅 - 24px`、画像下端とする。

現在の戦闘実装では `HEAL`、`DAMAGE`、`SLEEP`、`PROTECTION`、`SLOW` 以外の呪文による状態変化は適用しない。すべてのエフェクト再生が
完了してから6フレームを空けると、詠唱メッセージや回復数字の残り表示時間を待たずに行動者を
同じ速度で元の位置へ戻し、タイムライン移動へ進む。未登録の呪文と専用処理が必要な特殊呪文も、
エフェクト終了済みとして6フレームを空け、適用できる使用効果を反映したうえで手番を完了する。

行動演出フェーズはターゲット確定や手番進行から分け、共通の経過フレーム上へ画像エフェクトを
レイヤーとして保持する。回復数字、ダメージ数字、相性アイコン、および状態変化など今後追加する
時間制ポップアップも、
詠唱メッセージと同じくScene共通の独立レイヤーで更新・描画し、行動やフェーズの完了条件には含めない。

### 通常攻撃のターゲット選択

モックの敵は画面最上部のヒュージスパイダー1体とコヨーテ2体を前衛、残る
ヒュージスパイダー2体を後衛とする。「こうげき」の
選択可能範囲は、行動者の現在の隊列と装備中の武器の `reach` から次のように決定する。
二刀流で複数の武器を装備している場合は、DA2と同様に最も短い `reach` を使う。
右手に武器を装備していない場合は素手で通常攻撃できないため、「こうげき」を選択不可の色で
表示し、カーソル移動の候補から除外する。オート戦闘では通常攻撃の代わりに防御を選ぶ。

| 行動者 | `reach=1` | `reach=2` | `reach=3` |
| --- | --- | --- | --- |
| 前衛 | 敵前衛のみ | 敵全員 | 敵全員 |
| 後衛 | 選択不可 | 敵前衛のみ | 敵全員 |

「こうげき」を決定すると、選択可能な敵のうち末尾の敵を初期ターゲットとする。指アイコンは
コマンド選択と同じ `WindowCursor` を使い、モンスター名を含む全Windowより後に描画する。
上下左右入力では5体配置用の候補順に移動し、攻撃範囲外の敵を飛ばす。

配置を上から右列3、左列1、右列4、左列2、右列5とした場合、4からは上で3、下で5、
右で2、左で1へ移動する。2からは上下とも1、右で5、左で4へ移動する。フィオラの
`reach=1` では1と2を選択できないため、4で右を入力した場合は2を飛ばして5へ移動する。
全ての敵を選択できる場合、2で右を入力すると5へ、続けて5で左を入力すると2へ戻る。
横方向は、右入力で1、4、2、5、3の順、左入力でその逆順に循環する。選択できない敵は
同じ方向の循環順に沿って飛ばす。このため前衛だけを選択できる場合、5で左を入力すると
2を飛ばして4へ移動する。
「こうげき」を決定した時点で、呪文・アイテムと同じ2px/フレームで敵側へ16px前進する。
移動中は歩行絵を使用し、ターゲット選択は前進と並行して受け付ける。キャンセルすると
コマンド選択へ戻り、同じ速度で元の位置へ戻す。

ターゲットを決定するとコマンドWindowとカーソルを即時に閉じ、右手武器の `weapon_img` に対応する
`app/effects/attack_poses.json` の枝番 `1`、`2` を順に表示する。DA2の通常武器攻撃を基準に、
枝番1の振り上げを3フレーム、枝番2の振り下ろしを8フレーム表示する。各ポーズでは
登録された1〜2個の武器画像について座標、前後関係、左右・上下反転を適用する。二刀流による
左手側の連続攻撃は現段階では扱わない。対応ポーズがない場合も攻撃処理は継続し、通常立ち絵を使う。

ターゲット決定時に、ステータス画面で使う右手の武器攻撃力（りょうてもち適用後）をもとに、
`武器攻撃力 x 力 x (7 + 武器LV + 内部LV / 25) / 50` の小数点以下を切り捨てて
プレイヤー側の総合攻撃力を求める。表示用の武器攻撃力そのものをダメージ計算へ渡さない。
命中判定とダメージは後述のDA2準拠計算で決定する。命中時は振り下ろし開始フレームに対象の
現在HPからダメージを減算し、武器別打撃エフェクトと打撃SEを開始する。ダメージ数字はその
10フレーム後から表示する。
ミス時は対象のHPを変更せず、打撃エフェクトとSEを出さずに `miss` を表示する。HPは0未満にせず、
0になった対象だけ撃破演出へ進める。生存した対象は画面、攻撃対象、行動順に残す。
攻撃姿勢の11フレームが終了したら、打撃エフェクトとダメージ数字を継続したまま8フレームの
放物線を描いて元の位置へ後退する。着地直後はキャラクターシートの左から8番目にある
ガードポーズを6フレーム表示してから通常立ち絵へ戻す。振り下ろし終了とジャンプ開始の間には
静止フレームを挟まず、振り下ろしを終えたフレームから位置を移動する。
結果表示または撃破演出の完了後にタイムライン移動を開始する。移動後の手番が味方なら、
ボタン入力を待たずにコマンドWindowを開き直す。死亡済みの敵はターゲット候補から除外する。
選択可能な敵がいない場合はターゲット選択へ遷移せず、コマンド選択を継続する。
ターゲット選択中、攻撃範囲外となる後衛の敵画像は、元画像の色とUI用グレーを1対1で
合成した専用パレットへ変更して表示する。

「ねらう」で対象を決定した場合は、防御ポーズへ切り替えて右上の時間制ポップアップへ
`battle.command.aim` を表示する。防御ポーズのまま12フレーム待機した後、イメージバンク0の
`(0, 128)`、`(8, 128)`、`(0, 136)`、`(8, 136)` にある8×8pxの照準外枠を、対象画像の
中心からX・Yそれぞれ32px離れた位置から8px離れた位置まで、1フレーム6pxで近づける。
各外枠の中心をこの距離へ置き、中心に対して左上、右上、左下、右下へ対称に配置する。
8pxへ到達したフレームからは通常攻撃の第一段階ポーズへ切り替え、`(16, 128)` の
16×16px照準中心も対象画像の中央へ重ねる。外枠とともに第一段階ポーズで6フレーム静止し、
その後は通常攻撃の第二段階ポーズへ移り、同じ打撃演出、
ダメージ表示、帰還演出を行う。演出用の距離、速度、静止時間、スプライト座標は個別の定数として
保持する。

敵前衛の現在HPが全員0になった時点で、生存している後衛の敵を全員前衛へ昇格させる。
昇格そのものには移動などの演出を付けず、以後の攻撃範囲判定へ即時に反映する。

### 武器別打撃エフェクトとダメージ表示

`content/images/effects/weapons.png` の左上192×320pxを64×64pxの3列×5行として使用する。
各行は3パターンで、1パターン5フレーム、合計15フレーム表示する。
行と武器種別の対応は次のとおりとする。

| 行 | 武器種別 |
| --- | --- |
| 0 | 斧 |
| 1 | 剣・刀 |
| 2 | 短刀 |
| 3 | ハンマー・ワンド・ロッド |
| 4 | 槍 |

ダメージ数字は敵攻撃の結果表示と同じイメージバンク0の8×8px数字を使い、対象モンスターの
中央下部からDA2の上下移動パターンで32フレーム動かし、最後の表示を3フレーム保持して
合計35フレーム表示する。数字は振り下ろしと打撃エフェクトの開始から10フレーム遅れて開始し、
打撃SEは振り下ろし開始時に1回だけ再生する。SEもDA2に合わせ、剣・刀・短刀はSound 11、
ハンマー・ワンド・ロッドはSound 29を使う。DA2に存在しない斧と槍は剣と同じSound 11を使う。
ミス表示は敵攻撃と同じ13パターンを各2フレーム、合計26フレーム表示する。

### 通常攻撃の命中・ダメージ計算

味方と敵の通常攻撃は、次のDA2と同じ基本計算を共用する。

1. 基本命中率は、攻撃者の素早さが20を超える場合に `1 + (素早さ - 20) / 20` 倍し、
   10未満の場合に `1 + (素早さ - 10) / 20` 倍する。
2. `命中値 = 補正後の基本命中率 x (100 - 対象の回避率) / 100 - 0～99の乱数` とする。
3. 命中値が0未満ならミス、0以上なら命中とする。
4. 命中時は `ダメージ倍率 = 0.8 + 命中値 / 250` とする。
5. `max(攻撃力 - 対象の防御, 1) x ダメージ倍率 x (1 - 対象の防御 / 100)` に
   0.99を加えて整数化した値をダメージとする。

味方は装備・熟練度から求めた右手の命中率と調整後の素早さ、敵は `monsters.json` の
`hit` と `agi` を攻撃側の入力に使う。防御側は味方なら現在装備から求めた防御・回避率、
敵なら `monsters.json` の `defense`・`evasion` を使う。モンスターの回避率に `agi` の
補正は加えない。二刀流の左手攻撃、特効、追加効果、睡眠以外の状態異常による補正は、
現段階の戦闘モックでは扱わない。

睡眠中の対象へ通常攻撃するときは、DA2と同じく補正後の基本命中率へ100を加えて回避率を無視し、
会心可能条件を1つ満たす。攻撃者がスキル「かいしん」を持つ場合も会心可能条件を1つ満たす。
装備武器の`special`が`POWER_HIT`の場合も、DA2の会心率上昇武器と
同じく会心可能条件を1つ加える。命中後の会心率は
`会心可能条件数 x 0.1 x max(睡眠補正後の基本命中率, 100)`％とし、両手持ちの攻撃はさらに1.5倍する。
0～99の整数乱数より会心率が大きければ会心とする。会心時は総合攻撃力を2倍にし、対象の防御を
攻撃力から差し引かず、通常と同じダメージ倍率と`(1 - 対象の防御 / 100)`を適用する。防御コマンド中の
対象には、その後で通常どおりダメージを半減する。

会心時は、端末設定の画面フラッシュが「つうじょう」ならバンク色33で戦闘背景を
2フレーム塗りつぶし、味方・敵・エフェクト・Windowは通常どおりその上へ描画する。「おさえる」なら
全面フラッシュを行わず、バンク0の`(204, 24)`にある28×8pxの`SMASH`を対象へ26フレーム表示する。
敵を対象とする場合は対象画像の上端から20px下、味方を対象とする場合は戦闘スプライト左上を表示位置とする。

### モンスター撃破演出

通常攻撃のダメージで対象の現在HPが0になると、結果表示後に対象だけを
赤紫へ変色させる。6フレーム赤紫を保持した後、12フレームかけて白に近い薄紫へ明るくする。
続いて16フレームかけてディザの描画率を1から0へ下げ、ドットに少しずつ穴が開くように消滅させる。
全体は34フレームとし、元のモンスター画像の画素データは変更しない。
撃破演出の開始時には、DA2と同じSound 10をチャンネル0で1回だけ再生する。

演出中も現在HPは0であり、演出が完了した個体は画面、モンスター名、攻撃対象、行動順から除外する。
その後、攻撃した味方の行動を完了して通常のタイムライン移動へ進む。デバッグ用の戦闘再開時は、
全モンスターの現在HPを各個体の最大HPへ戻し、初期隊列、初期行動順、表示を復元する。

### ゲージ値と行動順

戦闘に参加する生存中の敵味方をすべて行動順に含める。味方の素早さは装備補正後の
`Member.adjusted_abilities.agility`、敵の素早さは `monsters.json` の `agi` を使う。
戦闘開始時は参加者ごとに `[1.0, 2.0]` の一様実数乱数を素早さへ掛け、その結果を初期ゲージ値とする。
ゲージ値の大きい順に安定ソートし、同値の場合はソート前の順序を維持する。モックのソート前の順序は
`BATTLE_TEST_PARTY` の設定順、続いて `BATTLE_TEST_MONSTER_KEYS` の設定順とする。

次の行動者を確定する直前に、先頭のゲージ値を `G` として `64 - G` を全参加者のゲージ値へ
一律加算する。したがって先頭のゲージ値は必ず64になり、他の参加者との値の差と順序は変化しない。
たとえば `(60, 45, 30)` は `(64, 49, 34)` となる。先頭の参加者が行動し、行動完了時にその参加者の
ゲージ値を現在の素早さと同値へ戻した後、ゲージ値の大きい順へ再挿入する。ただし「ねらう」の
行動後だけは規定値である現在の素早さから16を減算して設定する。同値の参加者がすでにいる
場合、行動済みの参加者はその同値グループの後ろへ入る。再挿入とタイムライン移動が終わったら再び
先頭を64へ補正し、戦闘終了まで同じ処理を繰り返す。HPが0になった敵は再挿入前に行動順から除外する。

画面上のタイムラインには行動順の先頭から最大6名／体までを表示する。味方の隊列は
`BATTLE_TEST_PARTY` の指定に従う。
タイムライン先頭の味方だけ、名前とHPを白文字で表示し、それ以外の味方は灰色で表示する。
コマンド、アイテム、呪文、攻撃対象、逃走確認を入力中の味方スプライトは、通常色からわずかに
白寄りの色、通常色へとパレットを周期的に変化させる。入力完了時から通常色で表示する。左側の
矢印カーソルは表示しない。
通常攻撃、ねらう、ためる、アイテム、じゅもん以外のコマンドは、ぼうぎょを除き効果を実行せず、
選択した時点でその味方の行動を完了して次へ進める。「ぼうぎょ」は次の自身の手番まで防御状態と
防御用スプライトを維持する。
攻撃可能な敵がいない味方でも、コマンドWindowの「こうげき」はdisabledで残す。右列の
コマンドと位置は変更しない。

### コマンドのキャンセルと逃走

キャラごとコマンド選択中は、画面右下へ透明Windowで「X：ぜんたい」（キーボード時）を
表示する。キャンセル入力（Bボタン）を行うと、モックを終了せず全体コマンドへ切り替える。
全体コマンドは「たたかう」「にげる」「オート」で構成する。「たたかう」の決定、または
全体コマンド中のキャンセルで、現在の味方のキャラごとコマンドへ戻る。全体コマンドWindowは
キャラごとコマンドWindowの半分の幅となる `(49, 0, 15, 13)` に表示し、完全に開いている間は
全ての生存モンスター名を白文字で表示する。

「にげる」は従来と同じ逃走確認・逃走処理を開始する。「オート」はオートバトルを開始し、
攻撃対象がある味方は通常攻撃を自動選択して通常どおりの初期ターゲットを攻撃し、攻撃対象が
ない味方は防御を自動選択する。オートバトル中は画面右下へ透明Windowで常に
「X：キャンセル」（キーボード時）を表示し、キャンセル入力でオートバトルを解除する。
ターゲット選択中のキャンセルは、従来どおりコマンド選択へ戻る。
コマンドWindowを開く際は通常の開閉アニメーションのうち開く演出だけを使用し、閉じる際は
遷移先にかかわらず1フレームで非表示にする。

「にげる」を選ぶと、ターン数にかかわらず「ほんとうに にげて いいですか？」の確認と
「はい」「いいえ」の選択を表示する。文言はそれぞれ `battle.escape.confirm`、
`settings.yes`、`settings.no` を参照する。「はい」を決定すると、行動中の味方を右向きへ反転し、
DA2の逃走を基準として6px/フレームでX=260まで走らせる。通常立ち絵とその16px右から始まる
歩行絵を2フレームごとに交互表示し、各味方の走行開始時にDA2のSound 26を再生する。
走行開始時点で、その味方の名前・HP表示を非表示にする。画面外へ到達した味方は戦場から離脱し、
タイムライン、敵の攻撃対象、味方への効果対象から除外する。以後に別の味方へ手番が回ると
コマンドWindowを開かず、その味方も同じ走行を行って順次離脱する。途中の敵手番は通常どおり
進行する。前衛の離脱によって後衛だけが残った場合は、前述の戦闘中だけの前衛繰り上げを適用する。

全ての生存メンバーが離脱した時点で画面上部へ `battle.escape.started` のメッセージを表示して
BGMを継続したまま入力を待つ。決定またはキャンセル入力でメッセージを閉じると同時にBGMを停止し、
共通の6フレームフェードで画面全体を暗転する。黒へ到達した後は明転させず、完全暗転した時点で
`BattleResult.ESCAPED` を確定する。単独テストだけはこの結果を受けて
Pyxelを終了する。本編では暗転状態のままフィールドへ切り替えてフェードインする。詳細は
[`encounters.md`](./encounters.md) に従う。メッセージ表示中以外の逃走演出では入力を受け付けない。
「いいえ」の決定またはキャンセルでは、行動順を進めずに
コマンドWindowを開き直す。確認WindowはコマンドWindowを即時に閉じた後に表示する。

モンスター名は常時表示せず、敵を対象とする通常攻撃・アイテム・呪文のターゲット選択中と、コマンドWindowが完全に閉じた
ボタン入力待ちの間だけ表示する。コマンドWindowの開閉アニメーション中、コマンド選択中、
逃走確認中、タイムライン移動中、敵手番には表示しない。ボタン入力待ちでは全ての生存
モンスター名を白文字で表示する。ターゲット選択中は選択可能なモンスター名を白文字、
攻撃範囲外となりグレー表示中の後衛モンスター名を灰色で表示する。

攻撃可能な対象がいる敵の手番ではコマンド入力を受け付けず、その敵を点滅させる。点滅時間はDA2の30fpsにおける
11フレームを、ZEROの60fpsに合わせた22フレームで再現する。点滅は12フレーム周期とし、
6フレーム表示、6フレーム非表示とする。
点滅終了後、行動中の敵が前衛なら、生存している味方前衛から1人をランダムに選んで通常攻撃する。
後衛の敵、および攻撃可能な味方前衛がいない場合は点滅を省略し、直ちにタイムライン移動へ進む。本編では
敵の射程に応じた後衛からの攻撃も扱う予定だが、モックでは扱わない。

攻撃結果は、敵の `attack`、`hit`、`agi` と対象の防御・回避率から、味方通常攻撃と共通の
DA2準拠計算で決定する。
ダメージ時はDA2の16フレーム、`miss` 時は13フレームの上下移動パターンを各2フレームずつ表示し、
ZEROではダメージを32フレーム動かした後に最後の表示を3フレーム保持して合計35フレーム、
`miss` を26フレームの演出とする。ダメージ数字はイメージバンク0の
`(128, 0)` から横に並ぶ8×8pxの0～9、`miss` は同バンクの `(208, 0)` にある16×8pxを使う。
表示位置は対象スプライトの中央付近を基準にする。1～15の結果では数字表示の開始と同時に
DA2のサウンド12をチャンネル0で再生する。`miss` ではDA2と同じくSEを再生しない。

1～15のダメージ中は、対象キャラクターを左右へ1pxずつ揺らしながら定位置から右へ8～9pxずらし、
キャラクター戦闘画像の左端から `16 * 5` pxの位置にある6番目の16×32pxパターンを描画する。
演出終了時に現在HPからダメージを減算して0未満を0へ丸め、HP表示を更新した後、タイムライン移動を
経て次の参加者へ手番を回す。HPが0になった味方は直ちにタイムラインから除外し、以後は手番を
回さない。戦闘開始時点ですでに死亡している味方もタイムラインへ追加しない。`miss` ではHPと
キャラクタースプライトを変更しない。

最後の生存メンバーが死亡した場合はタイムライン移動へ進まず、画面上部へDA2と同じ
`battle.defeat`（「ぜんめつした...」）を表示して決定またはキャンセル入力を待つ。本編の
`BattleScene` は入力後に `BattleResult.DEFEAT` を確定し、本編は最寄りのダンジョン出口直前へ
フェード遷移する。単独テストでは結果を外部へ返さず、同じfixtureから戦闘開始状態を再生成して開始演出から
リスタートする。

最後の生存モンスターは死亡演出の完了後にタイムラインから除外し、後述の勝利演出へ進む。
成長リザルトを閉じた後に `BattleResult.VICTORY` を確定する。本編のフェード復帰と戦闘回数更新は
[`encounters.md`](./encounters.md) に従う。単独テストでも同じ勝利演出とリザルトを表示し、
勝利結果を受けてPyxelを終了する。

### 勝利報酬と成長記録

敵個体の撃破経験値は次式で求め、全個体分を合計する。

`floor(12 × 敵LV × max(0, 敵LV - early_appear) ÷ max_occ × 行動数係数)`

行動数係数は1.0から始まり、その敵が実際に行動するたび0.1を加える。後列配置などにより
何もしなかった手番は数えない。浮動小数の丸め差を避けるため、実装では係数を
`(10 + 行動数) / 10` として最終除算時に一度だけ切り捨てる。Goldは全個体の `gold` の合計とする。
`monsters.json` の `exp` は参照用であり、実行時の報酬には使わない。
お宝候補は `treasure_item`、ドロップ確率は `treasure_rate / 16` とし、判定は戦闘終了後に行う。
判定回数、複数ドロップ、所有上限到達時の扱い、結果表示は敵ドロップ機能の実装時に定める。

共有経験値へ獲得値を加えた後、全メンバーの内部LVを共有経験値と各自の経験値補正値から
DA2の累計必要経験値式で再計算する。死亡者と逃走者もこの内部LV更新は受けるため、
戦闘中に条件を複数段階満たせば内部LVは一度に複数上昇する。ただし死亡者と逃走者には、
以降の熟練度、最大HP、最大MPの成長を適用しない。

武器熟練度は物理攻撃コマンド（通常攻撃、「ねらう」、「ためる」とその攻撃など）を選択した
行動と、装備武器をアイテムとして使用した行動を記録対象とする。通常のミスでも記録し、
左右に武器を装備していれば両方の武器種を対象にする。1行動の値は
`max(0, 最高対象敵LV + 適性 - 現在武器LV + 撃破加算 + 会心加算)` とする。
撃破加算と会心加算はそれぞれ1で、同時成立時は+2とする。戦闘内では武器種ごとの最大値だけを
保持し、累積しない。

呪文熟練度は通常の呪文使用時に、系統ごとに最高対象敵LVと実際に支払ったMPを記録する。
敵複数対象では対象の最高LV、味方対象では使用時点で生存している敵の最高LVを採用する。
戦闘終了時に系統ごとに
`max(0, 最高敵LV + 適性 - 現在呪文LV + floor(√消費MP累計))` を加える。
通常アイテムから発動した呪文は対象外とする。装備武器から発動した呪文は消費MP 0の
武器使用として武器熟練度へ記録する。

熟練度加算後、内部LVの低い順、同LVならパーティ表示順に、戦闘中に通常呪文を使ったメンバーの
最大MPを今回加算後の呪文LVで計算し、現在最大MPを上回る最初の1人だけ更新する。
次に同じ順で最大HPの内部計算値を比較し、現在最大HPを上回る最初の1人だけ更新する。
同じ戦闘で最大MPが上昇した本人だけは最大HP候補から外し、別キャラの最大HP判定は継続する。
どちらの判定にも6人目の控えを含め、内部LVや呪文LVが今回上がったかどうかは候補条件にしない。
最大値更新時も現在HP・現在MPは変更しない。熟練度は100ごとに複数LV繰り上げてよい。

### 勝利画面と成長リザルト

成長確定と同時に `da3-win.ogg` を非ループで再生し、再生終了後は直ちに現在フィールドのBGMへ
切り替える。勝利画面または成長リザルトでフィールド復帰の決定入力を受けた時点で同曲が再生中なら、
入力を保持し、曲の終了後にフィールド復帰を開始する。画面上部Windowへ
`battle.victory.reward` を使ってDA1と同じ「獲得経験値と合計Gold」のメッセージを表示する。
日本語表示の経験値、Gold、英字はすべて全角化し、日本語標準8×12フォントを使う。
ただし戦闘中の味方HP表示だけはレイアウト上の例外とし、全角文字を英語用6×8フォントで表示する。
生存して戦場に残った各キャラは戦闘スプライトの左から9番目（元X座標128px）と通常姿勢を、
DA2の30fps演出を60fps換算した40フレーム周期・最大70フレームで切り替える。

新しい決定入力時、最大HP、最大MP、いずれかの熟練度進行値のうち1つ以上が増えていれば
6人リザルトへ進み、すべて変化なしならリザルトを省略してフィールド復帰へ進む。
リザルトへ進む場合は標準の短いフェード（6フレームで暗転、黒画面で切り替え、6フレームで復帰）を
挟む。リザルトでは最初に成長前・熟練度加算前のスナップショットを12フレーム静止表示した後、
30フレームで各数値を整数補間して確定値まで増加させる。補間中に表示数値が変化したフレームでは、
変化した項目数にかかわらずSE2番を1回再生する。武器・呪文LVが上がった表示単位は
`POSITIVE_COLOR` にする。最大HP・最大MPが上がった場合は、HP／MPのラベル、現在値、区切りを
通常色のままとし、上昇した最大値の数値部分だけを `POSITIVE_COLOR` にする。
30フレーム終了時にいずれかの対象成長があれば、`da3-win.ogg` の再生途中でも中断して
`da3-lvup.ogg` を非ループで再生する。再生終了後は直ちに現在フィールドのBGMへ戻す。
レベルアップジングル開始前にフィールドBGMがすでに流れていた場合は、その再生位置から続きを流す。
待機中・補間中の入力とキャンセル入力は受け付けず、
補間完了後の新しい決定入力だけで `BattleResult.VICTORY` を確定してフィールド復帰へ進む。

### タイムライン移動

行動完了後は、先頭の行動済みアイコンを8フレームかけて画面下へ落下させる。落下終了後、
2～6番目のアイコンを8フレームかけて20px左へスライドする。同時に、表示範囲外にいる
7番目のアイコンを画面右端のX=256から、6番目の位置であるX=170へ同じ8フレームで
高速移動させる。

行動済み参加者の再設定後のゲージ値が6位以内に入り、かつその値より小さい参加者がいる場合は
「割り込み」とする。従来の左スライドが終了した直後、行動済みアイコンを画面下端から4フレームで
再挿入先へ垂直に滑り込ませる。アイコン同士は16×16pxの矩形で衝突判定し、割り込まれたアイコンを
20px右へ4フレームで押す。押されたアイコンが次のアイコンへ接触したら、そのアイコンにも同じ移動を
連鎖させる。6番目の位置から押し出されて7位へ転落するアイコンは右へスライドさせず、10フレームの
放物線で右下へ飛ばして画面外へ落下させる。参加者が6名未満で押し出し先に空きがある場合は、
空いた位置への右スライドだけを行う。

行動済み参加者が6位以内へ入らない場合は割り込みを行わず、左スライド完了時に新しい上位6名を
表示する。逃走して画面外へ到達した味方は再挿入せず、残りの参加者だけを左へスライドする。
全移動の完了後に次の手番へ遷移する。移動中はタイムラインの現在位置マーカーを表示しない。

## タイムラインの受け入れ条件

- 初期ゲージ値は各参加者の素早さと `[1.0, 2.0]` の乱数から計算され、降順に並ぶ。
- 各行動の直前は、全員へ同じ値を加算した結果として先頭のゲージ値が64になる。
- 行動済み参加者のゲージ値は現在の素早さへ戻り、安定した降順位置へ再挿入される。
- 逃走で離脱した味方はタイムラインへ再挿入されない。
- 再挿入位置が6位以内で後続により小さいゲージ値があれば、左スライド後に割り込み演出が発生する。
- 割り込みの衝突は16×16pxで連鎖し、7位へ転落したアイコンだけが右下へ放物線で画面外へ落下する。
- 画面へ表示するアイコンは、演出中を除いて常に現在の行動順の上位6名／体以内である。
- 戦闘中に決定ボタンを押し続けると、初回入力の20フレーム後から4フレーム間隔で、現在の
  入力対象に対する決定が繰り返される。ボタンを離して再度押すと初回入力として即時に決定される。
