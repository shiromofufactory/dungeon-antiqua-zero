# 戦闘表示データ

## 目的

本書は、戦闘Sceneがキャラクターとモンスターのマスターデータから戦闘用画像と
タイムライン表示を解決する規則を定める。行動順、ダメージ計算、コマンド入力などの
戦闘ルールは別途BattleSceneと戦闘Ruleの仕様で定める。

## 参照元と責務

- 正本は `content/data/characters.json` と `content/data/monsters.json` とする。
- ゲームは生成済みの `app/data` を読む。`app/data` は直接編集しない。
- BattleSceneまたは戦闘専用Rendererが、参加者の安定キーからマスターレコードを解決して
  描画する。表示名、配列順、敵種別による画像・アイコン座標の分岐を持たない。
- `Member`、戦闘ルール、セーブデータへ描画用の座標や画像サイズを複製しない。

## キャラクター

`characters.json` の各レコードは、既存の顔グラフィック座標に加えて次の表示データを持つ。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `icon_x` | integer | 戦闘シーン下部のタイムライン用16×16pxアイコンの、イメージバンク1内の左上X座標 |
| `icon_y` | integer | 同アイコンの左上Y座標 |
| `battle_sprite` | integer | `characters/ch_battle` の縦32px単位の戦闘スプライト位置を示す非負インデックス |

タイムラインアイコン座標は0以上の16px単位とし、イメージバンク1の範囲内に収める。
`battle_sprite` の描画元Y座標は `battle_sprite * 32` とする。スプライトの実際の切り出し幅、
配置、重なり順は戦闘Sceneが決め、キャラクター名を使って特例を作らない。

## モンスター

`monsters.json` の各レコードは次の表示データを持つ。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `image_id` | string または integer | モンスター画像のファイル名（拡張子なし）。`n-1` は `content/images/monsters/n-1.png` を指す |
| `width` | integer | モンスター画像の幅（px） |
| `height` | integer | モンスター画像の高さ（px） |
| `icon_x` | integer | 戦闘シーン下部のタイムライン用16×16pxアイコンの、イメージバンク1内の左上X座標 |
| `icon_y` | integer | 同アイコンの左上Y座標 |
| `mhp` | integer | 戦闘開始時の最大HPおよび初期HP |

`image_id` は空でない文字列または0以上の整数とし、画像ファイルは
`content/images/monsters/<image_id>.png` に置く。`width` と `height` は画像の実寸をpxで保持する。
タイムラインアイコンの座標規則はキャラクターと同じである。
`mhp` は1以上の整数とする。戦闘開始時に個体ごとの可変状態へコピーし、現在HPが0の
モンスターを死亡状態とする。マスターレコード自体は戦闘中に変更しない。

## 検証

共有JSONの検証では、キャラクターとモンスターの `icon_x`、`icon_y` がイメージバンク1内の
16px単位座標であることを確認する。キャラクターの `battle_sprite` は0以上の整数、
モンスターの `image_id`、`width`、`height`、`mhp` は上記の型と範囲を確認する。

画像の追加・変更時は `npm --prefix content run validate` を実行する。共有データを
ゲーム用へ反映する場合は `npm run sync`、画像をゲーム用に更新する場合は
`npm run image-build` を続けて実行する。

## 受け入れ条件

- キャラクターとモンスターのタイムラインアイコンは、各レコードの `icon_x`、`icon_y` が示す
  イメージバンク1の16×16px領域から描画される。
- キャラクターの戦闘スプライトは、各レコードの `battle_sprite` が示す縦32px単位の位置から
  描画される。
- モンスター画像は、各レコードの `image_id`、`width`、`height` から解決される。
- モンスターの現在HPは `mhp` で初期化され、0になった個体は死亡状態になる。
- 表示名、配列順、敵種別を画像またはアイコンの識別に使わない。

## 戦闘画面モック

`tools/screen_mocks/battle.py` は、フィオラ、セリオン、アルヴァンの3名を内部レベル99で
生成して表示する。
キャラクター名、戦闘スプライト、タイムラインアイコン、モンスター名、画像、画像寸法は、
いずれも生成済みのゲームデータから解決する。モック固有の敵配置とタイムラインの順序だけは
画面レイアウトのfixtureとして保持する。

### 戦闘開始演出

モック起動時は20フレームの戦闘開始フェーズとし、この間は入力を受け付けない。
モンスターはDA2の初期スライド量 `8, 8, 7, 7, 6` と1段階24pxの移動を基準にする。
ZEROは60fpsのため移動を補間し、各モンスターを画面左側からそれぞれ16、16、14、14、
12フレームで定位置へ到達させる。

味方は画面右端の見えない位置（X=256）かつ各自の定位置から上へ24pxの位置を始点とし、
10フレームかけて長い放物線を描きながら定位置へ着地する。フィオラ、セリオン、アルヴァンの
順に開始と着地を2フレームずつずらす。これらの移動と並行して、共通の画面フェードを使った
6フレームのフェードインを行う。
味方3名の名前とHPは、最後のアルヴァンが着地する14フレーム目からまとめて表示する。

タイムラインの先頭6アイコンは画面右端の見えない位置（X=256）を始点とし、各アイコンを
10フレームかけて定位置へ左移動させる。行動順に開始と到着を2フレームずつずらし、最後の
6番目は20フレーム目に到着する。移動中はタイムラインの現在位置マーカーを表示しない。
全演出の完了後はボタン入力待ちを挟まず、フィオラのコマンドWindowを開いて最初の行動ターンへ
遷移する。

開発中に開始演出を繰り返し確認できるよう、メニュー入力（Sキー、またはメニューに割り当てた
ゲームパッドボタン）で、どのフェーズからでも戦闘開始フェーズを再実行する。リセット時は
味方のHP・MP、モンスター、インベントリ、選択状態、演出タイマーを初期状態へ戻す。

### コマンド構成と「こうたい」

戦闘コマンドの表示有無と選択可否は、Pyxelや画面モックに依存しない
`app/battle_commands.py` で判定する。戦闘Sceneは行動者、パーティ、敵隊列に加え、沈黙、
アイテム、逃走などの戦闘状況に応じた可否を渡し、画面側は返されたコマンド順と
`enabled` を表示へ反映する。将来スキルや状態異常で選択肢が変化する場合も、モック固有の
条件分岐は追加しない。

左列は、次の順に表示条件を評価し、3件を表示した時点で以降を評価しない。「こうげき」は
攻撃対象がある場合だけ表示する（後衛で短距離武器の場合は表示しない）。「こうげき」が
非表示の場合は「ぼうぎょ」を左列先頭に表示する。「じゅもん」は、
ミスティック、セイクリッド、ネザーのいずれかの基礎適性が1以上なら表示し、沈黙中は
disabledにする。続いて「ねらう」「かくれる」「しきべつ」「いのり」「かばう」「いあい」
「ためる」「ブレス」「MPシェア」を、この順で対応スキルの保有時だけ表示し、最後に常時
表示の「ぼうぎょ」を評価する。

右列は「にげる」「アイテム」「こうたい」の固定順とする。隊列変更コマンドの表示名は、行動者が
前衛なら `battle.command.retreat`（こうたい）、後衛なら `battle.command.advance`（ぜんしん）とする。
パーティが1名なら表示せず、前衛を残せないときはdisabledにする。パーティが1名であり、かつ左列の上限により
「ぼうぎょ」が左列に表示されなかった場合だけ、右列3段目に「ぼうぎょ」を表示する。

「こうたい」を決定すると、行動中の味方を前衛から後衛、または後衛から前衛へ移す。
前衛から後衛へ移した結果、パーティ全員が後衛になる場合は「こうたい」をdisabled色で表示し、
カーソルの選択対象から外す。後衛から前衛への移動は常に選択できる。パーティが1名だけの場合は
「こうたい」自体をコマンドWindowへ表示しない。

「ぼうぎょ」を決定した味方は、次に自身の手番が始まるまで防御状態を維持する。防御状態中の
スプライトは、通常立ち絵ではなくキャラクター戦闘画像の左端から `16 * 7` px の位置を始点に
した16×32pxを描画する。

### コマンドガイド

コマンド選択中、同じコマンドにカーソルを30フレーム（DA2の30fps・15フレーム相当）留めると、
選択中コマンドのガイドWindowを表示する。Windowは `(0, 0, 34, 13)` とし、
コマンドWindow `(34, 0, 30, 13)` の左に接して画面左上を占める。カーソル移動、コマンドの
決定・キャンセル、またはコマンドWindowが開閉中の間は、ガイドを即時に閉じて待機時間を
リセットする。

ガイド本文は `battle.guide.*` の文言キーから3行までを表示する。DA2に同様のガイドがない
`battle.command.aim`、`battle.command.iai`、`battle.command.focus`、
`battle.command.breath`、`battle.command.mp_share`、`battle.command.escape`、
`battle.command.retreat`、`battle.command.advance` は、暫定として対応する `battle.command.*` の文言そのものを
1行で表示する。

隊列移動はDA2の戦闘中歩行を基準にする。DA2の30fps・1フレーム4pxに相当する速度として、
ZEROでは1フレーム2px、合計8フレームで前後列間の16pxを移動する。移動中のスプライトは、
通常立ち絵と同じ切り出し位置、およびその16px右から始まる切り出し位置を2フレームごとに
交互表示する。コマンドWindowは決定時に即時に閉じ、移動完了後はそのキャラクターの行動を
完了して通常のタイムライン移動へ進む。

### アイテム使用

「アイテム」を決定すると、コマンドWindowとは独立した使用候補Window `(32, 0, 32, 13)` を
表示する。コマンドWindowの右端は維持したまま、左へ8px広げる。一度に表示する候補は最大3件とし、上下入力で全候補を循環し、選択行が表示端を
越えた場合は一覧を追従スクロールする。候補が4件以上ある間は、一覧Window右枠の上端と下端へ
共通の縦スクロールインジケータを表示する。説明Windowはコマンドガイドから分離したアイテム専用の
`(0, 0, 32, 13)` に表示し、使用候補Windowと接して配置する。選択中アイテムの
`ItemDetailContext.BATTLE` の使用効果を最大3行表示し、アイテム選択を開いた直後から常時表示する。

候補はDA2と同じく、行動者が装備している武器・腕装備を使用効果の有無にかかわらず先に並べ、続いて所持中の
`type1=ITEM` かつ `type2=ITEM` の、使用効果が `spells.json` で `on_battle=1` の消耗品を
マスターデータ順に並べる。戦闘中に使えない成長アイテムやネクターは表示しない。装備品は名前の
先頭へ `＃` を付け、消耗品は右端に所持数を表示する。本モックのインベントリはテスト用に
`items.json` の全アイテムを1個ずつ所持した状態で開始する。

ZEROでは味方ごとにコマンドを選択・完了するため、DA2のような未発動の選択済みアイテムを
予約して候補から除く処理は行わない。使用効果のある候補を決定するとその味方の行動を完了する。`break=1` の
消耗品は所持品から1個減らし、同フラグの装備品は装備枠から外すため、それ以後の手番では候補に
表示しない。使用効果のない武器・腕装備を決定しても行動は完了せず、候補選択を継続する。
キャンセル時はコマンド一覧へ戻り、カーソルは「アイテム」へ復帰する。

### 呪文使用

「じゅもん」を決定すると、呪文Window `(36, 0, 28, 16)` を表示する。
高さは4行とし、1回に表示するのはミスティック、セイクリッド、ネザーのいずれか1系統とする。
左右入力で系統を切り替え、上下入力で各系統のレベル1から9、続いてレベル0の候補をスクロールする。
候補は行動者が習得済みで `on_battle=1` の呪文だけとし、MP不足の呪文は灰色で表示して選択対象から除く。

選択中呪文の説明と消費MPは画面左上のガイドWindow `(0, 0, 36, 16)` に、現在MPはその右下へ
重ねる小Window `(20, 9, 16, 7)` に表示する。ガイドは説明2行の後に1行空け、4行目へ消費MPを
表示する。
現在MPは最大MPを省略した `ＭＰ　２０７` 形式とし、日本語の8×12フォントで表示する英数字は
現在MPと消費MPを含めて全角化する。呪文を決定すると消費MPを引き、効果演出はまだ実行せずに
その味方の手番を完了する。キャンセル時はコマンド一覧へ戻り、カーソルは「じゅもん」へ復帰する。

### 通常攻撃のターゲット選択

モックの敵は画面最上部のヒュージスパイダー1体とコヨーテ2体を前衛、残る
ヒュージスパイダー2体を後衛とする。「こうげき」の
選択可能範囲は、行動者の現在の隊列と装備中の武器の `reach` から次のように決定する。
二刀流で複数の武器を装備している場合は、DA2と同様に最も短い `reach` を使う。素手は
`reach=1` 相当として扱う。

| 行動者 | `reach=1` | `reach=2` | `reach=3` |
| --- | --- | --- | --- |
| 前衛 | 敵前衛のみ | 敵全員 | 敵全員 |
| 後衛 | 選択不可 | 敵前衛のみ | 敵全員 |

「こうげき」を決定すると、選択可能な敵のうち末尾の敵を初期ターゲットとする。指アイコンは
コマンド選択と同じ `WindowCursor` を使い、モンスター名を含む全Windowより後に描画する。
上下左右入力では5体配置用の候補順に移動し、攻撃範囲外の敵を飛ばす。

配置を上から右列3、左列1、右列4、左列2、右列5とした場合、4からは上で3、下で5、
右で2、左で1へ移動する。2からは上下とも1、右で5、左で4へ移動する。フィオラの
`reach=1` では1と2を選択できないため、4で右を入力した場合は2を飛ばして5へ移動する。
全ての敵を選択できる場合、2で右を入力すると5へ、続けて5で左を入力すると2へ戻る。
横方向は、右入力で1、4、2、5、3の順、左入力でその逆順に循環する。選択できない敵は
同じ方向の循環順に沿って飛ばす。このため前衛だけを選択できる場合、5で左を入力すると
2を飛ばして4へ移動する。
キャンセルするとコマンド選択へ戻る。決定時は対象の現在HPを0にして、後述の撃破演出を開始する。
演出完了後にコマンドWindowを閉じたままタイムライン移動を開始する。移動後の手番が味方なら、
ボタン入力を待たずにコマンドWindowを開き直す。死亡済みの敵はターゲット候補から除外する。
選択可能な敵がいない場合はターゲット選択へ遷移せず、コマンド選択を継続する。
ターゲット選択中、攻撃範囲外となる後衛の敵画像は、元画像の色とUI用グレーを1対1で
合成した専用パレットへ変更して表示する。

敵前衛の現在HPが全員0になった時点で、生存している後衛の敵を全員前衛へ昇格させる。
昇格そのものには移動などの演出を付けず、以後の攻撃範囲判定へ即時に反映する。

### モンスター撃破演出

通常攻撃の対象を決定するとコマンドWindowとターゲットカーソルを即時に閉じ、対象だけを
赤紫へ変色させる。6フレーム赤紫を保持した後、12フレームかけて白に近い薄紫へ明るくする。
続いて16フレームかけてディザの描画率を1から0へ下げ、ドットに少しずつ穴が開くように消滅させる。
全体は34フレームとし、元のモンスター画像の画素データは変更しない。

演出中も現在HPは0であり、演出が完了した個体は画面、モンスター名、攻撃対象、行動順から除外する。
その後、攻撃した味方の行動を完了して通常のタイムライン移動へ進む。デバッグ用の戦闘再開時は、
全モンスターの現在HPを各個体の最大HPへ戻し、初期隊列、初期行動順、表示を復元する。

### モックの行動順

初期順はフィオラ、セリオン、アルヴァン、ヒュージスパイダー3体、コヨーテ2体とし、
戦闘に参加する敵味方8名／体をすべて行動順に含める。行動を終えるたびに先頭を末尾へ
追加して循環させる。画面上のタイムラインには行動順の先頭から最大6名／体までを表示する。
セリオンはモック内では前衛とする。
タイムライン先頭の味方だけ、名前とHPを白文字で表示し、それ以外の味方は灰色で表示する。
コマンド、アイテム、呪文、攻撃対象、逃走確認を入力中の味方スプライトは、通常色からわずかに
白寄りの色、通常色へとパレットを周期的に変化させる。入力完了時から通常色で表示する。左側の
矢印カーソルは表示しない。
通常攻撃、アイテム、じゅもん以外のコマンドは、ぼうぎょを除き効果を実行せず、選択した時点で
その味方の行動を完了して次へ進める。「ぼうぎょ」は次の自身の手番まで防御状態と防御用スプライトを
維持する。
攻撃可能な敵がいない味方では、コマンドWindowから「こうげき」を除外し、左列はコマンド
構成ルールに従って残りの候補から再配置する。右列のコマンドと位置は変更しない。

### コマンドのキャンセルと逃走

コマンド選択中にキャンセル入力（Bボタン）を行うと、モックを終了せずにコマンドWindowを
閉じ、コマンド非表示のボタン入力待ちへ戻る。決定入力でコマンドWindowを再度開く。
ターゲット選択中のキャンセルは、従来どおりコマンド選択へ戻る。
コマンドWindowを開く際は通常の開閉アニメーションのうち開く演出だけを使用し、閉じる際は
遷移先にかかわらず1フレームで非表示にする。

「にげる」を選ぶと、ターン数にかかわらず「ほんとうに にげて いいですか？」の確認と
「はい」「いいえ」の選択を表示する。文言はそれぞれ `battle.escape.confirm`、
`settings.yes`、`settings.no` を参照する。「はい」を決定すると、行動中の味方を逃走状態にして
右向きへ反転し、その味方の行動を完了する。以後に別の味方へ手番が回るとコマンドWindowを
開かず、自動的にその味方も逃走状態へ移して行動を完了する。途中の敵手番は通常どおり進行する。
味方全員が逃走状態になった時点でBGMを停止し、DA2の逃走を基準として全員を同時に画面右へ
6px/フレームでX=260まで走らせる。通常立ち絵とその16px右から始まる歩行絵を2フレームごとに
交互表示する。逃走開始と同時に味方の名前とHPを非表示にし、画面上部へ
`battle.escape.started` のメッセージを表示する。メッセージ表示中も走行を続け、全員が画面外へ
到達した場合はその位置で入力を待つ。決定またはキャンセル入力でメッセージを閉じると同時に、
共通の6フレームフェードで画面全体を暗転する。黒へ到達した後は明転させず、完全暗転かつ全員が
X=260へ到達した時点でモックを終了する。メッセージ表示中以外の逃走演出では入力を受け付けない。
「いいえ」の決定またはキャンセルでは、行動順を進めずに
コマンドWindowを開き直す。確認WindowはコマンドWindowを即時に閉じた後に表示する。

モンスター名は常時表示せず、通常攻撃のターゲット選択中と、コマンドWindowが完全に閉じた
ボタン入力待ちの間だけ表示する。コマンドWindowの開閉アニメーション中、コマンド選択中、
逃走確認中、タイムライン移動中、敵手番には表示しない。ボタン入力待ちでは全ての生存
モンスター名を白文字で表示する。ターゲット選択中は選択可能なモンスター名を白文字、
攻撃範囲外となりグレー表示中の後衛モンスター名を灰色で表示する。

敵の手番ではコマンド入力を受け付けず、その敵を点滅させる。点滅時間はDA2の30fpsにおける
11フレームを、ZEROの60fpsに合わせた22フレームで再現する。点滅は12フレーム周期とし、
6フレーム表示、6フレーム非表示とする。
点滅終了後はタイムライン移動を経て次の参加者へ手番を回す。モックでは敵の攻撃処理は行わない。

### タイムライン移動

行動完了後は、先頭の行動済みアイコンを8フレームかけて画面下へ落下させる。落下終了後、
2～6番目のアイコンを8フレームかけて20px左へスライドする。同時に、表示範囲外にいる
7番目のアイコンを画面右端のX=256から、6番目の位置であるX=170へ同じ8フレームで
高速移動させる。移動完了時に行動済みの参加者を行動順の末尾へ追加し、次の手番へ遷移する。
移動中はタイムラインの現在位置マーカーを表示しない。
