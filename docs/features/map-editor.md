# マップエディタ仕様

## 位置付け

本書は、マップチップメタデータ設定ツールで定義した地面・境界・表示候補・アニメーション・
オブジェクト・通行設定を使って、ワールド、ダンジョン、町のマップを制作するツールの仕様を
定める。タイルセット側の仕様は
[`map-chip-metadata-tool.md`](./map-chip-metadata-tool.md)を参照する。

地面、オブジェクト、ワールドマップ拠点、施設マップの名称なし移動口、マップ内到着地点を対象とする。拠点と移動口の詳細は
[`world-sites.md`](./world-sites.md)を参照する。通常イベントの定義、マップ上のトリガー、
actorとの接続は [`events.md`](./events.md) を正本とし、現在の制作用マップ形式version 6で扱う。
イベント本文や条件式はタイルセットメタデータへ埋め込まない。

## 結論

- 地面はタイルセットの地面IDをブラシとして選び、マップ上へドラッグ塗布する。
- オブジェクトはタイルセットの定義IDを選び、左上起点で配置する。
- 異なる起点のオブジェクトは重ねてよい。同一起点への複数配置は禁止する。
- 配置要素は右クリックで単体選択でき、右ドラッグの矩形で複数選択して一括移動・削除できる。
- 単体選択したオブジェクトはドラッグ移動、削除、同一下端内での前後移動ができる。
- 拠点は配置オブジェクトまたはセル座標をアンカーにし、複数入口と単一の移動先を設定する。
- actorを安定ID付きで配置し、宝箱以外のactor用の `touch` ・ `interact` トリガーを自動設定する。
  宝箱は専用画像とGold／アイテムの中身を設定する。
  cellとobjectには `step` または `touch` の単独トリガーを設定できる。
- 各マップには、別マップから入るときの到着地点を設定できる。
- 重なったオブジェクトは下端Y座標が大きいものを手前へ描画する。
- 境界ルールとランダム表示候補はマップエディタ独自の実装を持たず、共通の
  `scripts/map_pipeline` で解決する。
- 保存時に制作用JSONとゲーム用JSON・パレット番号アトラスを生成する。
- ゲーム用データには境界判定、ランダム抽選、地面合成、オブジェクト定義展開、通行判定を残さない。

## ファイル配置

```text
content/maps/
├── tilesets/<tileset_id>.json       # メタデータ設定ツールの正本
└── sources/<map_id>.json             # マップエディタの正本

app/maps/
├── <map_id>.json                     # 解決済みゲーム用データ
└── <map_id>.bin                      # Pyxelパレット番号の合成済みチップアトラス
```

`content/maps/sources` はGitでレビューする。`app/maps` は同じ入力から再生成できるGit管理外の
生成物であり、直接編集しない。

## 制作用マップ形式

形式version 6の例を示す。

```json
{
  "format_version": 6,
  "map_id": "worldmap",
  "profile": "world",
  "tileset_id": "worldmap",
  "bgm_id": "da3-field",
  "size": [32, 24],
  "visual_seed": 0,
  "grounds": [
    ["sea", "sea", "sea"],
    ["sea", "plain", "sea"]
  ],
  "objects": [
    {
      "id": "town_1_1",
      "definition_id": "town_1",
      "origin": [10, 8],
      "order": 4
    }
  ],
  "sites": [],
  "arrival_points": [],
  "actors": [],
  "event_triggers": []
}
```

| 属性 | 内容 |
|---|---|
| `format_version` | 制作用マップ形式。宝箱actorを含む形式は6 |
| `map_id` | `lower_snake_case` の安定ID |
| `profile` | `world`、`dungeon`、`town`。タイルセットのprofileと一致すること |
| `tileset_id` | 使用するタイルセットID |
| `bgm_id` | マップでループ再生するBGM ID。`app/audio` からの拡張子なし相対パス |
| `size` | 幅16〜512セル、高さ15〜512セル。最小寸法は1画面分 |
| `visual_seed` | ランダム表示候補を決定する0以上の整数 |
| `grounds` | 行・列順の最上位地面ID。行数と列数は `size` に一致させる |
| `objects` | オブジェクト実体の配列 |
| `sites` | worldでは名前付き拠点、town／dungeonでは名称なし移動口として使う移動元レコードの配列 |
| `arrival_points` | 別マップまたは同じマップから移動するときの到着地点レコードの配列 |
| `actors` | マップ内actorの安定ID、初期位置、種別、見た目または宝箱の中身 |
| `event_triggers` | イベントID、発火方法、cell／object／actorアンカー、対象offset |

オブジェクト実体IDは配置時に定義IDから自動生成する。`origin` は定義の左上起点、`order` は
描画グループと下端Y座標が同じ実体間の描画順を表す。通常の `object`、既存の前面パーツである
`object_overlay`、actorと下端Yで前後を切り替える `object_y_sorted`、屋根などの
`object_foreground` の順に描画する。`object` と `object_overlay` はactorより背面、
`object_foreground` はactorより前面に置く。`object_y_sorted` はactorの足元Yと実体の下端Yを
共通の描画列で比較し、同じYではactorを先に描いてオブジェクトを前面にする。各グループ内は
`origin.y + definition.size.height - 1` で求めた下端Y、`order`、起点X、実体IDの順に奥から手前へ行う。

タイルセットの先頭地面をベース地面とし、全profileで外周をベース地面にする。ベース地面は
タイルセット作成後に変更できず、親地面を持たない。`world` profileではベース地面を `sea` とする。
マップ外は全地面レイヤーに対して異なる地面とみなし、通行不可とする。

## 画面と操作

ヘッダーの「マップ／イベント」で、同じローカルサーバー上のマップエディタとイベントエディタを
切り替える。両エディタは同じヘッダー高とブランド領域幅を使い、切り替え前後でナビゲーションの
位置を変えない。編集対象・生成先のファイルパスはヘッダーに表示しない。未保存変更がある状態で
別のエディタへ切り替える場合は独自ダイアログを表示し、「保存して移動」「変更を破棄して移動」
「キャンセル」から選べるようにする。「保存して移動」は保存に成功した場合だけ移動する。
ブラウザ自体を閉じる、再読み込みするなど独自ダイアログを使えない操作ではブラウザ標準の確認を使う。
ヘッダーで選択した保存済みマップはブラウザへ記憶し、次回起動時にURLで別のマップが指定されて
いなければ自動選択する。記憶したマップが削除済みの場合は、通常の既定マップを開く。
問題一覧は編集のたびに自動更新するため、独立した検証ボタンは設けない。保存時にも同じvalidatorを
再実行する。
保存ボタンはエラーのない保存済み状態でだけ無効にする。未保存または検証エラーのある状態では、
保存を試行できるようボタン自体は有効にする。
外周がベース地面でないエラーがある場合も、編集用プレビューには現在の地面をそのまま表示し、
ベース地面ブラシで外周セルを塗り直せるようにする。ゲーム用生成時の外周検証は緩和しない。
既存マップを開いたとき、タイルセットから削除済みの地面IDが配置データに残っている場合は、
該当セルをタイルセット先頭のベース地面へ置き換える。補修したセル数を通知して未保存状態とし、
通常の「保存・生成」で制作用JSONとゲーム用データへ反映できるようにする。非対話検証では
未定義の地面IDを引き続きエラーにし、暗黙に補修しない。

画面は次の3列を基本とする。

1. 左: 地面／オブジェクト／拠点・移動／イベントのパレット
2. 中央: スクロール・ズーム可能なマップキャンバス
3. 右: マップ設定、選択オブジェクト・拠点・到着地点、問題一覧

狭いウィンドウでは問題一覧を下段へ移す。キャンバスを主要作業領域として最も広く取る。

マップ設定のBGM欄には `app/audio` にあるOGGを拡張子なしのIDで一覧表示し、profileに
かかわらずマップごとに1曲を選択する。新規マップはworld／dungeonを `da3-field`、townを
`da3-town` とする。マップチップを変更して配置内容を初期化する場合も、選択済みBGMは維持する。

### 地面

- 地面パレットは、親地面を含めて通常表示を合成した代表画像を表示する。
- 通常の「ブラシ」は、地面を選択してキャンバス上をドラッグすると、通過した各セルの最上位地面IDを置き換える。
- 「矩形塗り」は、左ドラッグ中に開始セルと終了セルを含む矩形を破線枠でプレビューし、ボタンを
  離した時点で矩形内の全セルを選択中の地面へ置き換える。クリックだけの場合は1セルを塗る。
- ブラシの1回のドラッグ、または矩形塗りの1回の確定を、それぞれ1回のUndo単位とする。
- 境界表示とランダム候補は、現在の周囲8セルと `visual_seed` から共通処理で解決する。
- アニメーションはタイルセットのフレーム間隔で再生し、一時停止できる。

### オブジェクト

- パレットで定義を選択し、左クリックしたセルを起点として新しい実体を配置する。配置モードと
  選択モードは設けない。
- キャンバス上へポインターを置くと、選択中定義の幅・高さに合わせた配置先を破線枠で表示する。
  配置できる範囲は緑、マップ外へはみ出すか同一起点が使用済みの範囲は赤で表示する。
- マップ外へはみ出す配置は行わない。
- 同一起点に既存実体がある場合は新規配置せず、既存実体を選択する。
- 右クリックでは現在のタブに属する対象を優先し、オブジェクトタブでは最前面オブジェクト、
  拠点・移動タブでは到着地点・拠点、イベントタブではactor・単独トリガーを先に選ぶ。
  現在のタブに対象がない場合は、他タブの対象を表示上の手前から選んで対象の編集タブへ移る。
  同じセルに複数種別が重なる場合は、右クリックを繰り返すと次の対象へ切り替える。
  オブジェクトを選択した場合は、パレットの選択中定義もその実体の定義へ切り替える。
  ブラウザのコンテキストメニューは表示しない。
- タブを切り替えた時点で、切替先タブに属さない選択状態を解除する。地面タブではオブジェクト、
  拠点・到着地点、actor・トリガーをすべて選択解除する。
- 単体選択済みのオブジェクト上から右ドラッグした場合は、その実体を続けて移動する。未選択の
  セルから右ドラッグした場合は配置要素の範囲選択とする。ボタンを動かさず離した場合は単体選択だけを行う。
- 選択実体はピンク枠で示し、左ドラッグでも移動できる。左右どちらのドラッグでも、掴んだ
  セルと起点の相対位置は維持する。
- オブジェクトタブでは、配置済みオブジェクトの各構成セルを薄いピンクで塗って同色の枠で囲み、
  地面や別のオブジェクトに紛れた配置も判別できるようにする。透明な矩形余白は表示対象にしない。
- ドラッグ先がマップ範囲外、または別実体と同一起点になる場合は、その位置へ移動しない。
- 1回のドラッグ移動を1回のUndo単位とする。
- オブジェクトの下端Y座標が大きい実体を手前へ描画する。同じ下端の場合は `order` で決め、
  背面移動・前面移動の操作対象は同じ下端の実体間に限られる。
- `object_overlay` の前面パーツは通常オブジェクトより必ず手前へ表示し、パレットと選択情報に
  「前面パーツ」と表示する。
- `object_y_sorted` はカウンターなどに使い、actorより下端Yが大きいときはactorの手前、
  小さいときはactorの背面へ表示する。同じYではactorの手前へ表示し、パレットと選択情報に
  「キャラクターY整列」と表示する。
- `object_foreground` はプレイヤーやactorより手前へ表示し、パレットと選択情報に
  「キャラクター前景」と表示する。屋根や樹冠などに使い、構成セルは通常オブジェクトと同様に
  `passable` を設定できる。
- DeleteまたはBackspaceでも選択実体を削除できる。ただし入力欄への文字入力中は反応しない。

### 配置要素の範囲選択

- 右ボタンを押して別セルまでドラッグすると、開始セルと終了セルを含む矩形をピンクの破線枠で表示する。
- 単体選択済みのオブジェクト、拠点・移動口、到着地点、actor、単独トリガーの表示セルから
  右ドラッグを始めた場合は、範囲選択ではなく選択対象を移動する。object／actorアンカーの
  拠点・移動口またはトリガーでは、アンカー側を移動して選択対象を追従させる。
- 矩形内に表示セルが1つでも入るオブジェクト、拠点、到着地点、actor、単独トリガーを、
  現在のタブにかかわらずまとめて選択する。地面セルは範囲選択の対象に含めない。
- 選択対象のいずれかを左ドラッグすると、セル間の相対位置を保ったまま全対象を移動する。
  セルアンカーの拠点・トリガー、到着地点、actorは直接移動し、object／actorアンカーの要素は
  アンカー側の移動へ追従する。
- いずれかの対象がマップ外へ出る場合、または移動後のオブジェクト起点が重複する場合は、
  その位置へ移動しない。1回の一括ドラッグを1回のUndo単位とする。
- インスペクターの「選択範囲を削除」またはDelete／Backspaceで全対象を1回のUndo単位として削除する。
  オブジェクトを削除した場合は、それをアンカーにする拠点・トリガーも削除する。actorを削除した
  場合は、actor用トリガーも削除する。
- 範囲選択後にEscを押すと、配置データとUndo履歴を変更せずに範囲選択だけを解除する。
  入力欄の編集中またはダイアログ表示中のEscは、入力欄・ダイアログ側の操作を優先する。
- ドラッグせず右ボタンを離した場合は従来どおり単体選択とし、重なった対象を順に切り替える。

### 拠点・移動

- world profileの配置オブジェクトは拠点、town／dungeon profileの配置オブジェクトは移動口へ紐づけられる。
- オブジェクトを使わない拠点・移動口は、座標アンカーとしてキャンバスへ直接追加する。
- 座標アンカーはキャンバス上のピンクのマーカーを左ドラッグして移動する。1回のドラッグを
  1回のUndo単位とし、専用の移動ボタンは設けない。
- 拠点ID、入口セル、単一の移動先マップID・到着地点IDを編集する。移動先は作成済みマップと、
  そのマップに存在する到着地点のリストから選択する。
- 拠点名の文言キーは `location.<拠点ID>` を拠点ID欄の下へ小さな注記として表示し、日本語名だけを
  入力できる。新規拠点の日本語名には `拠点1` のような重複しない仮名を入れ、保存時に
  `content/data/texts.json` へ反映する。
- town／dungeonの移動口は名称入力欄を持たず、ゲーム中にも名称を表示しない。
- town／dungeonの移動口一覧には名称の代わりに、移動先マップIDと移動先到着地点IDを
  `移動先: <map_id> / <arrival_id>` の形式で表示する。両方が未設定の場合は「移動先未設定」と表示する。
- 拠点・移動口IDの自動採番は、worldでは全worldマップの拠点ID、town／dungeonでは編集中
  マップ内の移動口IDを既使用IDとして扱い、検証と同じ一意性の範囲で衝突を避ける。
- 到着地点はマップprofileにかかわらず追加でき、位置、ID、向き、テレポート対象フラグを編集する。
  到着地点とactorの位置はキャンバス上でドラッグして移動し、各編集欄には専用の「セルを移動」ボタンを置かない。
  テレポート対象の場合は対応する拠点IDをリストから選択する。
- 拠点と到着地点のマーカーは常時判別できる濃さで表示し、「拠点・移動」タブではさらに強調する。
  選択中の拠点の入口セルと到着地点の配置セルは、他の選択対象と同じピンクの枠で囲む。
- 拠点または到着地点を一覧から選択すると、対象位置がスクロール可能な範囲でキャンバスの
  表示領域中央へ来るよう即時スクロールする。複数入口を持つ拠点は、入口セル群の中心を対象位置とする。
- 拠点を作成しても到着地点は自動作成しない。施設出口やテレポートに使う到着地点は、必要に応じて
  「到着地点を追加」から独立して作成する。拠点自身は到着座標・向きを持たない。未選択の移動先は
  IDの書式不正ではなく、マップまたは到着地点の選択が必要な状態として案内する。
- 詳細な操作、マーカー、検証条件は [`world-sites.md`](./world-sites.md) を正本とする。

### イベント

- actorはキャンバスへ配置後、安定IDと種別を編集する。スプライトは番号を直接入力せず、
  種別に対応する共通シートの候補をダイアログで確認して選択する。人物actorではNPC用と
  PC用の両シートを同じダイアログへ表示し、選択した `sprite_source` と `sprite_index` を保存する。
  選択肢には画像元と内部の `sprite_index` を併記し、キャラクターは下向きの静止画像を代表表示する。
  固定物には向きを表示せず、固定・移動キャラには初期向きを表示する。配置済みactorは
  現在の種別、スプライト、向きに対応する画像をキャンバス上へ直接表示する。人物actorは
  16×32pxの立ちコマを配置セルの足元に揃え、固定物は従来どおり16×16pxで表示する。
- 固定・移動キャラの編集欄には「浮遊」checkboxを置き、マップの `floating` booleanを編集する。
  新規actorの初期値はOFFとする。NPC画像とPC画像の切り替えでは値を変更せず、種別を
  `prop` または `treasure` に変えた場合はフィールド自体を削除する。スプライト選択ダイアログの
  候補画像は浮遊させず、選択中actorのプレビューとマップキャンバスではONのときだけ本編と同じ
  20フレーム間隔と `map_id + actor ID` 由来の開始位相で待機パターンを切り替える。
  描画Y座標はずらさず、ベッドなど浮遊を無効にした配置を制作時に確認できるようにする。
- 宝箱はキャンバス上で `actors/treasure` の閉じたコマを表示する。actor編集欄には画像プレビュー、
  画像選択、向きを表示しない。中身の種別をGold／アイテムから選び、Goldは金額、アイテムは
  マスターデータの候補から種類を設定する。
  詳細なデータ形式と開封規則は [`treasures.md`](./treasures.md) を正本とする。
- 宝箱以外のactorを作成または選択すると、`touch` と `interact` のペアを持つ専用トリガーを
  自動的に1件紐づける。actor編集欄で起動イベントだけを選び、発火方法は表示しない。
  宝箱ではactorトリガーとイベント操作を表示しない。
- 単独トリガーはcellを直接指定するか、「object trigger」を選んでからキャンバス上のobjectを
  指定して追加する。objectモードの選択状態はイベントモードへ持ち越さない。
- trigger IDは配置時に内部で自動採番し、画面には表示せず編集もさせない。トリガー一覧と
  選択情報の見出しには、参照するイベントIDを表示する。
- イベントIDは生成可能なイベント定義の一覧から選び、自由入力しない。
- 単独トリガーの発火方法は `step` と `touch` だけを選択でき、`interact` は選択肢に出さない。
  対象offsetはキャンバスで編集する。
- 単独トリガーのマーカーは常時表示し、「イベント」タブではさらに強調する。
- actorとトリガーの詳細な形式、発火優先順位、マーカーは [`events.md`](./events.md) を正本とする。

### 表示補助

- 地面タブでは「地面だけを表示する」を切り替えられる。有効時は地面編集を妨げないよう、
  オブジェクト、actor、拠点・到着地点、イベントマーカー、範囲選択、通行不可表示を隠す。
  グリッドと地面の塗布プレビューは表示する。
- グリッド表示と通行不可表示は独立して切り替えられる。
- 通行不可表示は、地面と全オブジェクトの判定を合成した結果を赤で示す。
- ズーム、グリッド、通行不可表示、地面だけの表示はマップIDごとのブラウザ設定として保持する。
- 「見た目を振り直す」は `visual_seed` を1増やす。通常の保存ではseedを変更しない。

### 寸法変更

- 幅の増減は左側または右側、高さの増減は上側または下側をそれぞれ指定できる。既定は
  右側・下側とする。
- 左側・上側を増減する場合は既存地面を新しい座標へ移し、配置済みオブジェクトの起点も
  増減セル数だけ移動する。actorとcellアンカーのトリガーも同じ量だけ移動し、相対位置を維持する。
- 拡張部分はprofileにかかわらずタイルセット先頭のベース地面で埋める。
- 縮小で範囲外になったオブジェクトは自動削除せず、問題一覧へエラーとして表示する。

## 保存とゲーム用生成

保存操作は次を1回の操作として行う。

1. タイルセットと制作用マップを検証し、`bgm_id` に対応するゲーム用OGGの存在を確認する。
2. 各セルの地面親子スタックと境界ルールを解決する。
3. `visual_seed`、マップID、座標、地面レイヤーまたは実体IDから表示候補を決定する。
4. 地面レイヤーを16×16pxへ合成し、同一チップをアトラス内で重複排除する。
5. オブジェクト定義を実体ごとの描画セルへ展開する。
6. 地面を初期値としてオブジェクトを描画順に処理し、`blocked` と `passable_override` を
   反映した通行グリッドを生成する。
7. `interact_through` が有効なオブジェクトの構成セルから、決定操作を1セル先へ通すグリッドを
   生成する。
8. 拠点の相対座標を絶対セルへ解決し、文言キーを拠点IDから生成して、到着地点とともに
   ゲーム用JSONへ収録する。
9. worldの拠点の日本語名を `content/data/texts.json` へ反映する。
10. actorとトリガーアンカーを検証し、トリガーの対象セルを解決して、`bgm_id` とともに
   ゲーム用JSONへ収録する。
11. 制作用JSON、ゲーム用JSON、パレット番号アトラスを原子的なファイル置換で保存する。

コンパイルが失敗した場合は制作用データと直前のゲーム用生成物を置き換えない。ゲーム用JSONは
入力ハッシュ、タイルセットハッシュ、合成済み地面チップ、展開済みオブジェクトチップ、
アニメーション差し替え列、通行行、決定操作通過行を持つ。ゲーム実行時は制作ルールを再評価しない。

## 検証

保存エラーにする項目:

- ID、format version、profile、tileset ID、BGM IDの不正、およびBGMのゲーム用OGGが存在しない状態
- `size` と地面行列の不一致、未定義地面ID
- 外周がタイルセット先頭のベース地面でない状態
- 未定義オブジェクト、重複実体ID、同一起点、範囲外配置、不正な描画順
- 拠点、入口、到着地点、マップ間参照の不正
- actor、トリガー、イベントID、発火方法、アンカー、offsetの不正
- タイルセット側の親循環、境界、表示候補、画像座標などのエラー
- 合成アニメーション周期が3,600フレームを超える状態
- 合成結果にパレット外色または半透明画素がある状態

異なる起点のオブジェクト領域重複はエラーにしない。
`passable_override` の下に通行不可オブジェクトがない配置は、意図しない通行可セルを
見つけやすくするため警告する。

問題一覧にエラーがある間も、地面とオブジェクトのチップ表示は消さない。表示に影響しない
拠点・actor・トリガーなどの中間エラーでは、検証対象外の表示部分だけを再解決する。表示自体を
解決できない中間状態では、直前に解決できたプレビューを保持する。保存は従来どおり禁止する。

## 起動と非対話生成

```sh
npm run tools:editor
npm run tools:editor -- --map field_01 --tileset dungeon --profile dungeon
npm run tools:editor -- --editor tileset --tileset dungeon
npm run tools:editor -- --editor event --namespace common
npm run maps:validate
npm run maps:build
```

`tools:mapchip-metadata`、`tools:map-editor`、`tools:event-editor` は、最初に表示する画面だけを
指定する互換入口として残す。どの入口から起動しても、同じ認証セッションのヘッダーから
マップチップ、マップ、イベントの3画面へ切り替えられる。各画面の編集中状態と保存・検証処理は
独立させ、画面切り替え時に未保存変更があればブラウザの離脱確認を表示する。

新規マップは既定で32×24セルとする。`--width`、`--height` で初期寸法を変更できる。
幅は16セル、高さは15セルより小さくできない。既存マップでは制作用JSONに保存された
タイルセット、profile、寸法を使用する。ヘッダーから既存マップの切り替えと新規マップ作成を行い、
新規作成時は同じprofileの既存タイルセットを選択する。

既存マップに紐づくマップチップを変更する場合は、同じprofileの別タイルセットを選択する。
変更時は寸法とマップID、profileを維持し、全セルを新しいベース地面へ戻す。オブジェクト、拠点、
到着地点、actor、イベントトリガーはすべてクリアする。変更結果は未保存状態として表示し、通常の
「保存・生成」で確定する。他マップから参照されていた到着地点などが消える場合は問題一覧へ表示し、
参照を修復するまで保存できない。

マップは確認後に削除でき、制作用JSONとゲーム用JSON・BINを同時に削除する。ただし、他マップの
移動先またはテレポート到着地点から参照されているマップと、ゲームの必須マップである `worldmap` は
削除できない。

## 受け入れ条件

- メタデータ設定ツールで定義した地面を選び、ドラッグで塗布できる。
- 地面だけを表示して配置要素に隠れたセルを確認・編集できる。
- 矩形のプレビュー範囲を選択中の地面で一括塗布し、1回のUndoで戻せる。
- 同じ起動プロセス内でマップチップメタデータを編集し、マップ画面へ戻って再読込できる。
- 8方向境界、ランダム候補、アニメーションがキャンバスへ反映される。
- 定義済みオブジェクトを配置でき、同一起点は禁止しつつ異なる起点で重ねられる。
- オブジェクトの配置前に、定義サイズ全体の配置先を破線枠で確認できる。
- 配置済みオブジェクトを右クリックで選択し、右ドラッグまたは選択後の左ドラッグで移動できる。
- 単体選択した拠点・移動口、到着地点、actor、単独トリガーの表示セルから右ドラッグすると、
  新しい範囲選択を開始せず選択対象を移動できる。
- 右ドラッグの矩形でオブジェクト、拠点、到着地点、actor、単独トリガーを横断して複数選択し、
  相対位置を保って一括移動・削除できる。
- 範囲選択をEscで解除でき、配置データとUndo履歴は変化しない。
- 重なったオブジェクトは下端Y座標が大きいものが手前に表示される。
- 前面パーツは通常オブジェクトより手前に表示され、通行可上書きを最終通行判定へ反映できる。
- キャラクター前景はプレイヤーやactorより手前に表示され、通行可能な屋根などを表現できる。
- オブジェクトまたはセルへ拠点を配置し、複数入口と単一の移動先を編集できる。
- town／dungeonでは名称なしの移動口を配置し、ワールドマップ側の到着地点を移動先にできる。
- マップ内の到着地点、向き、テレポート対象拠点を編集できる。
- 宝箱以外のactorを配置・選択すると `touch` ・ `interact` トリガーが自動設定され、
  actor編集欄で起動イベントを選択できる。
- 人物actorの浮遊を配置ごとにON／OFFでき、選択中プレビューとキャンバスで本編と同じ
  待機パターンと開始位相を、Y座標をずらさず確認できる。画像元の変更では設定を維持し、
  prop／treasureには浮遊設定を保存しない。
- 宝箱actorへGoldまたはアイテムの中身を設定して保存できる。
- cell／objectアンカーの `step` ・ `touch` トリガーを配置・編集でき、
  `interact` は単独選択できない。
- 同じ起動プロセス内でイベントエディタへ切り替え、選択トリガーのイベント本文を直接開ける。
- マップ寸法を左右・上下の任意の方向へ拡張、縮小できる。
- 地面とオブジェクトを合成した通行不可セルを確認できる。
- 保存後に同じ制作用マップを再読込できる。
- 同じprofileのタイルセットへ変更し、寸法を維持したままマップ内容を初期化できる。
- 未参照の通常マップを削除でき、参照中のマップと `worldmap` は削除できない。
- 同じ入力とseedから同じゲーム用JSON・アトラスを再生成できる。
- マップ設定でゲーム用BGMを選択でき、保存後のマップ移動で選択したBGMへ切り替わる。
- ゲーム用データに境界ルール、候補重み、オブジェクト定義、拠点アンカーを残さない。
