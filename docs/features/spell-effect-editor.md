# 呪文エフェクト設定ツール

## 目的

通常の呪文エフェクトについて、呪文ごとに画像パターン、再生するパターン数と速度、対象からの
位置調整、フラッシュ色、効果音を設定し、実際のゲーム用画像とPyxel音声で確認する
ローカル制作ツールとする。

ツール自身をPyxel製とし、ZERO本編と同じ60fps、本番パレット、生成済み画像、
`assets.pyxres` 内のSoundを使用する。ブラウザ上の近似表示や別の音声再生経路は使用しない。

## 対象範囲

初期版で扱うのは、次の処理だけで完結する通常エフェクトである。

1. 対象のエフェクト基準点へ32×32pxまたは64×64pxの画像を重ねる。
2. 横方向に並ぶ画像パターンを左から順にアニメーションする。
3. アニメーション中の対象スプライトだけを指定色へフラッシュする。
4. エフェクト開始時に効果音を1回再生する。

エインシェント、パニッシュ、テレポートのように、複数画像の移動、画面全体の変形、
背景演出、専用タイムラインを必要とする特殊エフェクトは扱わない。未設定の呪文は一覧へ
表示するが、通常エフェクトの設定を強制しない。特殊エフェクトの形式は、戦闘実装時に
通常エフェクトと別の`kind`として追加する。

ダメージ数値、命中・失敗、弱点・耐性表示、死亡演出、複数対象への開始時間差は本ツールの
対象外とする。これらはBattleSceneが呪文エフェクトの前後へ合成する。

## 時間表現と速度

DA2の通常エフェクトは30fpsで、1つの画像パターンを2ゲームフレーム表示していた。
ZEROでは同じ時間感覚を保つため、1つの画像パターンを60fpsで4ゲームフレーム表示する。
この4ゲームフレームを新規設定の初期値とし、実際の値は呪文ごとに変更できるようにする。

仕様上の用語を次のように区別する。

- `frame_count`: 左から使用する画像パターンの個数
- `frames_per_pattern`: 1つの画像パターンを表示し続けるゲームフレーム数
- ゲームフレーム: Pyxelの`update()`が1回進む1/60秒
- エフェクト時間: `frame_count * frames_per_pattern`ゲームフレーム

たとえば`frame_count=5`、`frames_per_pattern=4`なら、画像パターン0〜4を各4ゲームフレーム
表示し、全体は20ゲームフレーム（約0.333秒）となる。`frames_per_pattern`は1〜60とし、
1/60秒から1秒までを1ゲームフレーム単位で設定できる。

DA2のサイレンス、ポイズンガス、ヘヴンゲートにあった「最後の画像を表示した後に
ディザで消す」設定は初期版には含めない。通常エフェクトとして必要になった場合は、
単純な`frame_count`の意味を変えず、別フィールド`fade_out_frames`を追加する。

## 正本と生成物

呪文の効果計算と表示名の正本である`content/data/spells.json`へ、描画・音声設定を
追加しない。`spells.json`はGoogle Sheetsとの同期対象であり、本ツール固有の入れ子構造を
混在させると双方向同期とレビューが難しくなるためである。

リソースの責務は次のように分ける。

| パス | 責務 |
| --- | --- |
| `content/data/spells.json` | 呪文キー、効果、対象範囲など既存の呪文マスター |
| `content/effects/spells.json` | 本ツールが編集する呪文エフェクト設定の正本。Sheets同期対象外 |
| `content/images/effects/spells32.gif` | 32×32pxパターンの画像正本 |
| `content/images/effects/spells64.gif` | 64×64pxパターンの画像正本 |
| `app/images/manifest.json`、`graphics.bin` | 本番パレットへ変換した生成済み画像 |
| `app/effects/spells.json` | 検証・索引化したゲーム用エフェクト設定。Git管理対象外 |
| `app/audio/catalog.json` | 安定したSE IDからPyxelのchannelとSound番号への対応 |

`content/effects/spells.json`はマップやイベントと同様に共有コンテンツではあるが、
Google Sheetsへ送受信しない。ツール保存時と非対話ビルド時に、同じPyxel非依存の
検証・コンパイル処理から`app/effects/spells.json`を生成する。

## 保存形式

現在の形式は次の構造とする。

```json
{
  "format_version": 2,
  "effects": [
    {
      "spell_key": "FIRE1",
      "kind": "target_sprite",
      "image_id": "effects/spells64",
      "row": 0,
      "frame_count": 5,
      "frames_per_pattern": 4,
      "offset": {
        "ally": [0, -8],
        "enemy": [0, 4]
      },
      "flash_color": 30,
      "se_id": "spell_fire1"
    }
  ]
}
```

各フィールドの意味は次のとおり。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `spell_key` | string | `spells.json`の安定キーである`name_en` |
| `kind` | string | 初期版では`target_sprite`のみ |
| `image_id` | string | `effects/spells32`または`effects/spells64` |
| `row` | integer | 画像上端を0とする縦方向のパターン行 |
| `frame_count` | integer | 選択行の左端から再生する画像パターン数 |
| `frames_per_pattern` | integer | 1パターンを表示するゲームフレーム数。1〜60 |
| `offset` | object | `ally`と`enemy`それぞれのエフェクト基準点からのX、Y相対位置 |
| `flash_color` | integerまたはnull | フラッシュ先となるPyxel基準パレット番号。nullはフラッシュなし |
| `se_id` | stringまたはnull | `app/audio/catalog.json`の安定SE ID。nullは無音 |

セル寸法は`image_id`から一意に決まるため保存しない。画像の開始列も初期版では常に0とし、
保存しない。途中の列から始める要件が生じた場合だけ`start_column`を追加する。

`offset.ally`と`offset.enemy`はそれぞれ-128〜128pxを許可する。ツールでは1px単位で変更し、
エフェクトの左上ではなく、画像中心を「対象のエフェクト基準点 + 対象側のoffset」へ合わせる。
旧形式`format_version=1`の`offset: [x, y]`は読み込み時に味方・敵の両方へ引き継ぎ、次回保存時に
現在形式へ更新する。

エフェクト未設定は空のダミーレコードではなく、その`spell_key`のレコードが存在しない状態で
表す。これにより特殊呪文と制作途中の呪文を、不正な通常エフェクトとして保存せずに済む。

## 画像シートの解釈

`effects/spells32`は32px、`effects/spells64`は64pxを1セルとする。行のY座標は
`row * cell_size`、パターン`n`のX座標は`n * cell_size`である。選択した
`frame_count`より右側のセルは再生しない。

現行素材には制作注記の文字や赤い印が同じGIF内の右側に含まれ、`spells32.gif`の幅は
250pxで32の倍数ではない。初期版は次の規則で既存素材をそのまま扱う。

- 横幅に完全に収まる左側のセルだけを選択候補とする。
- 末尾の不完全な領域は表示・再生対象にしない。
- 選択した`frame_count`内に注記が入らないことは、画像ストリップとライブプレビューで
  制作者が確認する。
- 完全透過のセルを選択範囲に含めた場合は警告するが、意図的な空白フレームの可能性が
  あるため保存は妨げない。

素材を画像パターンだけの矩形atlasへ整理する場合も、保存データは同じ`image_id`、`row`、
`frame_count`で表現できる。ただし行番号を変える素材整理は、既存設定の移行と同時に行う。

## 対象の基準点と描画

BattleSceneまたは戦闘用Rendererは、描画中の各対象についてエフェクト基準点を返す。
基準点は表示名や種族ではなく、実際に描画したスプライト矩形から導出する。

初期基準はスプライト矩形の中央とする。キャラクターとモンスターでは画像内の立ち位置や寸法が
異なるため、呪文設定は味方用の`offset.ally`と敵用の`offset.enemy`を個別に持つ。戦闘側は対象が
味方か敵かを`SpellEffectPlayer`へ明示し、対象側の補正を選ぶ。

描画順は「背景、対象スプライト、呪文エフェクト、Window・操作案内」とする。
エフェクト画像の透過色にはZERO共通のパレット番号1を使う。画面外へはみ出した部分は
Pyxelの通常描画どおりクリップし、設定値を暗黙に補正しない。

## フラッシュ

`flash_color`がnullでない場合は、エフェクト開始から終了まで対象スプライトだけに
`PaletteShifter`の名前付き変換を適用する。エフェクト画像、背景、他の対象、Windowには
適用しない。

DA2と同じく、通常色から指定色へ寄って通常色へ戻る1周期の混色とする。経過率を`t`、
0〜360度の位相を`theta = 360 * t`としたとき、元色の比率を
`0.6 + cos(theta) * 0.4`とする。開始時と終了時は通常色、中央で指定色を80%混合した色になる。
設定値はRGBではなく基準パレット番号として保存し、現在の`assets.pyxpal`からRGBを解決する。

透過色であるパレット番号1は選択不可とする。フラッシュなしは色0ではなくnullで表し、
黒へのフラッシュも選択できる。

色はカラーピッカーから選択できる。0番の黒は独立して配置し、透過色1を除く2〜61番は
`2–5`、`6–9`、`10–13`のような4色単位の行に分ける。各行は同系色の暗色から明色の順に
左から右へ並べ、15組を8行と7行の2列に配置する。現在選択中の色には枠を表示し、
`NONE`でフラッシュなしへ戻せる。

## 効果音

保存データではPyxelのSound番号を直接持たず、`app/audio/catalog.json`の`se_id`を参照する。
カタログがchannelとSound番号を所有し、本ツールと本編はいずれも`play_se()`を使って再生する。
これにより`assets.pyxres`内のSound配置を変更しても、全呪文設定を書き換えずに済む。

効果音選択欄には`se_id`、channel、Sound番号を表示する。選択中の音はエフェクト全体を
再生せず、試聴操作だけでも鳴らせる。初期版はSoundのnotes、tones、volumes、speed自体を
編集せず、それらはPyxel Editorで管理する。

未登録のSoundは、本ツールの登録画面で安定した`se_id`、Sound番号、再生channelを指定する。
登録前に`assets.pyxres`のSoundを直接試聴でき、登録すると選択中の呪文へその`se_id`を設定する。
`se_id`は英小文字で始まる英小文字・数字・アンダースコアとし、既存IDとの重複を許可しない。
Sound番号は現在のPyxel Sound配列内、channelはBGM専用channel 2以外から選択する。

## 画面構成

Pyxelの論理画面を512×320px、表示倍率を2倍、fpsを60とする。上部左半分は本編と同じ
256×240pxの戦闘プレビュー、上部右半分は設定UIとする。下部80pxは画面幅全体を画像ストリップに
使用する。素材は拡大せず、プレビュー内では本番と同じ1pxを1pxとして描画する。

```text
┌──────────────────────────────┬───────────┬───────────────────┐
│                              │ 呪文一覧  │ 選択中の設定      │
│ 256×240 戦闘プレビュー       │           │ 画像 / 位置       │
│                              │           │ フラッシュ / SE   │
│                              │           │ SE登録             │
├──────────────────────────────┴───────────┴───────────────────┤
│ 選択行の画像ストリップ（512×80）                            │
└──────────────────────────────────────────────────────────────┘
0                            255 256       351 352             511
```

### 呪文一覧

- `spells.json`のうち`on_battle=1`のレコードをマスター順で表示する。
- ミスティック、セイクリッド、ネザー、アイテム効果で絞り込める。
- 表示名と同時に安定キーを確認できる。
- 設定済み、未設定、検証警告あり、検証エラーありをアイコンと色で区別する。
- 呪文を切り替えても編集中の値をメモリ上に保持する。保存前の変更が消えないようにする。

### 設定欄

設定欄では次を編集する。

- 画像ID: 32pxまたは64px
- 行番号: 前後操作で選択
- 使用パターン数: 1から横幅に収まる完全セル数まで
- パターン速度: 1パターンあたり1〜60ゲームフレーム。新規設定は4
- 味方用／敵用のX、Yオフセット: プレビュー対象側を1px単位で編集
- フラッシュ色: なし、または全61色を系統・明度順に並べたカラーピッカーから選択
- 効果音: なし、またはSEカタログのID

選択行は横長の画像ストリップとして表示し、各セルの境界、0始まりの番号、
`frame_count`に含まれる範囲を表示する。設定欄に収まらない部分は横スクロールする。
64px画像は一度に8セルまで表示し、9セル目がある行だけ横スクロールする。速度欄には
ゲームフレーム数に加えて、エフェクト全体の秒数も表示する。

### プレビュー

プレビューは生成済みの本番画像から、実際のキャラクター戦闘スプライトまたはモンスター画像を
表示する。最低限、次の確認操作を持つ。

- 味方／敵ターゲットの切り替え
- `characters.json`のキャラクターと`monsters.json`のモンスターの切り替え
- 1回再生、ループ再生、停止、先頭へ戻す
- 一時停止中の1ゲームフレーム送り
- エフェクト基準点、画像矩形、現在の画像パターン番号を表示するデバッグ表示

プレビュー対象、ループ状態、デバッグ表示はツール固有状態であり保存しない。味方／敵を切り替えると
設定欄もその対象側のOFFSETへ切り替わり、両方の値は設定欄下部で常に確認できる。同じ陣営内の
対象画像を切り替えてもOFFSETは変わらず、小型・大型モンスターや各キャラクターで確認できる。

設定値を変更した場合は、停止中なら現在フレームを再描画し、再生中なら先頭から再開する。
効果音は明示的に再生を開始したときだけ鳴らし、行番号や色を変更するたびには鳴らさない。

## 再生状態

本編と共有する`SpellEffectPlayer`相当の状態は、少なくとも次を所有する。

- 不変のエフェクト定義
- 対象のエフェクト基準点
- 対象が味方か敵か
- 0始まりの経過ゲームフレーム
- 開始音を再生済みか
- 完了済みか

`update()`が経過フレーム、画像パターン、完了状態を進め、`draw()`は状態を変更しない。
開始音は経過0の開始処理で1回だけ再生する。ツールの一時停止とループ再開は
`SpellEffectPlayer`の外側にあるプレビュー制御が担当し、本編のプレイヤーへツール固有操作を
持ち込まない。

## 保存と競合

- 自動保存は行わない。
- 保存前に全レコードを検証し、エラーがある場合はファイルを書き換えない。
- 正本とゲーム用生成物は、一時ファイルへ完全な内容を出力してから置き換える。
- 起動時に正本のハッシュを保持し、外部変更を検出した場合は上書きを拒否して再読込を促す。
- 呪文の切り替えやプレビュー対象の切り替えでは、未保存変更を破棄しない。
- 終了時に未保存変更があれば、保存、破棄、終了取消を選択させる。
- JSONはマスター順で出力し、無関係な並べ替えや再整形を避ける。

保存後は`content/effects/spells.json`と`app/effects/spells.json`を更新する。新しいSEを登録した
場合は`app/audio/catalog.json`も同時に更新する。`content/data/spells.json`、画像GIF、
`assets.pyxres`は変更しない。

## 検証規則

Pyxel非依存の検証・コンパイル処理で次を確認する。

- `format_version`が対応値である。
- `effects`がオブジェクト配列である。
- `spell_key`が重複せず、`spells.json`の既存`name_en`を参照する。
- `kind`が`target_sprite`である。
- `image_id`が対応する2画像のいずれかである。
- `row`と各使用セルが画像寸法内へ完全に収まる。
- `frame_count`が1以上である。
- `frames_per_pattern`が1〜60の整数である。
- `offset.ally`と`offset.enemy`がそれぞれ2個の整数で、各値が-128〜128である。
- `flash_color`がnull、または現在の基準パレット範囲内で、透過色1ではない。
- `se_id`がnull、またはSEカタログに存在する。

次は警告とし、保存を許可する。

- `on_battle=0`の呪文へエフェクトが設定されている。
- 選択範囲に完全透過セルがある。
- `on_battle=1`の呪文に設定がない。
- 32pxまたは64px画像が対象スプライトから大きくはみ出す。

## コード配置

責務分割は次のとおりとする。

```text
app/
├── spell_effect.py                  # 定義、形式解釈、Pyxel非依存の再生時刻計算
├── effects/spells.json              # 生成済みゲーム用設定
└── rendering/spell_effect.py        # Pyxel画像、対象フラッシュ、描画

scripts/spell_effect_pipeline/
└── model.py                         # 制作用形式の読込・検証、索引生成、原子的保存

tools/spell_effect_editor/
├── __main__.py                      # Pyxel初期化と依存の組み立て
├── app.py                           # 選択、編集中状態、保存、プレビュー制御
└── model.py                         # 下書き、診断、競合検出、保存
```

`tools/spell_effect_editor`は`Game`やBattleScene全体を生成せず、本番用の呪文loader、
`ImageResources`、`PaletteShifter`、`play_se()`、呪文エフェクトRendererへ必要なデータだけを
渡す。ゲーム本体から`tools/`を参照しない。

## 起動とビルド

リポジトリルートから次で起動する。

```sh
npm run spell-effect-editor
```

起動前に`content/images`から`app/images`を生成し、素材変更がプレビューへ反映された状態にする。
非対話で設定だけを検証・生成する入口も用意する。

```sh
npm run spell-effects:validate
npm run spell-effects:build
```

ゲーム本体は`content/effects`を直接読まず、`app/effects/spells.json`だけを読む。

## 受け入れ条件

- Pyxelの512×320px・60fps画面として起動し、左上に本番寸法の戦闘プレビューを表示する。
- 全戦闘用呪文を安定キーで選択し、設定済みと未設定を区別できる。
- 32px／64px画像、行、使用パターン数、パターン速度、味方・敵それぞれのX/Y位置、フラッシュ色、SEを設定できる。
- フラッシュ色は0番を独立表示し、2〜61番を4色単位の暗色〜明色として一覧選択できる。
- パターン速度を1〜60ゲームフレームの範囲で呪文ごとに保存し、60fpsの実時間で確認できる。
- 実際のキャラクター戦闘画像と複数サイズのモンスター画像で位置とフラッシュを確認できる。
- エフェクト開始時に`assets.pyxres`の選択SEが1回だけ鳴る。
- 未登録Soundをキー、Sound番号、channelとともに登録・試聴し、ゲーム用SEカタログへ保存できる。
- 一時停止、1ゲームフレーム送り、1回再生、ループ再生ができる。
- 不正な参照、範囲外セル、重複呪文キーを保存しない。
- 保存した正本を再起動時に復元し、同じ設定からゲーム用データを再生成できる。
- 外部で変更された正本を警告なく上書きしない。
- 未設定の特殊呪文が存在しても、他の通常エフェクトを編集・保存できる。

## 確定した制作方針

- 再生速度は`frames_per_pattern`として呪文ごとに設定し、DA2相当の4を初期値とする。
- 現行GIFの注記と不完全幅は残し、左側から完全に収まるセルだけを選択候補とする。
- 効果音はPyxel Sound番号を直接保存せず、SEカタログの安定した`se_id`で保存する。
- 未登録Soundの`se_id`と番号は本ツールからSEカタログへ追加できる。
- 位置調整は`offset.ally`と`offset.enemy`に分け、プレビュー対象側の値を編集する。
