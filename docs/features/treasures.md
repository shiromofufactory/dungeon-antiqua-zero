# 宝箱仕様

## 位置付け

本書は、フィールドに配置する宝箱の制作データ、開封、報酬、演出、保存規則を定める。
actorとイベントトリガーの共通仕様は [`events.md`](./events.md)、フィールド入力は
[`field.md`](./field.md)、保存形式は [`save-data.md`](./save-data.md) を参照する。

宝箱はマップ上に複数配置され、通行を妨げるactorの一種として扱う。一方、通常イベントへ
変換せず、宝箱固有の画像、報酬処理、開封状態を専用Systemが扱う。

## 制作用データ

制作用マップ形式version 6で `actors[].kind` に `treasure` を追加する。actorの `id` は
マップ内で安定した宝箱IDを兼ねる。位置変更で開封状態を失わないよう、座標を識別子に使わない。

Goldとアイテムの定義例を示す。

```json
{
  "id": "entrance_gold",
  "position": [12, 8],
  "kind": "treasure",
  "contents": {
    "type": "gold",
    "amount": 500
  }
}
```

```json
{
  "id": "entrance_potion",
  "position": [14, 8],
  "kind": "treasure",
  "contents": {
    "type": "item",
    "item_key": "POTION"
  }
}
```

- `contents.type` は現在 `gold` または `item` とする。
- `gold.amount` は1〜999999の整数とする。
- `item.item_key` は `content/data/items.json` に存在する安定キーとし、取得数は1個とする。
- 種別ごとの属性だけを指定し、Goldへ `item_key`、アイテムへ `amount` を混在させない。
- 宝箱は専用画像を使うため `sprite_index` と `facing` を指定しない。
- 宝箱にはactorアンカーのイベントトリガーを作成しない。
- 将来「ランダム」「罠」などを追加する場合は、仕様確定後に `contents.type` の新しい判別値と
  専用属性を追加する。現在の2種類へ将来用の省略可能属性は先行追加しない。

## 入力と開封

- 停止中に宝箱のセルを向いて決定するか、宝箱のセルへ進もうとして接触すると開封を試みる。
- 開封を開始する時、partyの先頭キャラクターを宝箱のある方向へ向ける。
- 宝箱の判定は同じセルの通常イベントより先に行い、1回の入力で複数の処理を起動しない。
- 開封中はメッセージを最上位Overlayとして表示し、フィールド移動と通常イベント入力を止める。
- 開封済みの宝箱へ決定または接触しても、メッセージ、音、再アニメーションを発生させない。
  接触時は通常の固定actorと同様にそのセルへ進入しない。

## 報酬と所有上限

- Goldは `SaveData.gold` へ加算し、上限999999を超える場合は一切加算しない。
- アイテムは `InventorySystem` で1個取得する。消耗品は同一品99個、装備品は全キャラクターの
  装備中個数を含めて同一品9個の所有上限を使う。
- 上限内なら報酬を付与した後、`(map_id, actor.id)` を開封済みとして記録する。
- 上限超過時は報酬も開封済み状態も変更しない。このため、所持数を減らした後に再試行できる。
- 報酬付与と開封済み記録は一体として扱い、一方だけ成功した状態を作らない。

## メッセージ

表示文言の正本は `content/data/texts.json` とし、次のキーを使う。

| 状態 | 文言キー | 値 |
|---|---|---|
| Gold発見 | `treasure.found_gold` | `AMOUNT` に金額を渡す |
| アイテム発見 | `treasure.found_item` | `ITEM` に現在言語のアイテム名を渡す |
| 所有上限超過 | `treasure.capacity_exceeded` | 発見文言の2行目へ追加する |

現在は日本語だけを登録する。英語・簡体字中国語では既存の言語フォールバック規則により
日本語を表示する。

## 画像とアニメーション

- 正本画像は `content/images/actors/treasure.png`、画像IDは `actors/treasure` とする。
- 画像寸法は48×16pxとし、16×16pxの3コマを横並びにする。
- 閉じた状態は元画像座標 `(0, 0)`、途中は `(16, 0)`、開いた状態は `(32, 0)` とする。
- 各コマの表示時間は6フレームとする。閉じた宝箱は入力前から第1コマを表示しているため、
  開封開始後は第2コマを6フレーム表示して第3コマへ移る。
- 取得成功は `閉 → 途中 → 開` と遷移し、開いた状態を維持する。
- 取得成功時はDA2と同じPyxel Sound 25を、安定SE ID `treasure_open` からチャンネル0で再生する。
  所有上限超過と開封済み宝箱への操作では再生しない。
- 上限超過はメッセージ表示中に `閉 → 途中 → 開` と遷移して開いた状態を維持する。
  メッセージを閉じた後に `開 → 途中 → 閉` の閉じる演出を開始し、途中コマを6フレーム表示して
  閉じた状態を維持する。
- マップ再読込時、開封済みの宝箱は最初から開いたコマで表示する。

## 状態の所有者

- `MapActor.contents` は検証済みの宝箱定義を保持する。
- `TreasureSystem` は所有上限の確認、報酬付与、`SaveData.opened_treasures` の更新を担当する。
- `FieldActors` は表示コマと演出タイマーだけを保持する。演出途中は保存しない。
- `Game` はフィールド入力、System呼び出し、メッセージOverlayを接続する。
- Rendererは現在の表示コマを描画し、開封判定や状態変更を行わない。

## マップエディタ

- actor種別で「宝箱」を選ぶとキャンバス上では固定の宝箱画像を表示する。actor編集欄には
  画像プレビュー、画像選択、向きのUIを表示しない。
- 中身の種別としてGold／アイテムを選び、Goldは金額、アイテムはマスターデータから
  アイテムキーを選択する。
- 宝箱ではイベント選択・追加UIを表示せず、保存データにもactorトリガーを生成しない。
- 種別を宝箱から通常actorへ戻した場合は `contents` を削除し、通常actorの必須属性と
  actorトリガーを設定する。

## 受け入れ条件

- Goldとアイテムの宝箱をマップエディタとJSONのどちらからでも定義・検証・生成できる。
- 決定と接触のどちらでも、報酬を1回だけ取得して指定メッセージと開封演出を表示できる。
- 所有上限を超える場合は2行目を表示し、報酬と開封状態を変更せず、宝箱を閉じた表示へ戻せる。
- 開封済み状態を保存・復元し、復元後は開いた画像を表示して再操作へ反応しない。
- 宝箱を通常イベントのactorトリガーや `move_actor` の対象にできない。
