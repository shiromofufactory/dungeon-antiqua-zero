# セーブデータ形式仕様

## 位置付け

本書はDungeon Antiqua ZEROのセーブデータ形式、保存対象、復元時の検証、バージョン移行方針を
定める。ゲーム進行状態の所有者と保存処理の配置は
[`program-architecture.md`](../program-architecture.md)、拠点IDと訪問済み状態は
[`world-sites.md`](./world-sites.md)を参照する。

セーブデータはUTF-8のJSONオブジェクトとする。識別子には表示名や翻訳後の文字列ではなく、
対応するマスターデータまたはマップデータの安定キーを保存する。

現在のゲームではスロット1〜8を
`~/.config/.pyxel/dungeon-antiqua-zero/save{slot}.json` に保存する。書き込み途中のデータを
正規スロットとして残さないよう、同じディレクトリの一時ファイルを書き終えてから置き換える。
起動直後のロード画面では、使用済みスロットからゲーム状態を検証・復元する。
一覧用メタデータには `format_version`、`saved_at` と
`party.active_character_keys` の全要素を使う。セーブ画面ではロード処理を経ずに、その先頭5人を
保存時の戦闘参加メンバーとしてパーティ順で顔表示する。6人目の控えは一覧へ表示しない。
ロード画面の構成と削除操作は [`start-load.md`](./start-load.md) を参照する。

## バージョン1の方針

- `format_version` は整数 `1` とする。
- 現在パーティだけでなく、一度加入状態を生成した離脱中キャラクターの状態も保存する。
- 世界進行の入力としてイベントフラグと戦闘回数を保存する。
- 魔力減衰率、敵強化段階、設備停止状態など、両者から導出できる結果は保存しない。
- 現在位置はマップID、セル座標、向きを保存する。
- 取得済み宝箱、訪問済み拠点、アイテム図鑑、モンスター図鑑、ログを保存する。
- オートマッピングの踏破状態は保存しない。
- 重要アイテム専用の所持一覧は設けない。重要アイテムによる進行状態はイベントフラグで表す。
- 保存時点では戦闘、イベントコマンド列、画面遷移、セル間の歩行が進行していないものとする。
- ロード後は保存地点のフィールドを起点とし、保存時に開いていたOverlayは復元しない。

順序に意味がない配列と辞書キーを安定ソートしてよい。

## トップレベル

| フィールド | 型 | 必須 | 内容 |
|---|---|---|---|
| `format_version` | integer | 必須 | セーブ形式のバージョン。v1では `1` |
| `saved_at` | string | 必須 | ISO 8601形式の保存日時。ゲーム進行の判定には使わない |
| `progress` | object | 必須 | パーティ共有の数値進行状態 |
| `location` | object | 必須 | ロード後に再開するフィールド位置 |
| `party` | object | 必須 | 現在パーティと全キャラクター状態 |
| `inventory` | object | 必須 | 未装備品の数量とアイテム図鑑 |
| `event_flags` | string[] | 必須 | 成立済み・選択済みイベント状態 |
| `visited_site_ids` | string[] | 必須 | テレポート候補に使う訪問済み拠点ID |
| `opened_treasures` | object[] | 必須 | 取得済み宝箱のマップIDと宝箱ID |
| `monster_records` | object | 必須 | モンスターごとの図鑑開示状態 |
| `logs` | object[] | 必須 | ロード後も参照できるメッセージログ |

すべての必須コレクションは、要素がない場合も省略せず、空の配列または空のオブジェクトとして
保存する。

## 共有進行状態

`progress` は次のフィールドを持つ。

| フィールド | 型・範囲 | 内容 |
|---|---|---|
| `gold` | integer、0〜999999 | 所持金 |
| `experience` | 0以上のinteger | パーティ全体で共有する経験値 |
| `battle_count` | 0以上のinteger | 世界進行の判定に使う完了済み戦闘回数 |
| `difficulty` | `normal` / `hard` | 難易度の安定値 |
| `play_time_frames` | 0以上のinteger | 60fps基準のプレイ時間 |

敵強化段階、魔力減衰率、種族ごとの補正、設備の稼働状態は保存しない。
`WorldProgression` はロード後も `event_flags` と `battle_count` から毎回これらを導出する。

## 現在位置

`location` は次のフィールドを持つ。

| フィールド | 型・値 | 内容 |
|---|---|---|
| `map_id` | string | 生成済みマップの安定ID |
| `x` | 0以上のinteger | セル単位のX座標 |
| `y` | 0以上のinteger | セル単位のY座標 |
| `facing` | `up` / `right` / `down` / `left` | 再開時の向き |

保存位置はセル境界上に限定し、ピクセル単位の移動オフセット、移動中の方向、カメラ座標は
保存しない。復元時はマップの存在と座標範囲を検証する。マップ編集によって保存セルが通行不能へ
変わっていてもロードは拒否せず、その座標から再開する。保存時にメニューを開いていた場合も、
ロード後はこの位置のフィールドから再開する。

## パーティとキャラクター

### 現在パーティ

`party.active_character_keys` は現在同行しているキャラクターの安定キーを表示順に保持する。
先頭5名が戦闘参加、6人目が控えとなるため、この配列だけはソートしない。

- 要素数は1〜6とする。
- 重複を許可しない。
- 各キーは `character_states` に存在し、`characters.json` のレコードへ解決できなければならない。
- フィオラを必ず含める。
- 現在パーティに1人以上の前列を必要とし、6人目の控えは前列とする。

`party.character_states` はキャラクター安定キーをプロパティ名とし、一度加入状態を生成した
全キャラクターを保持する。現在離脱中のキャラクターも削除しない。レコードが存在しないことは、
そのプレイデータで一度も加入状態を生成していないことを表す。

### キャラクター状態

各キャラクター状態は次を持つ。

| フィールド | 型・値 | 内容 |
|---|---|---|
| `internal_level` | integer、1〜99 | 現在の内部LV |
| `hp` | integer、0〜`max_hp` | 現在HP |
| `max_hp` | integer、1〜999 | 成長を反映した最大HP |
| `mp` | integer、0〜`max_mp` | 現在MP |
| `max_mp` | integer、0〜255 | 成長を反映した最大MP |
| `formation_row` | `FRONT` / `BACK` | 前列・後列 |
| `poisoned` | boolean | フィールドへ持ち越す毒状態 |
| `paralyzed` | boolean | フィールドへ持ち越す麻痺状態 |
| `ability_bonuses` | object | 永続成長アイテムによる能力上昇量 |
| `skill_keys` | string[] | 現在習得しているスキルの安定キー |
| `event_spell_keys` | string[] | 熟練度から導出できないイベント習得呪文の安定キー |
| `equipment` | object | 各装備スロットのアイテムキーまたは `null` |
| `proficiencies` | object | 武器・呪文種別ごとのLVと熟練度 |

`ability_bonuses` は `strength`、`agility`、`magic` の0以上の整数を必須とする。各能力について、
キャラクター正本の基礎値と保存した永続上昇量の合計は32以下でなければならない。装備補正は
アイテム正本と現在装備から導出するため、ここへ含めない。

`equipment` は `RIGHT`、`LEFT`、`HEAD`、`BODY`、`ARM` の5プロパティを必須とする。
装備品は `inventory.quantities` に重複して数えない。復元後は未装備品と、離脱中を含む
全キャラクターの装備品を合算し、アイテムごとの所持上限を検証する。

`proficiencies` は `ProficiencyKind` の全13キーを必須とし、各値を次のオブジェクトとする。

```json
{
  "level": 1,
  "progress": 25
}
```

- `level` は0〜9、`progress` は0〜99とする。
- 実際のLV上限は `characters.json` の適性0〜2から検証する。
- 適性は変更されないマスターデータであり、セーブデータへ複製しない。
- LV1以上の通常呪文の習得状態は呪文熟練度から導出し、個別には保存しない。
- `event_spell_keys` にはLV0のイベント習得呪文だけを保存する。

睡眠、混乱、沈黙、スタン、戦闘中のバフ、行動待ち時間、選択済みコマンドなど、戦闘終了時に
破棄される状態は保存しない。

## 所持品とアイテム図鑑

`inventory.quantities` はアイテム安定キーから未装備の所持数への辞書とする。

- 所持数は1以上の整数とし、0個のキーは書き出さない。
- 消耗品は99個、装備品は装備中を含めて9個を上限とする。
- 未知のアイテムキーを許可しない。

`inventory.recorded_item_keys` はアイテム図鑑で開示済みのアイテムキーを、重複のない配列として
保持する。現在所持している品と、全キャラクターが装備している品はこの配列にも含まれていなければ
ならない。所持数が0になっても図鑑記録は削除しない。

重要アイテム専用の配列は設けない。重要アイテムの取得、使用、喪失によってイベント条件が
変化する場合は、それぞれに対応する `event_flags` を正本とする。

## イベント、訪問済み拠点、宝箱

`event_flags` と `visited_site_ids` は、重複のない文字列配列とする。`event_flags` の各値は
`content/events/flags.json` と同じ形式のグローバルフラグID、`visited_site_ids` は非空の安定ID
とする。旧セーブに残る未宣言フラグは別の意味へ読み替えず、そのまま保持する。どちらも集合として扱い、書き出し時は安定ソートする。イベントフラグはイベント条件と結果、訪問済み拠点IDは
テレポート候補の抽出に使い、両者を兼用しない。

`opened_treasures` の各要素は次の形式とする。

```json
{
  "map_id": "nectar_forest",
  "treasure_id": "entrance_potion"
}
```

- `map_id` と `treasure_id` の組を宝箱の一意な識別子とする。
- 座標はマップ制作上変更され得るため保存しない。
- 同じ組の重複を許可しない。
- マップまたは宝箱IDが存在しない場合は、対応する形式バージョンの移行処理で解決する。
- 宝箱以外の扉、破壊物、NPC位置などの動的なマップ実体状態はv1の保存対象に含めず、
  必要な恒久変化はイベントフラグから導出する。

オートマッピング用の訪問セル、可視セル、踏破率は保存しない。

## モンスター図鑑

`monster_records` はモンスター安定キーから図鑑状態への辞書とする。辞書にキーが存在することが、
そのモンスターが図鑑へ登録済みであることを表す。表示名、能力値、弱点、耐性、ドロップ内容などの
実データは `monsters.json` から取得し、セーブデータへ複製しない。

各図鑑状態は `revealed_field_keys` を持つ。

```json
{
  "revealed_field_keys": [
    "profile",
    "FIRE"
  ]
}
```

`revealed_field_keys` は重複のない安定キーの配列とし、DA2と同様に「遭遇済みだが一部の情報は
未判明」という状態を表せるようにする。具体的な開示項目と、攻撃・識別・撃破による開示条件は
モンスター図鑑機能の実装時に定める。未知の開示キーを別の意味へ読み替えない。

## ログ

`logs` は新しいものから古いものへの順で、最大20件を保持する。各要素は次の形式とする。

```json
{
  "text_key": "shop.greeting",
  "arguments": {}
}
```

- 通常UIのログは `text_key` で `content/data/texts.json` を参照する。
- イベントメッセージのログは `text_key` の代わりに
  `"message_id": "fairy_village.meet_alvan.first"` を持ち、`content/events/messages.json` を
  参照する。1件のログに両方は指定しない。
- `arguments` は名前付きプレースホルダーへ渡す文字列、整数、booleanまたは `null` の辞書とする。
- 翻訳後の完成文字列、表示言語、フォント、色、改行後のレイアウトは保存しない。
- ロード後は現在のSettingsと言語で文言を解決する。
- 同じ文言キーまたはメッセージIDでも表示した時点が異なるログは重複して保持してよい。

ログの先頭へ1件追加した結果20件を超えた場合は、末尾の最も古い項目から削除する。

## 保存対象外

次はv1へ保存しない。

- オートマッピングの踏破状態
- 重要アイテム専用の所持状態
- イベントフラグと戦闘回数から導出可能な世界進行状態
- キャラクター、アイテム、呪文、モンスター、マップのマスターデータ
- 装備と成長状態から再計算できる攻撃、防御、命中、回避、術防御、耐性
- Settingsが所有する言語、音量、画面倍率、表示モード、入力設定
- Window、Overlay、カーソル、ガイド、カメラ、フェード、BGM再生位置
- セル間の移動オフセット、遷移予約、イベント実行位置
- 戦闘Sceneと戦闘中だけ有効な状態

## 読み込みとバージョン移行

1. JSONルートと `format_version` を検証する。
2. `format_version=1` の全必須フィールドと型、範囲、重複を検証する。
3. マップ、拠点、宝箱、キャラクター、アイテム、スキル、呪文、モンスターの安定キーを
   対応する正本へ解決する。
4. `CharacterDefinition` からMemberを再構築し、保存済みの可変状態を適用する。
5. 全キャラクターの装備とインベントリを合算して所持上限と装備可否を検証する。
6. 現在パーティの人数、順序、前後列、控えの規則を検証する。
7. 保存マップとセルを検証し、FieldSceneを生成する。

`format_version` がないデータはZEROの正規セーブとして扱わない。将来のバージョンでは、旧形式を
新しいメモリ上の状態へ変換する明示的な移行処理を用意する。実装が対応していない新しい
`format_version` は破損データとして初期化せず、ロードできないことを利用者へ通知する。

同じ形式バージョンの未知フィールドや未知キーを黙って破棄しない。フィールド追加、名称変更、
意味変更のいずれでも、保存済みデータの解釈が変わる場合は形式バージョンを更新する。

## 受け入れ条件

- JSONへ変換して復元した後、所持金、共有経験値、難易度、プレイ時間、戦闘回数が一致する。
- マップID、セル座標、向きを復元し、セル間移動やOverlayの途中状態を持ち越さない。
- 現在パーティの順序、控え、前後列を復元できる。
- 離脱中を含む全キャラクターの成長、HP・MP、永続能力上昇、スキル、イベント呪文、装備、
  持続状態異常を復元できる。
- インベントリ数量と全キャラクターの装備を重複なく復元し、所持上限を再検証できる。
- イベントフラグ、訪問済み拠点、取得済み宝箱を重複のない状態で復元できる。
- アイテム図鑑と、部分開示を含むモンスター図鑑を復元できる。
- ログを文言キーと引数から現在言語で再構築できる。
- オートマッピング、重要アイテム専用状態、導出済み世界進行状態がJSONへ出力されない。
- 不正な型、範囲外の値、重複、未知の安定キー、未対応バージョンを安全に拒否できる。
