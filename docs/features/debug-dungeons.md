# デバッグ用ダンジョンシミュレーション

## 目的と入口

マップ素材を必要とせず、入口から最奥部までの戦闘・成長・消耗を調整するための開発機能。
通常起動モードの「設定 → デバッグメニュー → ダンジョン試行」から選択する。
現在のパーティ、所持品、経験値、難易度、戦闘設定をそのまま使用する。
通常起動以外では従来どおりデバッグメニュー自体を表示しない。

制作は `npm run editor -- --editor dungeon`、または統合エディタの
ダンジョン試行タブから行う。制作データの正本はゲーム本体リポジトリの
`app/debug/dungeons.json`。マップ制作に先立つ開発専用データのため共有コンテンツや
Google Sheetsへ含めず、エディタとゲームで同じファイルを読む。生成・同期処理は不要。
ゲームではデバッグメニューを開くたびに読み直し、実行開始後の定義はその入場中固定する。

## 制作データ

ルートは `format_version: 1` と `dungeons` 配列。各ダンジョンは安定した `id`、
日本語の `name`（空白だけでない24文字以内の1行）、`bgm_id`、表示順の `steps` を持つ。
名前は表示用で、宝箱記録の識別には使わない。

各ステップもダンジョン内で一意の安定した `id` を持ち、次の3種類を扱う。

| type | 設定 |
|---|---|
| `random_encounter` | `count`（1〜9999回）、`encounter` |
| `treasure` | `contents` |
| `event_battle` | 共通登録から選択する `battle_id` |

`encounter` は [`encounters.md`](./encounters.md) のマップ編成設定と同じ
`monster_level`、`danger`、`polarity`、悪魔・人間・巨人・大型動物の出現可否を持つ。
エンカウント有無の `enabled` は扱わない。変動レベルの解決、候補抽出、不意打ちは通常と共通。
歩行や歩行用エンカウント変数、歩行による回復・毒ダメージはシミュレーションしない。

宝箱の `contents` は [`treasures.md`](./treasures.md) のGold／アイテム定義と共通。
所有上限、装備中個数、取得数1個、メッセージ、SEは本編の規則を使用する。
取得済み記録には `(debug_dungeon.<ダンジョンID>, <ステップID>)` を使用する。
通常マップIDにはドットを使えないため、実マップの宝箱と衝突しない。

イベント戦闘は `content/events/battles.json` の共通登録をIDだけで参照する。
敵編成はイベントエディタの「イベントバトル」タブで編集し、ダンジョン試行には複製しない。
ダンジョン試行エディタでは登録済みIDのリストと読取専用の編成プレビューを表示する。
共通バトル登録の変更は通常イベントと同様に、保存・生成後のゲーム再起動で反映する。
ID・敵編成と開始イベントは [`events.md`](./events.md#イベントバトルと戦闘からの起動)
に従う。不意打ちと通常の逃走コマンドは無効。登録済みの戦闘開始イベントを通常どおり実行する。

不正な形式、重複ID、範囲外の数値、未登録のアイテム・敵・BGMは保存を拒否する。
実行時に不正なファイルを検出した場合は選択画面にエラー案内を表示する。
候補が空になるランダム戦闘は開始せず、進行位置を維持して設定確認の通知を行う。

## ゲーム内の進行

1. ダンジョン選択後、「入口から開始」を選ぶ。毎回、先頭から開始する。
2. 最初のステップを1件実行する。ランダム戦闘は指定回数のうち1戦だけ行う。
   ただし先頭がイベント戦闘の場合は、実行前に警告と3択を表示する。
3. ステップ完了またはランダム戦闘1戦終了後に、「進む」「ダンジョンを出る」
   「メニューを開く」を表示する。
4. 「進む」で次の1件へ進む。次がイベント戦闘なら警告を表示した状態から決定して開始する。
5. 全ステップ完了後は最奥部への到達を表示し、「進む」を灰色にしてカーソル対象から外す。

ランダム戦闘の勝利・逃走・戦闘内FADEはいずれも1戦分を消化する。
報酬、熟練度、成長、モンスター図鑑、コマンド記憶は本編の戦闘処理と共通。
完了済み戦闘回数は本編同様に勝利時だけ増え、逃走・全滅・スキップでは増やさない。
全滅時は通常の暗転・復帰メッセージを経てシミュレーションを終了する。
実マップのダンジョン出口解決は行わない。

宝箱は取得済みの場合も1件として進行し、重複報酬を与えない。
所持上限で取得できなければ、未取得状態を維持して先へ進む。
再入場時は同じ宝箱を再度取得できる。

通常退出・全滅ともに現在パーティ全員を全回復（HP・MP、死亡を含む全状態異常解除）し、
開始前のマップ・位置・向きへ戻る。成長、所持品、取得物、消耗、戦闘回数などは維持する。
退出前に元のフィールドの歩行・actor移動・通常イベントを進行させない。

## メニュー・探索用呪文

メニューは通常の回復・アイテム・装備・呪文・並べ替え・情報・設定画面を使用し、
閉じると進行位置を変えずに3択へ戻る。シミュレーション内から別のデバッグ操作は開かない。
TELEPORT相当の呪文・アイテムは使用不可。

フィールド用FADEと同効果のアイテムは、既存のMP・アイテム消費と熟練度成長を使って発動する。
発動後は今回の退出まで有効で、ランダム戦闘の開始直前に1/2の確率でその1戦だけをスキップする。
スキップ時は通知して3択に戻り、その戦闘の報酬・成長を発生させない。
宝箱とイベント戦闘はスキップ対象外。有効中の再発動は受け付けず、通常フィールドのFADE状態は変更しない。

探索中は設定したBGMをループ再生し、戦闘後は退避位置から再開する。
メニューでの呪文LVアップジングル後も、このダンジョンのBGMへ戻す。
退出後は開始前のマップのBGMを先頭から再生する。
強制割り込みゲームメニューの停止・復帰・タイトル復帰は本編と共通。

## 保存とリセット

シミュレーション中も通常メニューのセーブ画面を利用し、スロット1〜8へ手動保存できる。
戦闘・演出・宝箱メッセージ中はメニューを開かず、3択からメニューを開いた状態で保存する。
試遊版の手動セーブ禁止は維持し、ダンジョン試行中のオートセーブは引き続き行わない。

保存には現在のパーティ・成長・所持品・取得済み宝箱に加え、ダンジョンID、次に実行するステップID、
そのランダム戦闘ステップ内の消化回数、FADE有効状態を含める。行番号や制作定義全体は保存しない。
最奥部到達後はステップIDをnull、消化回数を0として保存する。
既存のセーブ形式version 3へ省略可能な `debug_dungeon` を追加し、旧セーブは試行状態なしとして復元する。

通常起動モードでロードすると、その進行位置の3択から再開する。
ロード直後に最初のステップや保存済み戦闘を自動実行せず、HP・MPの回復も行わない。
戦闘IDは現在の共通登録、編成設定は現在のダンジョン定義から解決する。
ステップの並べ替え後も保存したIDを検索し、同じステップ内の消化回数を復元する。
保存対象のダンジョン・ステップが削除された場合、回数が現在の設定以上になった場合、
または通常以外の起動モードでは、遷移前にロードを失敗させて現在の状態を変更しない。

退出先として元のフィールド位置・向きも保存し、スロットの地点名はこの元フィールドを表示する。
退出・再入場する場合は従来どおり先頭から開始し、FADEは無効になる。
退出後の通常セーブには試行の再開情報を含めない。
取得済み宝箱は既存の `SaveData.opened_treasures` に保持する。

ダンジョン選択後の「宝箱の取得記録をリセット」は確認画面を表示し、初期選択は戻る側にする。
確定した場合だけ、そのダンジョンの全宝箱記録を解除する。
通常マップ・他ダンジョンの記録、成長・所持品などには影響しない。

## 画面とエディタ操作

選択画面はデバッグWindow `(2, 2, 60, 56)`、1ページ10件。
上下入力で全件を循環選択し、キャンセルでデバッグメニューへ戻る。
開始／リセット画面からのキャンセルはダンジョン一覧、リセット確認からは開始／リセットへ戻る。

進行画面は `(0, 0, 64, 60)`。名前をY=3、ステップ位置をY=8、残り戦闘数とFADE状態を
Y=12、次の内容・イベント戦闘警告をY=17、直前の結果をY=21に置く。イベント戦闘警告は注意色を使う。
パーティ6人までの名前・現在HP・MPをY=28から3グリッド間隔で表示する。
3択はY=47・51・55。通常のメニュー入力でもメニューを開ける。
デバッグ専用文言は `app/ui/debug_text.py` の `dungeon*` に集約し、日本語固定。
宝箱の取得メッセージとマスター由来の名称は既存の言語解決を使用する。

エディタはダンジョンの追加・削除、名前・BGM、ステップの追加・削除・上下への並べ替え、
最大100操作のUndo／Redo、保存、未保存変更を伴うエディタ切替確認に対応する。
各ステップは選択行の後（未選択なら末尾）へ追加する。
ランダム戦闘を追加すると、挿入位置より前にある直近のランダム戦闘設定を独立したコピーとして
引き継ぐ。前の設定がなければ既存デバッグエンカウントと同じ初期値を使う。回数の初期値は5回。
宝箱・ダンジョンIDは新規作成時に生成し、名称・設定の編集や並べ替えでは変更しない。
削除後の再追加では新しいIDを発行する。

## 受け入れ条件と検証

- ランダム戦闘を1回ずつ進め、宝箱とイベント戦闘へ順番に到達できる。
- 先頭・途中・連続するイベント戦闘の直前に必ず警告と準備可能な3択を表示する。
- 戦闘開始イベント、報酬・成長、逃走、全滅復帰を本編と接続できる。
- メニューから進行位置を変えずに復帰し、最後の「進む」を選択できない。
- 所持上限・再入場・保存復元・並べ替えでも宝箱の重複取得を防ぎ、確認後に対象だけリセットできる。
- FADEがランダム戦闘だけを1/2でスキップし、消費と進行回数が一致する。
- 試行中のメニューから手動保存し、再起動・ロードで消化回数・FADE・HP・所持品・宝箱記録を保持して3択から再開できる。
- 旧セーブの通常フィールド復元、最奥部での保存、退出後の通常保存、削除・変更された定義の検証、試行中のオートセーブ抑止を確認する。
- 元フィールドの位置を維持し、通常退出・全滅時の全回復、BGMと割り込み復帰を確認する。

```sh
python3 -B -m unittest tests.test_debug_dungeon tests.test_game tests.test_debug_menu tests.test_game_menu tests.test_encounter tests.test_treasure_system tests.test_game_events tests.test_save_system tests.test_launch_modes tests.test_main tests.test_editor_server
node --test tests/test_debug_dungeon_editor.mjs tests/test_editor_navigation.mjs
```

Pyxel起動時に進行・警告・通常メニュー・戦闘画面を目視確認する。
