# Dungeon Antiqua ZERO 開発用ツール

`tools/` には、Pyxelウィンドウを開いてデータやリソースを手動確認する開発用プログラムを置く。自動生成・同期・CI向けの処理は `scripts/`、配布するゲーム本体は `app/` が所有する。

開発用ツールは次の方針に従う。

- 画像、パレット、JSONなどを `tools/` へ複製しない。
- `app/data`、`app/images`、`app/assets.pyxpal` など本番用生成物をそのまま読む。
- リソース形式の解釈は `app/resources` の本番用loaderへ置き、ツール固有の状態と操作だけを `tools/` へ置く。
- ゲームのSceneやSaveDataをグローバルに変更せず、必要な対象を引数で明示する。
- カレントディレクトリへ依存させず、リポジトリルートから `python3 -m tools.<module>` で起動する。
- `pyxel package app ...` の対象へ `tools/` を含めない。

## Image Viewer

生成済み画像を本番パレットで表示する。

```sh
npm run images:build
npm run tools:image-viewer
```

パレット修正前の試作生成物を表示する場合は、先に `npm run images:build:force` を実行する。

画像IDを指定する場合:

```sh
npm run tools:image-viewer -- background/bg_nector
```

画像ID一覧:

```sh
npm run tools:image-viewer -- --list
```

操作は矢印キーでパン、`N`または`Tab`で次の画像、`P`で前の画像、`Q`または`Esc`で終了する。透過色1は市松模様として確認できる。

## Screen Mocks

画面モックは `tools/screen_mocks/` に画面・機能単位で置く。単独で確認する画面は小さなComposition Rootとし、実際の画面遷移を確認する画面は起点となるモックから子画面部品を呼び出す。

```text
tools/screen_mocks/
├── _runtime.py             # 共通初期化、資産、入力設定
├── _runner.py              # 例外表示と終了コード
├── _fixtures.py            # 疑似パーティなどの共有fixture
├── battle.py               # 戦闘画面モック
├── status.py               # メニューから使うステータス画面部品
├── spell.py                # メニューから使う呪文画面部品
├── item.py                 # メニューから使うアイテム画面部品
├── equipment.py            # メニューから使う装備画面部品
├── menu.py                 # メニューと各子画面の接続モック
└── shop.py                 # ショップ画面モック（追加時）
```

Pyxel、共通アセット、パレット、Q終了入力は `_runtime.py`、想定内エラーの表示と
終了コードは `_runner.py` へ集約する。ゲームデータJSON自体は本編と同じ
`app.resources.load_record_array()` で読み、モック固有の疑似パーティ構築だけを
`_fixtures.py` に置く。Settings、SaveData、画面固有画像は起点となるComposition Rootが所有し、
子画面へ必要なものだけを明示的に渡す。すべてのモックを管理する巨大な共通Appは作らない。

### Battle Screen Mock

`background/bg_nector`、キャラクター、モンスター、ウィンドウなどの本番用リソースを使って戦闘画面の仮レイアウトを表示する。

```sh
npm run tools:screen-mock:battle
```

起動直後はコマンドウィンドウが閉じている。`Z`または`Enter`を押すと中央から開き、開き切った後は矢印キーでコマンドカーソルを移動できる。もう一度`Z`または`Enter`を押すと現在位置のコマンドキーを取得してウィンドウを閉じる。`Q`または`Esc`で終了する。

### Menu Screen Mock

左側へ6人分の名前・HP・MP・顔、右側へDA2相当のコマンド、ゲーム情報、閉じる操作案内を
表示するメニュー画面モック。名前は従来位置から4px左、HP・MPは4px右へ寄せ、6人を
収めるため控えがいる場合はメンバー間の行間を詰めている。控えがいない5人以下の場合は、
顔の間を従来どおり12px空ける。顔は前列を左、後列を12px右へずらして表示する。
疑似パーティはフィオラ、セリオン、アルヴァン、エリカ、ラグナ、ダインの6人とし、
セリオンとエリカを後列、末尾のダインを控えとする。控えはdisabled表示し、顔とテキストを
ほかのメンバーより8px下へ置く。控えの通常テキストには
白より少し暗いパレット4番を使い、名前の横に「（ひかえ）」を表示する。
アイテム・呪文などの子画面は従来どおり5人表示とする。
「ステータス」を決定するとステータス画面へ切り替わる。左右キー、ゲームパッドの左右方向、
またはL・Rショルダーボタンで表示メンバーを循環切り替えでき、キャンセルでメニューへ戻る。
ステータス画面はアニメーションなしで即時表示し、次回開いたときは直前に表示していた
メンバー位置から再開する。控えを含む6人全員を切り替えられる。力・素早さ・魔力には現在装備の
能力補正を反映し、上限は32とする。
キーボードでは左Shift・右ShiftもL・R操作として使用できる。ステータス画面で決定を押すと、
表示中のメンバーがスキルを持つ場合だけスキル欄へカーソルが移り、上下入力で選んだ
スキルの説明を画面下部へ表示する。キャンセルで通常のステータス表示へ戻る。
スキルを持たないメンバーでは右上の操作ガイドを表示せず、決定も受け付けない。
「じゅもん」を決定するとDA2準拠の呪文画面へ切り替わる。上段には選択中メンバーの顔、
名前、MPと選択中呪文の説明・消費MP、中央には習得済み呪文、下段には5人分の顔とHPを表示する。
中央の各行は習得レベルに対応し、左から元素、神聖、暗黒の順に種別アイコン付きで並べる。
レベル0呪文は通常の呪文レベルでは習得せず、イベント習得キーを明示した場合だけ表示する。
最初に左右キー、左Shift・右Shift、またはL・Rショルダーで控えを含む6人から使用者を選び、
決定するとその
メンバーの呪文選択へ進む。使用者選択中は名前左の固定カーソルでフォーカスを示し、
呪文選択へ進んだ後は同じカーソルをグレーで残す。呪文選択中のキャンセルは使用者選択へ
戻り、使用者選択中のキャンセルはメニューへ戻る。キャンプで使用できる呪文を決定すると、
下段に対象選択カーソルを表示する。使用対象は戦闘参加中の先頭5人に限り、控えは含めない。
対象への呪文効果適用は未実装である。
「そうび」を決定するとDA2準拠の装備画面へ切り替わる。左欄は顔、名前、前衛／後衛、
装備可能な武器9種と盾、現在装備、オート装備、戦闘性能、耐性を表示する。右上の候補を
選んでいる間は装備後の性能と耐性差分をプレビューし、決定時だけ所持品と交換する。
交換確定後は左欄へ戻り、交換元の部位にカーソルを残す。
装備可能な武器アイコンの直下には現在レベルをPyxel標準の3x5テキストで右寄せ表示する。
アイコン間は2px空け、レベル成長のない盾アイコンには半角ハイフンを表示する。
候補選択中も交換元の部位にはグレーの非アクティブカーソルを残す。
候補一覧の武器は武器種アイコンを名前の前に表示する。装備部位は日本語と英語で
武器を外した手は部位見出しだけを表示し、「すで」相当の装備名は表示しない。
対応部位の所持装備品はすべて候補へ表示し、装備できない品はグレー表示して装備可能品の
後ろへ並べる。disabled項目にもカーソルを合わせて詳細を確認できるが性能差分は表示せず、
決定時はエラー音と横振動を発生させる。左手の片手武器は二刀流スキル所持者にだけ表示する。
アイコン、簡体字中国語で部位名を表示する。左Shift・右Shift
や左右キー、またはL・Rショルダーで控えを含む6人のMemberを循環切り替えできる。
控えのメンバーは、隊列欄の「ぜんえい」「こうえい」の代わりに「（ひかえ）」と表示する。
`characters.json` の `type=NPC` は
初期装備だけを外せず、空き枠へ追加した装備は外すこともできる。固定された
初期装備名だけを緑色で表示し、部位見出しと「：」は通常色のままにする。交換しようと
決定した場合はエラー音と横振動を発生させる。
「ならびかえ」を決定するとメンバー欄へカーソルが移る。異なる2人を順に決定すると
表示順を交換し、同じ1人を続けて決定すると前列・後列を切り替える。6人目は常に控えとなり、
フィオラを含むどのメンバーとも交換できる。控えに入ったメンバーは強制的に前列とし、
控えのまま後列へは変更できない。ただし戦闘参加中の5人全員を後列には
できない。1人目の選択中にキャンセルすると選択を解除し、未選択時にキャンセルすると
コマンド欄へ戻る。カーソルは顔の左に表示し、1人目の決定後は選択元へ少し右へずらした
グレーのカーソルを表示する。現在のカーソルが選択元に重なっている間だけ、移動可能な
前後列方向を示す矢印を30フレームごとに切り替えて表示する。最後の前列メンバーには
後列方向の矢印を表示せず、後列へ移そうとすると効果音と横揺れのアラートを出す。
メニューモックでは `da3-field` をBGMとしてループ再生する。「せってい」を決定すると
DA2相当の設定ウィンドウを開く。左右入力で言語、BGM音量、SE音量、画面サイズ、
ピクセル／なめらか表示を変更できる。言語変更とBGM音量は即時反映し、SE音量変更時は
確認音を鳴らす。「タイトルがめんへ もどる」は確認後に端末設定を維持して
Pyxelプロセスを再起動し、選択した画面サイズを適用する。「ゲームを しゅうりょうする」は
確認後にモックを終了する。設定ウィンドウはDA2と同じ横224pxで表示する。メイン、設定、
確認の全ウィンドウは、表示時に中央から上下へ開くアニメーションを行う。設定画面での
言語切り替えによるメインWindowの再構築時はアニメーションを行わない。
本編でも使う表示用語は `content/data/texts.json` の `menu.*` / `settings.*` キーを正本とし、
日本語、英語、簡体字中国語を同じWindow構築処理で解決する。デバッグ画面だけに登場する文言は
`tools/screen_mocks/debug_text.py` の日本語固定テキストとして管理し、翻訳データには含めない。
現時点のモック表示は日本語・キーボード操作を使用する。

```sh
npm run tools:screen-mock:menu
```

メニューモック自体が開発用ツールのため、起動オプションなしで常に設定画面へ
「デバッグメニュー」が追加される。この入口は`negative`色で表示する。パーティLVはフィオラの
内部LVとして1〜99を指定し、ほかのメンバーは `characters.json` の `lv_diff` を加えたLVへ
再生成する。Goldは0〜999999を指定できる。数値入力はDA2のセーブコード入力と同じ
数字パッドを使い、キャンセルは入力済みなら末尾1桁を削除し、未入力なら前画面へ戻る。
メンバー画面ではフィオラを固定し、フィオラを含む総数が1〜6名になるよう、
ほかの全キャラクターを選択できる。候補20人は
10行×2列へ配置し、スクロールなしで1画面に表示する。

### Shop Screen Mock

メニューモックは仮フィールドから開始する。ショップ画面はこの仮フィールドから確認し、決定すると
`shops.json` の全 `shop_key` をデータ順に並べた選択Windowを開き、選択した店の固定商品を
表示する。メニューモックは確認用に999999 Goldで開始し、ショップとアイテム・装備画面で
同じ `SaveData` と `InventorySystem` を共有する。

画面上部は「かう／うる／みせをでる」のコマンドWindowと所持金Windowを左右に分ける。
上段は高さ7グリッドとし、コマンド側44、所持金側20グリッドに分ける。その下の商品一覧と
詳細欄は `y=7`、高さ40グリッドとする。
詳細テキストは `y=2` から12行を表示できる。購入一覧と売却一覧は別UIとする。購入一覧は
商品名だけを最大8件表示し、商品横に個数を置かない。一覧Window下部へ選択品の購入価格と、
装備中を含む総所有数を「○こ もっています」形式で表示する。売却一覧は最大12件をすべて
商品表示に使い、各商品名の右へインベントリ内だけの個数を表示する。売却個数は1桁時の
表示位置を右端として固定し、2桁でも同じ右端へ揃える。スクロール時の
左右インジケーターが隠れないよう、詳細Windowを先、一覧Windowを後に描画する。売却一覧では
左右キーで12件ずつページを移動する。
店へ入った直後は、下部の高さ13グリッドのWindowへ店主メッセージを通常の12px行送りで表示する。
購入の商品選択中は控えを含む6人の顔を名前・HPなしで横並びにし、装備不可の顔を暗くする。
装備品では顔の上へEまたは上昇・下降アイコンを右寄せで表示し、顔とアイコンの組を上下中央に置く。
売却の商品選択中は店主メッセージを表示し、メッセージWindowの右上へ
小さいWindowを重ね、選択品の売値を6桁右揃えの「うりね　○Ｇ」形式で表示する。
店主画像と商品種別タブは置かない。品物を決定すると個数選択へ進み、左右で増減して決定すると
取引する。個数は最大値を併記せず、桁数に依存しない固定位置の矢印を現在値の左右へ置き、
従来位置から2px下へ描画する。「たんか」は表示せず、「ごうけい」をGold表記にし、同じWindow内へ
Z・Xキーアイコンを使った決定・キャンセルガイドを表示する。現在個数の右端は合計価格の
6桁数値欄の右端へ揃える。個数選択中とレア売却確認中も、直前の商品位置へ非アクティブカーソルを
残す。購入・売却後は下部欄をそれぞれDA2と同じ店主メッセージへ切り替える。売却完了メッセージ中は
売値Windowを一時的に隠し、個数選択を始めるか売却画面を抜けるまで維持する。
「かう」または「うる」の決定後は、選択した上段コマンドへ非アクティブカーソルを残す。
「うる」の決定直後はDA2と同じ「なにを かいとればいいかな？」を表示する。売却完了後の
「オッケー！　ほかにも…」はカーソル移動やページ移動でも維持する。
どの店にもない品の売却時はDA2と同じ警告を表示するが、売却後も店の商品には追加しない。
この警告も通常の店主メッセージと同じ下部Windowへ12px行送りで表示し、
「はい／いいえ」の選択肢だけを独立した小Windowへ表示する。
キャンセルは個数選択、品物一覧、ショップコマンドの順に戻り、最後は仮フィールドへ戻る。
`shop_key` 選択中のキャンセルは選択Windowだけを閉じて仮フィールドへ戻る。
